EviCtrl: Evidence-State Memory Control

Last updated: 2026-06-16 · Version 2 of Continuous Memory Model and Retrieval

Chinese | Brainstorming hub

Research track

What can a lossy long-video memory still support? EviCtrl reformulates streaming long-video QA as evidence-state memory control: under a fixed memory budget, the system tracks which required evidence roles are still supported by surviving memory, then controls retrieval, verification, answer granularity, and abstention from that state. RAG is the execution loop, not the core contribution.

Problem: Lossy Continuous Video Memory QA

Show full description

Given a continuous video stream V = {f1, f2, ...}, build a bounded memory module M_t that ingests incrementally, consolidates continuously, and answers natural-language queries with evidence. The key change from ordinary streaming QA is that answerability changes as memory is compressed: the original video may contain the answer, but the current memory state may no longer contain the evidence needed to support every claim.

The paper-level question is: what can a lossy continuous video memory still support, and how should an agent control retrieval and generation according to surviving evidence states? This shifts the v2 line away from "hierarchical memory + RAG + verifier" toward a method contribution: active evidence acquisition over uncertain evidence-role states.

Example query

"What did I do between taking my phone out and putting it back in my pocket?"

Evidence roles: phone-out anchor, phone-back anchor, interval evidence, app-interaction evidence, and visual/OCR evidence for the specific activities. If only anchors and a summary survive, the system should return a coarse grounded answer, not a precise unsupported story.

  • Central variable: answerability is determined by surviving evidence, not by what happened in the original stream.
  • Method core: maintain a belief over role-level evidence states during retrieval, not just a final evidence chain after retrieval.
  • ICLR framing: evidence-state control under lossy memory, with RAG as one implementation of the control loop.

Core abstraction: evidence roles and states

Show full description

For a query q, EviCtrl parses a set of required evidence roles R(q) = {r1, ..., rn}. A role is a typed requirement that must be supported before a corresponding answer claim is allowed. The internal state is State(ri, M_t), not a scalar confidence attached to the final answer.

Role-state belief. Each role state lies in {supported, missing, insufficient_fidelity, ambiguous, contradicted, not_yet_found}. EviCtrl should not keep only a hard label such as "missing"; it maintains a belief distribution b_t(ri)=P(si | q, M_t, h_t). This distinction matters because "stored but not found yet" should trigger more search, while "probably missing" should trigger degradation or abstention.

Bayesian-style filtering. Retrieval and verification return observations such as FOUND_EVIDENCE, NO_RESULT, MODALITY_MISSING, LOW_FIDELITY, CONTRADICTION, and ENTITY_AMBIGUOUS. The controller updates belief with b_{t+1}=F_theta(b_t, a_t, o_t), making EviCtrl a partially observable evidence-state control problem rather than a deterministic state machine.

Multimodal role schema. Role types include TemporalAnchor, ObjectState, ActionEvent, EntityIdentity, SpeakerIdentity, SpeechContent, OCRText, SpatialRelation, CausalTransition, and IntervalSummary. Each role has modality and fidelity requirements: speaker identity needs diarization/voice/face evidence; OCR text needs crop or frame evidence; object state needs keyframe or raw visual evidence; temporal anchors need timestamped events.

Failure codes. Failed roles are reported with typed codes such as NO_EVIDENCE_POINTER, MODALITY_MISSING, FIDELITY_TOO_LOW, ENTITY_AMBIGUOUS, TEMPORAL_ANCHOR_MISSING, CONTRADICTION_FOUND, and BUDGET_EXHAUSTED. This makes abstention diagnostic rather than generic.

  • Evidence chain becomes belief state: the chain is built by updating role-state beliefs through retrieve-verify-act, not merely assembled at the end.
  • Granularity follows fidelity: raw clips can support fine visual claims; summaries can support only coarse claims; belief or gist alone can support only hypotheses.
  • Diagnostic refusal: the system reports the failed role and failure code, e.g. "I can confirm phone use, but not the specific app because OCR/screen evidence was not retained."

Method: EviCtrl as evidence-state MDP

Show full description

Sequential decision view. EviCtrl is a partially observable evidence-state MDP. The hidden state is whether each required role is supported, missing, insufficient, ambiguous, or contradicted in the current lossy memory. The belief b_t summarizes what the controller knows after previous retrieval and verification observations. The objective is max_pi E[AnswerUtility(b_T) - lambda SearchCost - mu UnsupportedRisk].

Algorithm 1: Evidence-State Belief Filter. Given a query, parse roles R(q), initialize b_0, execute evidence-seeking actions, and update b_{t+1}=F_theta(b_t, a_t, o_t) from verifier observations. This filter separates not found yet from probably missing, and represents contradiction probability instead of treating contradiction as a post-hoc flag.

Algorithm 2: Value-of-Evidence Controller. Candidate actions include search_ASR(role), search_visual(role), expand_temporal(role), retrieve_schema(role), check_contradiction(role), stop_and_answer, and abstain. At each step, choose the action with largest expected value of evidence: VoE(a)=E_o[U(F_theta(b_t,a,o))-U(b_t)]-lambda C(a). Stop when max_a VoE(a) <= tau.

Algorithm 3: Risk-Constrained Claim Generation. After stopping, choose the answer level with a risk-sensitive decision rule over {precise, coarse, hypothesis, abstain}. A claim c_j may be generated only if its role-level support risk is below threshold: Risk(c_j | b_T) <= epsilon. Contradiction probability and ambiguity probability directly increase risk, so checking contradiction can have high value before high-stakes claims.

  • Novelty: the controller performs active evidence acquisition over role-state beliefs, not fixed top-k retrieval.
  • Adaptive stopping: the system keeps searching only while expected answerability gain exceeds evidence-acquisition cost.
  • Anti-hallucination by construction: high-risk roles mask unsupported claims before generation.
  • RAG is subordinate: retrieval is one action in a state-control loop, not the paper's main abstraction.
Related work
  • Deep Video Discovery (DVD) — Agentic search over multi-granularity video; closest read-path baseline.
  • HippoRAG — Graph-structured multi-hop RAG; reference for warm-tier graph traversal.
  • Self-RAG — Retrieval and self-reflection baseline; EviCtrl differs by controlling role-level evidence states under lossy video memory.
  • RIVER — Streaming video benchmark with memory and live perception; useful for mid-stream queryability.

Learning objectives

Show full description

Unified role-coverage objective. Retention and query-time retrieval should optimize the same abstraction: typed evidence-role coverage under budget. Long-term memory budget chooses M_B to maximize E_q RoleCoverage(q, M_B); query-time budget chooses actions A_{1:T} to maximize RoleCoverage(q, Retrieved(A_{1:T})) - lambda Cost(A).

Budgeted retention as coverage maximization. Each memory item e supports a set of role types with fidelity-dependent capacity Support(e,r). The retention objective can be written as a knapsack / submodular coverage problem: max_{Cost(M)<=B} sum_r w_r max_{e in M} Support(e,r) - lambda Redundancy(M). A practical online approximation adds the item with largest marginal answerability gain Delta(e | M) while budget remains.

Training the controller. Use two stages. First, teacher-trace imitation learns pi_theta(a_t | q, b_t, M) from oracle evidence chains and verifier-labeled trajectories. Second, offline preference learning / DPO ranks trajectories by RoleRecall + alpha Answerability - beta UnsupportedClaims - lambda Cost, preferring shorter trajectories that find enough evidence and avoid unsupported precise claims.

Counterfactual compression supervision. Compare full memory, keyframe-only, schema-only, summary-only, gist-only, and missing-evidence states. The model should learn that output granularity follows survivability: full supports precise, schema supports coarse, gist supports hypothesis, and missing supports abstention.

  • Retention target: maximize future evidence-role coverage, not visually salient clip retention.
  • Control target: learn value-of-evidence action selection and adaptive stopping.
  • Generation target: strongly penalize unsupported factual answers while rewarding calibrated precise, coarse, hypothesis, or abstain outputs.

Evaluation protocol

Show full description

Setting. Fixed-budget, growing-horizon long-video QA with realistic lossy tiers. Adapt Ego4D, QAEgo4D, EgoSchema, MovieChat-1K, RIVER-style retrospective tasks, and M3-style long-memory tasks. The benchmark should include gold answers, evidence roles, evidence-chain labels, surviving evidence crumbs, allowed answer granularity, and ambiguity/failure labels.

Metrics. Report Evidence-Role Recall@K, Evidence-Chain Completion@K, Role Recall@Budget, Search Steps to Answerability, Answer Accuracy with Support, Unsupported Answer Rate, False Support Rate, Correct Abstention, Stop Decision Accuracy, Missing-vs-Not-Found Separation, Risk-Coverage AUC, Granularity Calibration, Role-State Belief Accuracy, forgetting curves, latency, storage cost, and deletion-compliance rate.

Baselines. Include long-context VLM/LLM with sampled frames, caption-RAG, ANN over retained clips, ANN + graph traversal, MMR + reranker, LLM planner with the same tools, RAG + verifier + abstention classifier, M3-Agent-style memory, RIVER/StreamBridge-style streaming memory when comparable, DVD-style agentic search, LongMem-style SideNet memory fusion (non-attributable residual injection), oracle decomposition, oracle retention, and oracle evidence chain.

  • Hero result: at fixed answer coverage and search budget, lower unsupported-answer rate without simply over-abstaining.
  • Algorithm result: VoE control should dominate random unresolved-role search, greedy semantic retrieval, uncertainty-only search, and LLM planners on role recall per search step.
  • Scaling result: as horizon grows under fixed memory budget, retain higher evidence-role recall and better risk-coverage than strong retrieval and memory baselines.
  • Oracle baselines: identify whether bottlenecks come from retention, decomposition, retrieval, or generation.

Ablations and attribution

Show full description

Retention experiment. Fix the controller and compare retention policies: FIFO, reservoir, saliency, summary-only, graph memory, learned survivability policy, and oracle retention. This tests whether survivability-aware consolidation is doing real work.

Retrieval/control experiment. Fix the memory store and give every method the same retained evidence. Compare EviCtrl VoE search to random unresolved-role search, greedy semantic retrieval, uncertainty-only search, graph traversal, reranker, verifier-only systems, LLM tool planners, and oracle VoE. This isolates the value of belief-state tracking and value-of-evidence action selection.

Belief-filter experiment. Compare hard state labels, answer-level confidence, role-level belief state, and oracle role state. Metrics: belief calibration, missing-vs-not-found separation, contradiction detection, and stop decision accuracy.

Generation/gating experiment. Fix the evidence chain and compare direct LLM answering, LLM + verifier, answer-level abstention classifier, claim-level binding, risk-constrained claim generation, and oracle claim binding. This tests whether hallucination reduction comes from risk-constrained generation rather than from better retrieval.

  • Remove components: role decomposition, belief filter, VoE controller, adaptive stopping, fidelity labels, failure codes, risk gate, contradiction check, and claim-level binding.
  • Attribution discipline: separate retention, retrieval, and generation so the paper can explain why the method wins.
  • Failure analysis: report whether failed answers came from not stored, not found, insufficient fidelity, ambiguity, or contradiction.

ICLR reviewer scoring view

Show full description

Recommendation target. The realistic ICLR goal is not "8/10" as a generic quality score. In ICLR reviewer terms, the current concept without strong experiments is around borderline; the formal EviCtrl algorithm plus strong baselines can reach Overall 6 = Weak Accept; strong risk-coverage and role-recall results can reach Overall 7 = Accept. An Overall 8+ = Strong Accept requires a clearer new phenomenon and a result that feels hard for existing RAG / verifier / selective-answering systems to reproduce.

Reviewer dimensions. EviCtrl should be judged on soundness, significance, novelty, empirical rigor, clarity, prior-work positioning, and reproducibility. The story is likely strong on significance because bounded long-video memory is a real problem, moderate on novelty unless role-state belief control is clearly separated from RAG sufficiency / verifier baselines, and decided mainly by empirical rigor.

Score ladder. A pipeline version with role parser + retriever + verifier + answerability gate is likely Overall 5: interesting but too close to system assembly. The evidence-state MDP version with belief tracking, value-of-evidence acquisition, adaptive stopping, risk-constrained generation, and attribution experiments is likely Overall 6. To reach Overall 7, EviCtrl must beat strong baselines on risk-coverage, unsupported claim rate, role recall under budget, and granularity calibration. Overall 8+ needs a broad, well-demonstrated phenomenon plus large gains over strong baselines.

  • Do not claim: "EviCtrl solves hallucination." Claim: "EviCtrl reduces unsupported factual claims under bounded/lossy memory by conditioning generation on role-level evidence states."
  • Do not claim: "EviCtrl remembers better." Claim: "EviCtrl better preserves and recovers query-required evidence roles under fixed memory and retrieval budgets."

8+ strategy: support collapse under bounded memory

Show full description

Killer phenomenon. To have 8+ ICLR potential, EviCtrl should identify and control a failure mode of bounded video memory: support collapse under relevance preservation. Under compression, a memory may remain semantically relevant to the query while losing the specific evidence roles needed to support a fine-grained factual claim. This is not ordinary retrieval failure and not ordinary hallucination; it is a bounded-memory support-degradation problem.

Example. A compressed memory summary says "the user used their phone around noon." The query asks, "Which app did I open?" A baseline retrieves the relevant summary and guesses an app. EviCtrl detects that OCR / screen / app-interaction evidence is missing or insufficient-fidelity, so it downgrades to a coarse answer or abstains from the fine-grained app claim.

Controlled Support Decay experiment. For the same video-query pairs, construct memory tiers: full clip, keyframe, ASR/OCR, schema, summary, gist/latent, and missing. Then show three curves: (1) semantic relevance stays high while role-level support drops, (2) unsupported claim rate versus coverage shows EviCtrl lower-risk at the same coverage and higher coverage at the same risk, and (3) RoleRecall@Budget shows EviCtrl finds more required evidence per memory access than RAG, LLM planners, rerankers, and selective sufficiency baselines.

Quantitative bar for a standout paper. The result should not be a small average QA gain. A convincing 8+ attempt would show large reductions in Unsupported Claim Rate, higher Coverage@FixedRisk, better RoleRecall@Budget, lower fine-detail hallucination under summary/schema memory, and better granularity calibration, all against strong baselines such as RAG + verifier + abstention, MMR + reranker + verifier, LLM planner with same tools, SURE-RAG-style selective sufficiency, and long-video memory systems when comparable.

  • 8+ thesis: relevant memories can stop supporting claims under bounded compression; EviCtrl actively controls support, not just relevance.
  • Best title direction: EviCtrl: Active Support Control for Bounded Long-Video Memory, with the subtitle "When Relevant Memories No Longer Support the Answer."
  • Honest target: design the paper with 8+ ambition, but write with 7-level restraint: no overclaiming, just strong evidence for support collapse and active support control.

High-fidelity feature tier: latent/KV evidence vs semantic features

Show full description

One tier, three candidate feature sources. Several recent memory designs store learned features instead of text or pixels: Mirage caches diffusion VAE latents at 3D points, and LongMem caches frozen-LLM KV pairs in an external bank. We unify these as one optional high-fidelity feature tier inside EviCtrl's fidelity hierarchy: the stored unit can be a diffusion latent, a VLM visual token, or an LLM KV pair. This tier is meant to support fine-grained roles (OCRText, ObjectState, precise SpatialRelation) that caption/summary tiers lose.

Why it is only a luxury tier, not the default store. Raw latents and KV are high-dimensional and expensive, so they directly fight the fixed bit budget. LongMem assumes an unbounded bank; EviCtrl does not. Feature-level evidence can therefore only be afforded for a few budgeted items, which is exactly why it sits at the top of the fidelity ladder (raw/feature > keyframe > schema > summary > gist > missing), not as the backbone.

Representation-mismatch risk (the deciding bet). Generation latents (diffusion VAE) and frozen-model KV are optimized for reconstruction / next-token prediction, not for query-aligned semantics. LLaVA-style reasoning consumes semantic, language-aligned features (CLIP/SigLIP). So feeding raw latents directly into a VLM for navigation or reasoning is unproven and may underperform semantic features. We treat this as a falsifiable hypothesis, not an assumption.

Deciding ablation. For the same long-video QA, feed three visual-token sources into the same VLM and use each for where-to-look navigation: (1) SigLIP semantic features, (2) raw diffusion/KV latents, (3) latents + a trained semantic adapter. The feature tier earns its place only if (2)/(3) beat (1) on fine-grained / OCR / spatial roles and on RoleRecall; otherwise it becomes a baseline, not a component.

What LongMem actually contributes. Its real gift is the decoupling principle — a frozen reasoner plus a small trainable memory-side module — which backs EviCtrl's fixed-policy controller and filtering belief state over a frozen VLM. But LongMem's SideNet fuses memory as an opaque hidden-state residual, which is in direct tension with EviCtrl's claim-level attribution and abstention. Opaque fusion is therefore allowed only on a coarse/gist tier (no attribution needed) or kept as a non-attributable baseline.

  • Unify, do not stack: diffusion latent / VLM token / LLM KV are one high-fidelity tier with different feature sources, not three separate modules.
  • Budget tension: feature/KV storage is a luxury top tier under the bit budget, never the default store.
  • Attribution vs fusion: SideNet-style residual fusion conflicts with role-level support gating; keep evidence explicit where claims must be attributable.
  • Frankenstein warning: EviCtrl stays the spine; latent/KV ideas enter only as a verified tier or as baselines.
Related work
  • LongMem — Frozen LLM + trainable SideNet over an unbounded external KV bank (NeurIPS 2023); precedent for decoupled memory, contrast on bounded budget and attribution.
  • Mirage (Latent Spatial Memory) — Diffusion-latent 3D cache for video generation; source for the latent feature tier and for the generation-vs-understanding representation risk.

Two-distribution lossy memory buffer: event distribution × importance distribution

Show full description

Factorize the buffer into "where to store" × "how finely to store". The lossy memory buffer is governed by two distributions with orthogonal jobs, which is why a single scalar score is not enough. Event distribution p_E answers "where in the stream is a memorable unit, and how dense are they": it controls the support (anchor placement, segmentation, granularity) and is learned self-supervised from prediction surprise / boundary / novelty, query-agnostic. Importance distribution p_I answers "how valuable is this unit for future answering": it controls the bit / fidelity allocation per anchor and is learned weakly-supervised as value-of-evidence from teacher evidence chains. In one line: the event distribution decides where and how densely to sample; the importance distribution decides how high-fidelity each sample is kept.

Formulation 1 — marked point process. Ground process = inhomogeneous intensity λ_E(t) (Poisson/Hawkes; Hawkes captures one event making short-term follow-ups more likely) placing anchors with expected count N ≈ ∫ λ_E ≤ N_max. Marks = importance samples m(e) ~ p_I mapped to a fidelity tier f(e) ∈ {raw, keyframe, schema, summary, gist} (the idea-010 ladder). Retention factorizes as keep_and_fidelity(e) ∝ p_E(e) · p_I(f | e). Importance is conditioned on the event, not independent, because important things are often event boundaries — conditioning avoids double counting.

Formulation 2 — rate–distortion bit allocation. "Lossy" is literally lossy compression: the event distribution defines the source symbol set (how to segment the stream), the importance distribution supplies weights w(e)=p_I(e), and under budget Σ b(e) ≤ B we solve min_b Σ w(e) D(b(e)). The optimum is reverse water-filling: higher importance → more bits → higher fidelity tier; low importance → compressed to summary/gist or dropped. This makes the buffer an online, samplable factorized approximation of the idea-004 submodular role-coverage retention objective (idea-004 is the target; this buffer is the efficient implementation).

Why this is the generative model of support collapse (the 8+ thesis). Relevance ≈ survival in p_E (the event is still represented, still retrievable). Support ≈ enough bits allocated by p_I for the role's required fidelity. Support collapse is exactly a mismatch between the two distributions: the event survives in p_E (relevant) but p_I under-allocated bits for the role a future query needs (detail compressed away) → relevant-but-unsupported. The two knobs (sampling density vs fidelity allocation) can be turned independently to produce the idea-009 support-decay curves.

Online forgetting = both distributions degrade over time. Under growing horizon and budget pressure: (1) importance decay — add recency / already-answered decay to p_I so old anchors slide down the fidelity ladder (raw→summary→gist); (2) event coarsening — merge old events into IntervalSummary so p_E coarsens. Together this yields a sharp-recent, blurry-distant buffer for free.

Learning. p_E: self-supervised boundary/novelty model, no labels. p_I: learn importance(e)=E_q[Δ RoleCoverage(q) | keep e] from teacher evidence chains; since the query is unknown at retention time, marginalize over a query prior and decompose into an intrinsic evidence-density prior (faces, text, object-state changes, interactions are evidence-dense) plus a learned query-marginal term to resist train/test query shift.

  • Orthogonal roles: event distribution = support / where & how dense; importance distribution = fidelity / how many bits per anchor.
  • Two clean math views: marked point process (anchors + fidelity marks) and rate–distortion reverse water-filling under a bit budget.
  • Support collapse made explicit: it is a measurable p_E-survives / p_I-under-allocates mismatch, giving two independent experimental knobs.

Notes: Risks — (1) importance is query-blind at retention time, so it must use a query-marginal plus intrinsic prior or it breaks under test-query shift; (2) the two distributions are correlated, so model importance as p_I(·|e) rather than independent; (3) event mis-segmentation propagates into bit allocation (a missed boundary merges two events and loses evidence), so segmentation should be recoverable/revisable. Open question: jointly vs sequentially learn p_E and p_I, and whether to share an encoder.

Trainable buffer-management agent and where its learning signal comes from

Show full description

The hard part is not the policy, it is the credit assignment. The buffer agent acts query-blind and now, while the only ground-truth reward (answerability) arrives query-conditioned and much later. The whole design problem is converting delayed downstream answerability into a retention-time signal. EviCtrl therefore has two controllers sharing one objective (role coverage under budget): the query-time value-of-evidence controller (idea-003, fast, query-aware, has direct reward) and a new buffer-management agent (slow, query-blind, runs at consolidation).

Buffer agent as a memory-control MDP. State = current memory M_t (summary stats + per-item fidelity) + incoming item + budget remaining + intrinsic evidence-density features. Action = admit (the p_E gate), fidelity_tier (the p_I bit allocation), merge/coarsen, demote, evict. Architecture = frozen VLM encoder (idea-010 / LongMem decoupling) + small trainable memory-side head; only the manager is trained, not the reasoner.

Learning signals, weakest-coupling first. (1) Self-supervised for p_E: next-feature prediction / reconstruction / boundary prediction; predictive surprise = boundary = high intensity, no query needed. (2) Retrospective oracle labels for p_I (cleanest): run unbounded memory + oracle evidence chains (idea-005), and for each future query you know which items were on a needed chain, so importance(e)=E_q[1(e ∈ evidence_chain(q))] ≈ E_q[Δ RoleCoverage(q) | keep e] — a supervised regression target, no RL for the first cut. (3) Counterfactual compression for the fidelity head: ablate each item to tiers and label the minimum tier at which the claim is still supported (idea-004). (4) Hindsight-optimal imitation for the joint policy (most practical): solve the offline submodular/knapsack optimal keep set given the full future and full query set, then DAgger-imitate it online, converting intractable online credit assignment into supervised imitation of a tractable offline oracle. (5) RL / preference fine-tuning last: reward R = RoleRecall@Budget + α Answerability − β UnsupportedClaims − λ Cost via trajectory DPO with the query-time controller frozen as evaluator.

Beating delay and sparsity. The importance model is the critic: p_I predicts future role-coverage value, so it doubles as a dense query-blind retention-time reward (supervised pretrain, then refine with downstream reward). Per-item credit comes from claim-level attribution — when a query is answered, the evidence chain credits the specific retained items, reusing EviCtrl's risk-gate attribution as the credit-assignment mechanism. Hindsight relabeling (HER-style) treats whichever queries actually arrived as the realized goal distribution.

Suggested 4-stage recipe. Stage 0: self-supervised p_E on raw video. Stage 1: supervised p_I from retrospective evidence-chain importance + counterfactual-compression fidelity labels. Stage 2: DAgger imitation of the hindsight-optimal buffer for the joint admit/fidelity/merge policy under budget. Stage 3: trajectory DPO / RL with downstream answerability reward, query-time controller frozen as evaluator.

  • Two controllers, one objective: buffer agent (retention, query-blind) and VoE controller (query-time) co-trained on role coverage under budget.
  • Signal ladder: self-supervised p_E → retrospective oracle importance → counterfactual fidelity labels → hindsight-optimal imitation → downstream-reward RL.
  • Importance = critic: the same p_I head provides the dense retention-time reward, bootstrapped from supervised labels and refined by downstream answerability.

Notes: Pitfalls — query-distribution shift (regularize with intrinsic evidence-density prior + randomize query types), reward hacking toward "keep everything" (enforce a hard budget / Lagrangian, not a soft cost), and non-stationarity from the agent changing its own future state distribution (on-policy with trajectory replay or off-policy correction). Open question: whether the buffer agent and query-time controller should share weights/encoder or stay separate heads.

Diffusion evidence-navigation agent over the memory distributions (impact verdict)

Show full description

Honest verdict first. A trainable navigation agent over the p_E/p_I landscape is promising and diffusion is a strong instantiation, but it is "more impactful" only if it earns its place on a phenomenon that step-wise VoE control cannot handle. Otherwise reviewers read it as a method-for-method's-sake swap — the Frankenstein risk of idea-010.

Reframe: retrieval as trajectory navigation over the landscape. The two distributions define a structured landscape: λ_E(t) says where events are dense, p_I says where surviving fidelity/value is high. The current controller (idea-003) walks it greedily one discrete action at a time. A Diffusion Evidence Navigator (à la Diffuser / Decision Diffuser) instead generates a whole trajectory of memory-access waypoints conditioned on (query, role set R(q), belief b_t, landscape (λ_E, p_I)), trained with the VoE objective as reward.

Why diffusion fits. (1) It models a multimodal "where to look" distribution — a query's evidence is often scattered (phone-out anchor, app-interaction, OCR elsewhere), and greedy top-k/single-step VoE gets trapped in one mode while a diffusion planner samples several coherent multi-target trajectories that jointly cover roles. (2) It plans non-greedy combinatorial search orders under budget and is naturally anytime: sample K candidate plans, score each by expected role coverage − cost, execute the best.

On-thesis impact link (support collapse). A navigator that reads both distributions can detect support-collapse zones — regions where p_E survived (relevant/retrievable) but p_I fidelity collapsed (role evidence gone). A greedy semantic retriever walks into that zone, pulls the relevant-but-unsupported memory, and hallucinates; a landscape-aware navigator learns to route around it or trigger abstention. This converts diffusion navigation from a bolt-on into a direct mechanism for controlling support collapse. It is also the non-hallucinatory home for v1's diffusion field (idea-007): used as a navigation proposal prior over where degraded evidence likely lives, not as an answer generator.

Honest risks. (1) Method-for-method's-sake: the EviCtrl core does not require diffusion, so any gain must be attributed to trajectory-level generative planning + landscape awareness, not the diffusion brand — mandatory baseline is a non-diffusion trajectory planner (AR-transformer planner, MCTS over the same landscape). (2) Latency: denoising steps fight streaming/latency metrics, so report the cost curve. (3) Representation mismatch (idea-010): navigation must run in a semantic, query-aligned space, not raw diffusion-latent space, unless the SigLIP-vs-latent-vs-latent+adapter ablation passes.

Decisive experiment. On a fixed memory store (idea-006 retrieval/control protocol), compare greedy semantic retrieval, step-wise VoE, AR-transformer planner, MCTS planner, and the diffusion navigator — the last two with vs without (λ_E, p_I) landscape conditioning and semantic vs latent space. Metrics: RoleRecall per search step, Coverage@FixedRisk, and especially the scattered-multi-role / multimodal-evidence query subset where greedy fails. Diffusion earns inclusion only if it wins there and on anytime budget curves; if transformer/MCTS matches it, the claim degrades gracefully to "trajectory-level landscape-aware navigation beats greedy retrieval," with diffusion as one implementation.

  • Conditional yes: raises the ceiling (multimodal multi-role coverage, support-collapse-aware routing, a safe home for v1's field) but only with an honest non-diffusion planner baseline.
