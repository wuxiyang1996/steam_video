流式视频问答中的碎片化证据链恢复

最后更新：2026-06-25 · 连续记忆建模与检索的第 2 版

English | 头脑风暴主页

研究方向

当记忆是碎片化的，8B agent 的 answerability 取决于它如何管理证据。这个方向研究有界、有损记忆下的 streaming video QA：原始视频不可回看，或只能回看极少 cached clips。核心不是让 8B 从完整视频回答，而是让一个 8B Evidence-Memory Agent 用 typed actions 管理 sparse evidence anchors，调用 diffusion proposal 工具连接幸存 fragments，并通过 evidence-bounded verification 和 answer gate 控制哪些 claims 可以被回答。

问题：碎片化证据链恢复

展开完整描述

给定连续到达的视频流 V = {f1, f2, ...}，系统只能维护一个有界记忆 M_t。它不保存完整 clip，而是保存压缩后的 fragments，例如 object state、human pose/state、event sketch、scene relation、temporal anchor、low-res visual token 和 uncertainty tag。很多用户问题依赖的中间转移并没有被完整保存。

这个 setting 是实际问题，但它不是“视频存储问题”。更准确的说法是：这是流式智能体的证据可用性问题，或者 answerability under lossy operational memory。一个 agent 在持续观察世界时，不可能把所有历史都作为可推理证据永久保留；它只能把历史压缩成 operational memory。未来问题到来时，答案是否还能被当前记忆支持，是一个真实且困难的问题。

Publishable 与否取决于关键中间区间。这个 setting 是 valid 的；论文能否站住，取决于能不能证明 diffusion 在 sparse anchors + missing transitions 的中间预算区间显著优于 LLM planner，同时更少产生 unsupported claims。也就是说，贡献不是证明“视频能不能存”，而是证明“agent 能否从它选择保留下来的证据中负责任地回答”。

核心 failure phenomenon：support collapse under relevance preservation。有界压缩后，某条 memory fragment 仍然语义相关、仍然能被检索出来，但它已经不再支持细粒度 claim。也就是 relevance survives, support collapses：系统记得“红袋子后来在桌边”和“B 在窗边”，但没有 handoff / pickup 的过渡证据。普通 RAG 容易把相关性误当成支持性；本方法要显式判断当前 memory 是否仍能支持 claim。

任务不是简单“检索哪个 clip”。clip 可能已经没了。任务是恢复一组候选 evidence chains，把幸存碎片连接起来；然后把每条 chain ground 到真实 memory item，或标记为 unsupported。

要避免的陷阱。如果表述成“我们删除中间 transition，然后用 diffusion 猜回来”，它会像人为 benchmark。更实际的 framing 是：streaming agents maintain sparse, lossy memories for future unknown queries. This creates an answerability gap: the original stream may contain the answer, but the retained memory may only partially support it. The system must recover candidate evidence chains and know when not to answer.

实际场景
场景 为什么是实际问题
家庭 / 机器人助手 机器人看到过很多事件，但不能永久保存完整室内视频。
wearable / egocentric assistant 第一视角视频很长、隐私敏感，而且未来查询未知。
edge camera agent 系统本地实时处理，只上传或保留语义事件。
long-running lab / warehouse agent 需要记住物体、人和任务状态，但完整回放成本高。
streaming multimodal agent 模型 context 和 memory API 有限，必须压缩历史。

三层真实问题。第一是 memory survival：哪些 evidence anchors 在 streaming compression 后还活着？第二是 evidence reconstruction：这些 anchors 是否能组成一条可能的 evidence chain？第三是 answerability control：哪些 chain 被当前 memory 支持到足以回答，哪些只能拒答？

区别于普通 RAG。普通 RAG 假设文档或 clip 还在，只要检索出来即可。这里原始 evidence path 不一定还在，只剩稀疏 anchors，中间 transition 可能缺失，系统必须判断“是否还能回答”。

示例查询

“那个一开始拿红色袋子的人，后来是不是把它交给了坐在窗边的人？”

幸存碎片：red bag near table；person B by window；A disappeared；uncertain handover event。真正缺失的是连续转移：A holding bag -> bag near table -> B picks it up -> B by window。

更实际的回答纪律：如果 memory 只有 m1: A earlier held red bag、m2: red bag later near table、m3: B later sat near window with red object，agent 不应该直接回答“是的，他给了”。它应该说：我记得 A 早些时候拿着红袋子，也记得之后窗边的人附近出现了红色物体，但我没有保留到交接或拿取过程，所以不能确认是交给了他。

  • 核心变量：answerability 取决于一条 plausible latent chain 能否 ground 到幸存记忆，而不是原始视频里是否曾经有完整证据。
  • 方法核心：先在碎片化有损记忆上重建候选证据轨迹，再决定检索、验证和回答。
  • 论文设定：exact evidence path 部分丢失，只剩压缩 fragments 的 streaming video QA。
  • 实际价值：防止 agent 把 plausible memory 写成 confirmed memory claim。

核心：8B Evidence-Memory Agent

展开完整描述

8B agent 是系统核心 controller。它不是只作为 offline teacher 或 final verbalizer；它负责在 streaming 过程中选择 memory actions，在 query-time 调用 retrieval、diffusion、verification 和 answer gate。论文问题变成：一个 8B streaming video agent 在只能保留 lossy operational memory 时，如何管理证据、恢复候选证据链，并避免 unsupported memory claims。

Typed action space。8B agent 不能自由写事实，而是通过受限动作操作 memory：BUDGET_SELECT、WRITE_ANCHOR、SET_FIDELITY、PROMOTE、DEMOTE、MERGE、EVICT、ADD_EDGE、MARK_UNCERTAIN、ADD_GAP_RECORD、ADD_SUPPORT_RECORD、ADD_QUERY_TRACE、RETRIEVE_BY_ROLE、CALL_DIFFUSION、VERIFY_CHAIN、ANSWER_PRECISE、ANSWER_CONSERVATIVE 和 ABSTAIN。

工具分工。p_E/p_I 不是主 controller，而是给 8B agent 提供 anchor utility、fidelity-cost tradeoff 和 budget-aware recommendations 的 learned tools。Diffusion 不是 memory，也不是 answer model，而是 8B agent 在 sparse anchors disconnected 时调用的 latent evidence-chain proposal tool。Verifier 是同一个 8B agent 的 evidence-bounded support-checking mode，answer gate 是它最后必须遵守的输出策略。

硬边界。8B agent 可以 propose、retrieve、verify、mark gaps，但不能把 unverified hypothesis 写成 factual memory。Unsupported diffusion transitions 只能写入 QueryTrace 或 GapRecord，不能写入 EvidenceAnchor。最终回答只能来自 verifier-approved support records。

  • Agent core：8B model controls memory actions and tool calls.
  • Memory tools：p_E/p_I provide learned utility and fidelity recommendations.
  • Proposal tool：diffusion samples candidate latent evidence chains.
  • Safety constraint：verified support, not plausible reasoning, licenses final claims.

为什么需要 Diffusion

展开完整描述

ANN 检索是局部的。它可以找到 “red bag”、“window person”、“table” 这些相关 fragment，但不知道它们之间能否组成合理的事件转移。

图搜索依赖已有边。如果 handover 没被存下来，图上就没有边。图遍历会在最需要重建的地方断掉。

Beam search 只能扩展观察到的候选。如果中间状态缺失，beam 大多是在残缺状态空间里扩展，容易局部失败。

RL navigation 需要更明确的 action/reward。这里 latent transition 本身不确定，reward 稀疏，而且每个 query 需要的 evidence chain 形态都可能不同。

Diffusion 正好贴合这个 failure mode。它可以学习 trajectory prior：从 noisy / incomplete evidence fragments 到 coherent latent evidence trajectories 的条件去噪分布。因此它发生在 navigation 之前，而不只是一个 navigation policy。

  • 一句话：当 memory partially missing 时，diffusion 可以在碎片状态之间采样 coherent latent evidence trajectories。
  • 边界：diffusion 只 propose chains；grounding 和 verification 决定 support。
  • 新意来源：missing-transition recovery，而不是更快检索。

方法：Diffusion Evidence Trajectory Prior

展开完整描述

输入。Diffusion model 条件化在 question embedding、surviving memory fragments、temporal anchors、entity states、scene graph snippets、low-resolution visual tokens，以及标记缺失/低保真区域的 uncertainty mask 上。

输出。模型采样 K 条 latent evidence chains，例如 A holding red bag -> table region -> B picks object -> window seat、A holding red bag -> bag left on chair -> B near chair -> window seat，或 A holding red bag -> no transfer -> B has different object。

执行循环。每条生成 chain 都做三步检查：grounding 把 latent states snap 到幸存 memory fragments；verification 检查关键 transition 是否有支持；answer control 决定精确回答、保守回答、报告 unsupported transition，还是拒答。

  • 多峰性：一个问题可能有多条 plausible chains，top-1 reconstruction 不安全。
  • 粗到细：先生成事件级路径，再细化实体、物体和时间状态。
  • 不确定性：多条 sampled chains 分歧越大，说明答案越不稳定。

可训练实现：预训练 Encoder + 小型 Diffusion Head

展开完整描述

方案 B 是最适合论文的版本：不要从零训练一个大生成模型，而是让预训练 LLM/VLM encoder 提供输入空间，只训练一个小型 conditional latent DDPM head。Qwen2.5-VL、InternVL 或 GPT-4o 负责抽取 video fragments；LLM embedding、CLIP 或 SigLIP 负责把 question 和 retained fragments 编码；小型 diffusion head 只在 latent evidence-chain space 里生成候选轨迹；verifier 再判断哪些 transition 被当前记忆支持。

训练形式。question + retained fragments -> pretrained encoder -> condition embedding C。同时把 oracle evidence chain 经过 pretrained 或 learned step encoder 编成 Z_0。训练目标是条件去噪：denoise Z_t -> Z_0 conditioned on C。这样 diffusion 本身不是完全 pretrained，但它站在预训练语义空间上学习，训练压力小很多。

我心里的具体模型。8B agent 是 controller；前端 encoder 尽量冻结：用 Qwen2.5-VL / InternVL 一类 VLM 抽取结构化 anchors，用 SigLIP / CLIP 或 LLM embedding 编码 question、anchor text 和 visual tokens。Diffusion 本体不是大 LLM，而是一个小型 conditional latent diffusion tool：优先用 Transformer/DiT-style denoiser 处理 variable-length chain latents，也可以从 1D U-Net DDPM 做轻量 baseline。8B agent 调用 structured chain decoder、8B verifier mode 和 answer gate；它不能直接相信 diffusion，也不能把 unverified proposal 写成事实。

Diffusion 的训练数据。每个样本包含原始视频 V、问题 q、full-video oracle evidence chain C*、在压缩率 R 下由 learned buffer 得到的 M_R，以及 answer / support labels。训练时 diffusion 不能看 full video，只能条件化在 q + M_R + R 上；full video 只用来产生 oracle chain supervision。

Latent chain supervision。先用 step encoder 把 oracle chain C* = [c_1, ..., c_L] 编成 Z_0 = [z_1, ..., z_L]。每个 c_i 是一个 structured evidence step，例如 role、entity refs、time span、state / transition type 和 support requirement。训练时对 Z_0 加噪得到 Z_t，denoiser 学 ε_θ(Z_t, t, C) 预测噪声，损失为 L_diff = ||ε - ε_θ(Z_t, t, C)||^2，其中 C = Enc(q, M_R, R)。

Decoder 与 grounding-aware loss。Diffusion sample 出 Z = [z_1, ..., z_L] 后，chain decoder 把每个 waypoint 解成结构化 proposal：role、entity_refs、time_hint、anchor_query、transition_type 和 support_requirement。Decoder 用 oracle chain 标签训练：role / transition classification、entity linking、temporal bin regression 和 support-requirement multi-label loss。再加 grounding loss：如果 oracle step 在 M_R 里有 retained anchor，就用 contrastive loss 拉近 z_i 和对应 anchor embedding；如果该 step 缺失，就训练 missing / hypothesis flag。

总训练目标。第一版可以用 L = L_diff + λ_dec L_dec + λ_ground L_ground + λ_missing L_missing。后期再用 verifier score 做 reranking 或 preference fine-tuning，偏好 grounded support 更高、unsupported transition 更少、contradiction 更少的 chains。关键边界是：diffusion 学 p(latent evidence chain | question, compressed anchors, compression rate)，不是学 p(answer | video)。

生成形式。先计算 C = encode(question, memory)，再从 diffusion sample K 条 latent chains，decode 成 structured evidence chains，ground 到具体 memory items，最后由 verifier 检查 support、contradiction 和 missing transition。

  • 论文表述：diffusion operates over latent evidence trajectories, not raw language.
  • 模型选择：frozen VLM / embedding encoder + small DiT-style latent denoiser + structured chain decoder + verifier。
  • 安全边界：diffusion 不是在编故事，而是在 proposal 多条 latent evidence chain。
  • 实现优势：大模型负责感知和编码，小 diffusion head 负责多峰轨迹 proposal，verifier 负责事实支持。

记忆表示

展开完整描述

Memory buffer 存的是 fragments，而不是完整 footage。一个 memory item 可以包含 ObjectState、HumanState、ActionSketch、SceneRelation、TemporalAnchor、LowResVisualToken 和 UncertaintyTag。这些足以形成约束，但不足以保证事件转移已经被保存。

保留 fragment，但改变它的角色。Fragment 不再是论文的主问题标题；主问题是 answerability under lossy operational memory。Fragment 是这种 operational memory 的具体载体，而 evidence anchor 是其中能被 verifier 使用的证据单元：带 provenance、时间、实体、状态、fidelity 和 claim scope 的 compressed fragment。

术语关系。memory fragment 是压缩后的历史观察；evidence anchor 是保留了足够来源、实体状态、时间位置和可支持 claim 类型的 fragment。换句话说，系统不是从随机碎片里“猜回视频”，而是从可验证 anchors 上 proposal 可能的 evidence chains，再由 verifier 决定 support。

候选 chain 形式是 fragment_1 -> latent transition -> fragment_2 -> latent transition -> fragment_3。每个 observed fragment 必须 ground 到真实 retained item。每个 latent transition 只能作为 hypothesis，直到被验证或被标记 unsupported。

  • 已存证据：带时间戳、实体、关系和 fidelity tag 的压缩状态 fragments。
  • Anchor 化：只有带 provenance、claim scope 和 verifier 可检查字段的 fragment 才是 evidence anchor。
  • 缺失证据：retained states 之间的中间转移。
  • 回答纪律：chain 可以指导搜索，但只有 grounded memory 能许可 factual claim。
  • 方法链条：compressed fragment -> evidence anchor -> latent evidence chain -> verified answer。

Buffer：稀疏多保真 Evidence Substrate

展开完整描述

旧的 multi-level buffer 仍然可行，但必须瘦身。它不应该被写成一个大而全的 memory architecture，而应该被收缩成 sparse multi-fidelity evidence substrate。也就是说，buffer 的职责不是理解、存储、检索和推理一切，而是让未来 answerability 仍然有 grounded evidence 落点。

三层主结构。L0 Ephemeral Visual Cache 保存最近短窗口的 keyframes、object crops、low-res visual tokens、ASR/OCR snippets 和少量 short clip cache，只服务于近期 grounding，过期后 demote 或删除。L1 Structured Evidence Anchors 是长期主体，保存 anchor 化后的 EntityState、ObjectState、ActionSketch、SceneRelation、TemporalAnchor、被支持的 StateTransition 和 UncertaintyRecord。L2 Evidence Role Index 不是另一套记忆，而是按 identity、object_state、location、action、interaction、temporal_order、count、text/OCR、causal_transfer 等 evidence roles 组织 L1 anchors。

Multi-fidelity，而不是 multi-storage。同一批 evidence anchors 可以处在不同 fidelity tier：raw/cache -> keyframe/token -> schema -> summary -> gist -> missing。系统可以 promote 重要 anchor 到更高 fidelity，demote 旧 cache 为 schema 或 summary，merge 相邻/重复 anchors，split 错误事件边界，evict 低价值 anchor，或在 query-time refresh 低保真但高风险的证据。

p_E × p_I 是 learning-based memory writer，而不是 heuristic 规则。p_E(e | x_t, M_t; θ_E) 学习 anchor placement：当前 streaming chunk 里的 candidate event/span 是否应该成为 evidence anchor。p_I(f | e, x_t, M_t; θ_I) 学习 fidelity allocation：如果保留这个 anchor，它应该以哪个 fidelity tier 存活。联合写入决策是 p(e, f | x_t, M_t) = p_E(e | x_t, M_t) · p_I(f | e, x_t, M_t)，其中 x_t 是当前 VLM/ASR/OCR/metadata features，M_t 是已有 buffer 状态。

BERT-style writer backbone。p_E 和 p_I 可以用一个很小的预训练文本 encoder 参数化，例如 MiniLM、DistilBERT、BERT-base 或 DeBERTa-v3-small。它不直接看 raw video，而是吃结构化 anchor descriptions：[BUDGET=5%]、role tokens、以及 [ANCHOR] t=12 person_A holds red_bag fidelity=F3 uncertainty=low 这类文本化/schema 化证据 token。视觉信息先由 VLM/SigLIP 变成 object labels、action labels、caption snippets、crop embeddings 和 uncertainty，再和 BERT hidden state 拼接。

Writer heads as tools。对每个 [ANCHOR] token 的 hidden state h_i 接小 head：s_E(e_i)=W_E h_i 输出 anchor utility logit；s_I(e_i, f, r)=W_I[h_i, f_emb, role_emb, budget_emb] 输出某个 fidelity-role pair 的 utility logit；可选再加 role coverage head 和 unsupported-risk head。在线时 8B agent 读取这些 logits、budget state 和 graph/memory state，然后通过 typed actions 决定 WRITE_ANCHOR、SET_FIDELITY、MERGE、DEMOTE 或 EVICT。因此小 writer heads 是 8B agent 的 learned utility tools，而不是取代 agent 的 controller。

Rate-constrained objective。Buffer 不是为了“压缩得好看”，而是为了在压缩率 R 下最大化未来 answerability：max E_q[SupportCoverage(q, M_R) - λ UnsupportedRisk(q, M_R)] subject to Cost(M_R) / Cost(V) <= R。这里 M_R 是压缩率为 R 的 operational memory，V 是原始视频流。这样 compression rate 就不是附属指标，而是问题设定的核心变量。

训练 p_E：用 ranking 学 evidence survival。不要回归 8B 的绝对分数，因为 0.83 这类 score 会随 prompt、batch 和视频分布漂移。更稳的是构造同一 video chunk、同一 memory state、同一 compression budget 下的 pairwise preference：e_i ≻ e_j 表示 e_i 比 e_j 更值得保留。偏好来源可以是 oracle chain（出现在 future evidence chain 的 anchor 优于未使用/冗余 anchor）、8B pairwise choice，或 counterfactual memory evaluation。训练损失用 L_rank_E = -log σ(s_E(e_i) - s_E(e_j)) 或 margin ranking loss。

训练 p_I：用 ranking 学 minimum sufficient fidelity。对同一个 anchor 和 evidence role 比较不同 fidelity：(e, F1), ..., (e, F5)。Preference 不是“越高 fidelity 越好”，而是 最低但足够支持 的 fidelity 优于 insufficient fidelity，也优于更贵但冗余的 fidelity。例如 handoff role 里 F4 ≻ F2 表示 F2 不足，若 F3 已足够，则 F3 ≻ F4 表示 F3 更省 budget。训练损失为 L_rank_I = -log σ(s_I(e, f_preferred, r) - s_I(e, f_rejected, r))。这样 p_I 学的是 support fidelity / cost tradeoff，而不是总想存最高保真。

Counterfactual compression supervision。p_I 的标签可以通过反事实压缩获得：对同一个 oracle evidence item，构造 full clip -> keyframe/crop -> visual token -> schema -> summary -> gist -> missing 多个 tier，然后让 verifier 判断某个 claim / role 在每个 tier 下是否仍被支持。最低且足够支持的 tier 作为 preferred fidelity；低于它的是 insufficient_fidelity，高于它但不增加 support 的是 redundant cost。这个监督直接训练 answer granularity 跟随 survivability：full 支持 precise，schema 支持 coarse，gist 只能支持 hypothesis 或 abstain。

训练 8B agent / writer tools。训练时用更强 teacher，例如 Llama3.3-70B 或 GPT-oss-120B，在 richer context、oracle chains、full-memory replay 和预算约束下产生 memory-control action traces：哪个 anchor 更 critical、哪个 fidelity 是 minimum sufficient、哪个 memory action 更好、哪条 candidate chain 更 grounded。然后做 on-policy distillation：让 8B agent 在自己的当前 memory state 上 rollout，teacher 对这些 on-policy states 给出更优的 typed actions / rankings / correction labels。小 writer heads 学这些 utility preferences，8B agent 通过 action-level distillation 学 typed memory control。部署时 8B agent 只看 streaming chunk、当前 memory、budget、writer logits 和 graph state；所有事实写入仍必须经过 evidence constraints。

Compression rate 的报告方式。主实验应该报告 CR_storage = Cost(M_R) / Cost(raw video)，也可以补充 CR_token = Tokens(M_R) / Tokens(raw captions or dense frames) 和 CR_evidence = #retained anchors / #oracle evidence units。关键曲线是：x-axis 为 compression rate，例如 1%、2%、5%、10%、20%；y-axis 为 Answer Accuracy with Support、Evidence-Chain Recovery@K 和 Unsupported Claim Rate。最重要的区间是中间预算：极高预算大家都接近 full video，极低预算大家都没证据，而 sparse anchors + missing transitions 的中间区间决定方法价值。

Support collapse。当 anchor 存活，但它的 fidelity 不足以支持当前 evidence role，就发生 support collapse。例如系统记得红袋子后来在桌边，也记得 B 在窗边，但没有保留 handoff / pickup 过程；这时 anchor exists, but fidelity is insufficient for the required evidence role。

与 diffusion 的接口。Query 到来后，系统先预测 required evidence roles，用 L2 检索 sparse anchors；diffusion 在这些 disconnected anchors 之间 sample K 条 latent evidence chains；chain waypoints 再 snap 到 L1/L0；verifier 检查 support、conflict、missing transition；answer gate 决定回答、保守回答或拒答。

  • 8B agent 负责：memory action selection、tool calling 和 answer policy。
  • Buffer 负责：evidence survival 和 grounded evidence substrate。
  • Anchor 负责：定义可验证证据单位。
  • Diffusion 负责：disconnected evidence reconstruction / navigation。
  • Verifier 负责：answerability control，防止 unsupported claims。
  • 最小可行版本：8B agent + L0 recent cache + L1 structured anchors + L2 role index + BERT-style ranking-trained p_E/p_I tools + fidelity/uncertainty metadata。

Memory Manager：Write / Query / Update Loop

展开完整描述

Memory manager 把 8B agent 的 typed actions 落到可写、可查、可更新的 evidence substrate 上。它不是一个静态压缩文件，而是围绕三条路径运行：streaming write path、query-time retrieval path、post-query update path。核心原则是：真实 observation 写成 evidence anchors；diffusion / agent 的 hypothesis 只能写成 trace 或 gap；verifier 支持过的 claim 写成 support record。

Evidence Anchor Graph。系统维护 G = (V_G, E_G) 作为 store / query substrate，而不是主推理器。Graph nodes 包括 EvidenceAnchor、SupportRecord、GapRecord、QueryTrace 和必要的 entity/object/time nodes。Graph edges 包括 temporal_before、same_entity、same_object_candidate、near_time、same_location、possible_interaction、verified_transition、missing_transition、contradiction 和 insufficient_fidelity。

Verified edge vs hypothesis edge。verified_transition、verifier-approved same_object 和 support-backed relations 可以作为 evidence constraints；same_object_candidate、possible_interaction 和 diffusion-proposed edges 只能用于 retrieval / proposal，不能许可 factual claim。Graph 的作用是让 8B agent 快速找到 evidence neighborhood，而不是用 graph traversal 直接回答问题。

Write path。write(video_chunk) 先用 VLM/SigLIP/ASR/OCR extractor 产生 candidate anchors E_t，每个 anchor 包含 time span、entity/object ids、event type、state/relation、text/visual embeddings、provenance、uncertainty、candidate roles 和 cost-by-fidelity。8B agent 读取 p_E/p_I utility、budget state、current memory M_t 和 graph neighborhood G_t，先执行 BUDGET_SELECT 得到 under-budget action set，再选择 WRITE_ANCHOR、SET_FIDELITY、ADD_EDGE、MERGE、DEMOTE、EVICT 或 MARK_UNCERTAIN，最后更新 L0 recent cache、L1 anchor store、L2 role index 和 graph G。

Budgeted controller action。预算目标不是外部 oracle optimizer，而是 8B controller 的一个 constrained action policy：BUDGET_SELECT(E_t, M_t, G_t, R) 输出一组 typed memory actions。它的训练/执行目标可写成：M_{t+1} = argmax Σ[s_E(e) + s_I(e,f,r) - λ Cost(f) - ρ Redundancy(e,M_t)] subject to Cost(M_{t+1}) / Cost(V_{1:t}) <= R。因此公式定义的是 controller 的 action preference 和 budget legality：s_E/s_I 给 action ranking，Cost 给 legality mask，Redundancy 惩罚重复写入。这个 policy 通过 on-policy distillation 学出来：8B 先在真实压缩 memory state 上提出 BUDGET_SELECT / WRITE_ANCHOR / SET_FIDELITY / EVICT / ADD_GAP_RECORD 等动作，70B/120B teacher 在同一 state 上重排、修正或拒绝这些动作，形成 action-level supervision。实现上可以用 top-k candidate actions + constrained decoding、knapsack-style action mask，或 teacher-corrected preference learning 后让 8B agent 直接输出合法 action sequence。

Query path。query(question) 先由 8B agent 解析 required evidence roles R(q)，例如 identity、object_state、location、interaction/handoff、temporal_order、OCR/text。然后系统用 L2 role index 和 graph neighborhood 检索 sparse anchors，把 question、anchors、fidelity metadata、uncertainty 和 gap records 打包给 diffusion；diffusion sample K 条 latent evidence chains；grounding 把 waypoints snap 回 L1/L0/G；8B verifier mode 检查 support；answer gate 输出 precise / conservative / abstain。

Post-query update actions。update_after_query(verified) 也不是自由写 memory，而是由 8B agent 选择受限更新动作：若 verifier 输出 supported，只能执行 ADD_SUPPORT_RECORD(claim, supporting_anchors, support_label)；若输出 missing 或 insufficient_fidelity，执行 ADD_GAP_RECORD(role, missing_span, required_fidelity) 并可追加 PROMOTE 或 SET_FIDELITY 来提高未来 retention pressure；若输出 contradicted，执行 ADD_EDGE(type=contradiction)；diffusion proposals 和 agent search trace 只能执行 ADD_QUERY_TRACE。任何 unsupported 或 hypothesis transition 都被 action mask 禁止写成 WRITE_ANCHOR 或 factual ADD_EDGE。

  • Write：video_chunk -> candidate anchors -> 8B typed actions -> L0/L1/L2/G update。
  • Query：question -> evidence roles -> role/graph neighborhood -> diffusion -> grounding -> verifier -> answer gate。
  • Update：SupportRecord / GapRecord / QueryTrace 更新 memory metadata，但不创造未验证事实。
  • Graph 定位：store/query substrate，不是替代 diffusion 或 verifier 的主推理器。

Verifier：8B Evidence-Bounded Support Classifier

展开完整描述

Verifier 是 8B agent 的 evidence-bounded mode。同一个 8B agent 在 verifier mode 下不是开放式 QA model，也不是让它回答“发生了什么”。它只回答一个受限问题：给定 structured claim / transition 和 grounded anchors，当前 retained memory 是否支持这个 claim？因此 8B 的能力被用在 evidence sufficiency / NLI-style 判断上，而不是用来生成新的 evidence chain。

输入 schema。Verifier 输入包含 claim_or_transition、grounded_anchors 和 support_requirement。例如 claim 是 handoff(person_A, red_bag, person_B)，grounded anchors 包括 a12: person_A held red_bag at t1, fidelity=F3_visual_token、a18: red_bag near table at t2, fidelity=F2_schema、a24: person_B near window with red object at t3, identity_uncertain，support requirement 是 object_identity、temporal_order、visual_transition。

输出 schema。8B verifier 必须输出固定标签，而不是自由解释：supported、unsupported、missing、not_found_yet、contradicted、insufficient_fidelity、ambiguous_identity。同时输出 support_score、supported_parts、unsupported_parts、missing_evidence、failure_code 和 allowed_answer，例如 precise、conservative 或 abstain。

Missing-vs-not-found 边界。not_found_yet 表示当前 retrieval / graph neighborhood 还没找到证据，但 memory 里仍可能存在，需要继续查或扩大 neighborhood；missing 表示在当前 memory budget 与索引可见范围内，该 role 所需证据没有存活，应该降级或拒答。这个区分防止系统把“还没检索到”误判为“证据不存在”，也防止在预算耗尽后继续空转。

Diagnostic failure codes。Verifier 还要输出可诊断失败码，例如 NO_EVIDENCE_POINTER、MODALITY_MISSING、FIDELITY_TOO_LOW、ENTITY_AMBIGUOUS、TEMPORAL_ANCHOR_MISSING、TRANSITION_MISSING、CONTRADICTION_FOUND 和 BUDGET_EXHAUSTED。这样 abstain 不是泛泛“不知道”，而是报告哪个 evidence role 缺失、低保真或冲突。

硬约束 prompt。Verifier prompt 必须写死：only use listed anchors；do not infer missing transitions；relevant is not supported；if transition evidence is absent, output missing or insufficient_fidelity。关键原则是：相关 anchor 不是充分证据，除非 required transition、identity 和 temporal constraints 都被 retained fidelity 支持。

Chain-level verification。Diffusion 生成一条 chain 后，verifier 不只看最终答案，而是检查 node、edge 和 identity link：node support 判断 anchor 是否支持状态；transition support 判断 handoff / pickup / putdown 等边是否有证据；identity support 判断 red_bag 和 later red object 是否是同一物体；chain support 综合为 supported、partially_supported、answer_insufficient 或 contradicted。

Answer gate。8B verifier 的输出直接约束后端回答。LLM verbalizer 只能看到 verified_facts、unsupported_transitions、missing_evidence 和 allowed_answer，不能新增未验证事实。如果 handoff transition 是 missing 或 insufficient_fidelity，最终回答必须保守或拒答。

  • 8B 的角色：agent core 的 verifier mode / evidence-bounded support classifier。
  • 不是：open-ended QA、diffusion decoder、自由 evidence-chain generator。
  • 防幻觉原则：relevant anchors are not sufficient evidence unless required constraints are supported。
  • 输出给后端：verified_facts + unsupported_transitions + missing_evidence + answer_policy。

Answer Gate：最终后端回答策略

展开完整描述

Answer gate 是 verifier 之后的最后一道策略层。它不重新推理视频，也不让 8B agent 自由补证据；它只把 verifier mode 的结构化输出转换成可回答、保守回答或拒答。这样 8B agent 的 answer mode 被限制为 verbalizer：把 verified support state 写成自然语言，而不是生成新的 evidence。

8B answer mode 可见输入。最终 answer mode 只能看到 verified_facts、unsupported_transitions、missing_evidence、contradictions、insufficient_fidelity 和 answer_policy。它不能看到未验证的 diffusion latent chain，也不能把 plausible transition 写成 confirmed fact。

输出策略。precise_answer 只在所有 required evidence roles 被 supported 且无关键 contradiction 时允许；conservative_answer 用于部分事实 supported、但关键 transition / identity / temporal link missing 或 insufficient fidelity 的情况；abstain 用于证据缺失、冲突、身份歧义过强或 unsupported risk 超过阈值的情况。

形式化规则。可以写成 π_answer = Gate(S_chain, U_chain, C_chain, F_chain)，其中 S_chain 是 verifier 支持度，U_chain 是 unsupported transition risk，C_chain 是 contradiction flag，F_chain 是 insufficient-fidelity flag。若 S_chain >= τ_s 且 U_chain <= τ_u 且无 contradiction，则 precise；若有 supported facts 但存在 missing / insufficient fidelity，则 conservative；若 contradiction 或 unsupported risk 高，则 abstain。

红袋子例子。如果 verifier 支持 A held red_bag、red_bag near table、B near window with red object，但将 A handed red_bag to B 标为 missing 或 insufficient_fidelity，answer gate 必须输出 conservative answer：可以确认已支持的观察，但不能确认 handoff。

  • 8B answer mode 输入：verified_facts + unsupported_transitions + missing_evidence + answer_policy。
  • 8B answer mode 禁止：自由补全 missing transition，或把 plausible chain 写成事实。
  • 三类输出：precise_answer、conservative_answer、abstain。
  • 作用：把 diffusion proposal 和 verifier labels 转成风险受控的最终回答。

评测协议

展开完整描述

设定。构造 streaming video QA：回答时原始视频不可用，或只允许回看极少 cached subset。benchmark 用 full-video oracle chains 做标注，但模型输入只暴露 compressed memory fragments。

指标。报告 Evidence-Chain Recovery@K、Grounded Chain Precision、Transition Support Recall、Unsupported Transition Rate、Answer Accuracy with Support、Conservative Answer Calibration、Abstention Quality、conflict detection、storage cost、latency，以及不同 compression rate 下的 risk-coverage 曲线。

主实验假设。论文最重要的结果不是 full-memory 上的 QA accuracy，而是 tight-budget / lossy-fragment regime 下的 answerability gain：当 memory 只保留少量 anchors、许多 transition 缺失时，我们的方法应该在同一 compression rate 下取得更高的 grounded evidence-chain recovery、更低的 unsupported-claim rate，并保持更好的 conservative / abstain calibration。换句话说，核心贡献要被展示为：under fragmented memory and tight storage budgets, the agent can answer more questions only when current memory supports them, and refuse more appropriately when it does not.

基线。比较 ANN retrieval、caption-RAG、retained-fragment graph traversal、fragment graph 上的 beam search、LLM tool planner、RL/value-of-information navigator、autoregressive trajectory planner 和 oracle reconstruction。还要比较 8B agent + ranking-trained p_E × p_I tools + diffusion + verifier、8B agent + ranking-trained p_E × p_I tools + LLM planner + verifier、8B agent without diffusion、BCE/CE score-regression p_E × p_I、learned p_E only + fixed fidelity、随机/heuristic anchors、oracle p_E、oracle p_E + p_I 和 full-video upper bound。关键比较是：8B agent 调用 diffusion 后，能否在同一 learned compressed memory 上恢复 search/planner methods 无法从缺失边里创造出来的 missing-transition hypotheses。

Diffusion 必要性测试。为了回应 reviewer 对 beam search、LLM planner、graph search、retrieval reranking 或 MCTS 的质疑，实验必须固定同一 memory buffer、同一 retained anchors、同一 verifier 和同一 answer gate，只替换 proposal mechanism。若 diffusion 真的有贡献，它应在 sparse anchors + missing transitions 的中间预算区间产生更高 proposal recall / chain diversity，同时经过 verifier 后带来更少 unsupported transfer、handoff、causal 和 object-continuity claims。若 memory 极宽，普通 retrieval 已经足够；若 memory 极窄，所有方法都没有证据。最有说服力的区间正是中间预算。

Decisive subset。除了平均结果，必须单独报告 scattered multi-role / multimodal evidence 子集：同一个问题需要跨时间、跨对象、跨模态连接多个证据点，例如 person identity、object continuity、handoff transition、OCR/text 和 temporal order 分散在不同 anchors 中。这个子集最容易暴露 greedy retrieval、beam search 和 LLM planner 的局限，也是 diffusion trajectory proposal 最应该赢的地方。

归因实验纪律。为了避免“系统堆料”质疑，消融要拆成三组：retention/write 实验固定 query policy，比较 FIFO、reservoir、saliency、heuristic anchors、learned p_E/p_I 和 oracle retention；proposal/query 实验固定同一 memory store，只替换 diffusion、beam search、LLM planner、graph search、reranker 和 MCTS；generation/gating 实验固定 evidence chain，只比较 direct answer、LLM+verifier、answer-level abstention、claim-level verifier gate 和 oracle claim binding。

  • Hero result：同一 lossy fragment-memory budget 下，grounded chain recovery 更高，unsupported claims 更少。
  • Compression result：在 1% 到 20% 等不同 compression rate 下画 answerability / unsupported-claim 曲线，重点展示中间预算区间。
  • 风险结果：当中间 transition 缺失时，unsupported transfer/causal claims 更少。
  • 消融：固定 buffer、anchors、verifier 和 answer gate，只替换 diffusion 为 beam search / LLM planner / graph search / reranker / MCTS，证明差异来自 trajectory proposal prior。
  • 归因：分别证明 memory retention、trajectory proposal 和 answer gating 的贡献，而不是只报告端到端平均分。

贡献表述

展开完整描述

我们提出面向 8B streaming video agent 的碎片化记忆问答：原始视频不可回看，答案证据只以压缩、不完整的 memory fragments 存在。核心是一个 8B Evidence-Memory Agent：它通过 typed memory actions 管理 rate-constrained evidence substrate，用 p_E/p_I tools 获得 anchor survival 与 fidelity-cost 建议；在 query-time 调用 diffusion evidence trajectory proposal tool 生成连接 anchors 的多条潜在证据链；随后用 evidence-bounded verifier mode 检查 support、missing transition 和 insufficient fidelity；最终 answer gate 只把 verified state verbalize 成 precise、conservative 或 abstained answer，从而在 exact evidence paths 部分丢失时实现 uncertainty-aware QA。

收紧后的主贡献。这不是一个大而全 memory architecture。主贡献是一个可检验的能力边界：在 lossy memory + fragmented evidence + tight budget 下，8B agent 如何通过受限 memory actions、learned anchor/fidelity utilities、diffusion trajectory proposals 和 verifier-gated answering，把有限 memory 转化为更可靠的 answerability。各模块的必要性按功能分解：buffer/graph 负责可查询证据 substrate；p_E/p_I 负责预算下的 anchor 与 fidelity preference；diffusion 负责在 disconnected anchors 之间 proposal 多条 missing-transition hypotheses；verifier/answer gate 负责阻止这些 hypotheses 变成 unsupported claims。

  • fragmented memory
  • evidence chain recovery
  • diffusion trajectory prior
  • streaming video QA
  • grounded verification

Notes: 更强的 claim 是：search 默认路径已经存在；这个 setting 里路径可能断了，所以必须先重建候选路径，再验证。论文成败要靠同一 tight compression budget 下的曲线证明：diffusion proposal + verifier 比 planner/search 更能恢复可验证 chain，并更少产生 unsupported claims。
