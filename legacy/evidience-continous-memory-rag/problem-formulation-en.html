Fragmented Evidence Chain Recovery for Streaming Video QA

Last updated: 2026-06-25 · Version 2 of Continuous Memory Model and Retrieval

Chinese | Brainstorming hub

Research track

When memory is fragmented, an 8B agent's answerability depends on how it manages evidence. This track studies streaming video QA with a bounded, lossy memory buffer where the original video is unavailable or almost unavailable. The core is not asking an 8B model to answer from full video; it is an 8B Evidence-Memory Agent that uses typed actions to manage sparse evidence anchors, calls a diffusion proposal tool to connect surviving fragments, and uses evidence-bounded verification plus an answer gate to control which claims may be answered.

Problem: Fragmented Evidence Chain Recovery

Show full description

Given a continuous video stream V = {f1, f2, ...}, the system can only keep a bounded memory M_t. Instead of retaining complete clips, it stores compressed fragments such as object states, human pose/state, event sketches, scene relations, temporal anchors, low-resolution visual tokens, and uncertainty tags. Many user questions depend on transitions that were never stored as complete evidence.

This setting is an actual problem, but it is not a video-storage problem. A better formulation is: evidence availability for streaming agents, or answerability under lossy operational memory. When an agent continuously observes the world, it cannot permanently retain all history as reasoning-ready evidence. It must compress history into operational memory. When a future query arrives, whether the answer is still supported by the current memory is a real and difficult problem.

Publishability depends on the critical middle-budget regime. The setting is valid; the paper becomes publishable if it shows that diffusion significantly outperforms an LLM planner in the sparse anchors + missing transitions regime while producing fewer unsupported claims. The question is not whether we can store the video, but whether the agent can still justify an answer from what it chose to remember.

Core failure phenomenon: support collapse under relevance preservation. After bounded compression, a memory fragment may remain semantically relevant and retrievable while no longer supporting a fine-grained claim. In short, relevance survives, support collapses: the system remembers that the red bag later appeared near the table and that B was near the window, but it did not retain the handoff / pickup transition. Ordinary RAG can mistake relevance for support; this method explicitly asks whether current memory still supports the claim.

The task is not simply to retrieve the right clip. The clip may be gone. The task is to recover a small set of candidate evidence chains that could connect the surviving fragments, then ground each chain back to real memory items or mark it unsupported.

Avoid the wrong framing. If the paper says "we delete the middle transition and use diffusion to guess it back," the setting looks artificial. The practical framing is: streaming agents maintain sparse, lossy memories for future unknown queries. This creates an answerability gap: the original stream may contain the answer, but the retained memory may only partially support it. The system must recover candidate evidence chains and know when not to answer.

Practical scenarios
Scenario Why this is practical
Home / robot assistant The robot observes many events but cannot permanently store full indoor video.
Wearable / egocentric assistant First-person video is long, privacy-sensitive, and future queries are unknown.
Edge camera agent The system processes locally in real time and uploads or retains only semantic events.
Long-running lab / warehouse agent The agent must remember objects, people, and task states, but full replay is expensive.
Streaming multimodal agent Model context and memory APIs are limited, so history must be compressed.

The real problem has three layers. First, memory survival: which evidence anchors remain after streaming compression? Second, evidence reconstruction: can those anchors form a possible evidence chain? Third, answerability control: which chains are supported enough by current memory to answer, and which require abstention?

Why this is not ordinary RAG. Ordinary RAG assumes the document or clip still exists and only needs to be retrieved. Here the original evidence path may no longer exist in memory; only sparse anchors remain, the middle transition may be missing, and the system must decide whether the question is still answerable.

Example query

"Did the person who first held the red bag later hand it to the person sitting by the window?"

Surviving fragments: red bag near table; person B by window; person A disappeared; uncertain handover event. The missing part is the continuous transition: A holding bag -> bag near table -> B picks it up -> B by window.

Practical answer discipline: if memory only contains m1: A earlier held red bag, m2: red bag later near table, and m3: B later sat near window with red object, the agent should not directly answer "yes, he handed it over." It should say: I remember A holding the red bag earlier, and I remember a red object near the person by the window later, but I did not retain the handoff or pickup process, so I cannot confirm that it was handed to him.

  • Central variable: answerability depends on whether a plausible latent chain can be grounded to surviving memory, not whether the original stream once contained the evidence.
  • Method core: reconstruct candidate evidence trajectories over fragmented lossy memory before deciding what to retrieve or verify.
  • Paper setting: streaming video QA where exact evidence paths are partially lost and only compressed fragments remain.
  • Practical value: prevent the agent from turning plausible memory into confirmed memory claims.

Core: 8B Evidence-Memory Agent

Show full description

The 8B agent is the system's core controller. It is not only an offline teacher or a final verbalizer; it chooses memory actions during streaming and calls retrieval, diffusion, verification, and the answer gate at query time. The paper question becomes: how can an 8B streaming video agent manage compressed evidence memory, recover candidate evidence chains, and avoid unsupported memory claims when only lossy operational memory is retained?

Typed action space. The 8B agent cannot freely write facts; it operates memory through constrained actions: BUDGET_SELECT, WRITE_ANCHOR, SET_FIDELITY, PROMOTE, DEMOTE, MERGE, EVICT, ADD_EDGE, MARK_UNCERTAIN, ADD_GAP_RECORD, ADD_SUPPORT_RECORD, ADD_QUERY_TRACE, RETRIEVE_BY_ROLE, CALL_DIFFUSION, VERIFY_CHAIN, ANSWER_PRECISE, ANSWER_CONSERVATIVE, and ABSTAIN.

Tool roles.p_E/p_I are not the main controller; they are learned tools that provide anchor utility, fidelity-cost tradeoffs, and budget-aware recommendations to the 8B agent. Diffusion is not memory and not an answer model; it is a latent evidence-chain proposal tool the 8B agent calls when sparse anchors are disconnected. The verifier is the same 8B agent in evidence-bounded support-checking mode, and the answer gate is the final output policy it must obey.

Hard boundary. The 8B agent may propose, retrieve, verify, and mark gaps, but it cannot write unverified hypotheses as factual memory. Unsupported diffusion transitions may be written only into QueryTrace or GapRecord, never into EvidenceAnchor. Final answers may only be licensed by verifier-approved support records.

  • Agent core: 8B model controls memory actions and tool calls.
  • Memory tools:p_E/p_I provide learned utility and fidelity recommendations.
  • Proposal tool: diffusion samples candidate latent evidence chains.
  • Safety constraint: verified support, not plausible reasoning, licenses final claims.

Why Diffusion Is Needed

Show full description

ANN retrieval is local. It can retrieve fragments about "red bag", "window person", or "table", but it does not model whether these fragments form a coherent temporal event transition.

Graph search assumes existing edges. If the handover was not retained, the edge is missing. Graph traversal stops exactly where reconstruction is needed most.

Beam search extends observed candidates. When the middle state is absent, beam search mostly expands over a broken state space and can fail locally.

RL navigation needs a clearer action/reward surface. Here the latent transition itself is uncertain, reward is sparse, and every query may require a differently shaped evidence chain.

Diffusion fits the failure mode. It can learn a trajectory prior: a conditional denoising process from noisy, incomplete evidence fragments to coherent latent evidence trajectories. That makes it useful before navigation, not merely as a navigation policy.

  • One-line claim: diffusion is useful when memory is partially missing, because it can sample coherent latent evidence trajectories between fragmented states.
  • Important boundary: diffusion proposes chains; grounding and verification decide support.
  • Novelty source: missing-transition recovery, not faster retrieval.

Method: Diffusion Evidence Trajectory Prior

Show full description

Input. The diffusion model conditions on the question embedding, surviving memory fragments, temporal anchors, entity states, scene-graph snippets, low-resolution visual tokens, and an uncertainty mask that marks missing or low-fidelity regions.

Output. It samples K latent evidence chains such as A holding red bag -> table region -> B picks object -> window seat, A holding red bag -> bag left on chair -> B near chair -> window seat, or A holding red bag -> no transfer -> B has different object.

Execution loop. For each generated chain, the system runs three checks: grounding snaps latent states to surviving memory fragments; verification checks whether key transitions have support; answer control decides whether to answer, downgrade to a conservative statement, report unsupported transitions, or abstain.

  • Multimodality: a query may have several plausible chains, so top-1 reconstruction is unsafe.
  • Coarse-to-fine: generate event-level paths first, then refine entity, object, and time states.
  • Uncertainty: large disagreement across sampled chains is evidence that the answer is unstable.

Trainable Version: Pretrained Encoder + Small Diffusion Head

Show full description

Option B is the most paper-ready version: do not train a large generative model from scratch. Use pretrained LLM/VLM encoders to define the input space, then train only a small conditional latent DDPM head. Qwen2.5-VL, InternVL, or GPT-4o extracts video fragments; LLM embeddings, CLIP, or SigLIP encode the question and retained fragments; the small diffusion head proposes candidate trajectories in latent evidence-chain space; the verifier then decides which transitions are supported by the current memory.

Training form.question + retained fragments -> pretrained encoder -> condition embedding C. The oracle evidence chain is encoded by a pretrained or learned step encoder into Z_0. The diffusion objective is conditional denoising: denoise Z_t -> Z_0 conditioned on C. The diffusion module is therefore not fully pretrained, but its input space is provided by pretrained semantic encoders, which sharply reduces training pressure.

Concrete model in mind. The 8B agent is the controller. Keep the front-end encoders mostly frozen: use a VLM such as Qwen2.5-VL or InternVL to extract structured anchors, and use SigLIP / CLIP or LLM embeddings for the question, anchor text, and visual tokens. The diffusion module is not a large LLM; it is a small conditional latent diffusion tool. The preferred version is a Transformer / DiT-style denoiser over variable-length chain latents, with a 1D U-Net DDPM as a lighter baseline. The 8B agent calls the structured chain decoder, 8B verifier mode, and answer gate; it cannot directly trust diffusion or write unverified proposals as facts.

Diffusion training data. Each training sample contains the original video V, question q, full-video oracle evidence chain C*, compressed memory M_R produced by the learned buffer at compression rate R, and answer / support labels. During diffusion training, the model must not condition on the full video; it only receives q + M_R + R. The full video is used only to construct oracle chain supervision.

Latent chain supervision. First encode the oracle chain C* = [c_1, ..., c_L] into Z_0 = [z_1, ..., z_L] with a step encoder. Each c_i is a structured evidence step containing role, entity refs, time span, state / transition type, and support requirement. Add noise to Z_0 to obtain Z_t, then train the denoiser ε_θ(Z_t, t, C) to predict the noise with L_diff = ||ε - ε_θ(Z_t, t, C)||^2, where C = Enc(q, M_R, R).

Decoder and grounding-aware loss. After diffusion samples Z = [z_1, ..., z_L], a chain decoder turns each waypoint into a structured proposal with role, entity_refs, time_hint, anchor_query, transition_type, and support_requirement. Train the decoder from oracle chain labels using role / transition classification, entity linking, temporal-bin regression, and support-requirement multi-label loss. Add a grounding loss: if an oracle step has a retained anchor in M_R, use contrastive learning to pull z_i toward that anchor embedding; if the step is absent, train a missing / hypothesis flag.

Total objective. A clean first version uses L = L_diff + λ_dec L_dec + λ_ground L_ground + λ_missing L_missing. Later, verifier scores can rerank or preference-tune chains toward higher grounded support, fewer unsupported transitions, and fewer contradictions. The boundary is crucial: diffusion learns p(latent evidence chain | question, compressed anchors, compression rate), not p(answer | video).

Generation form. Compute C = encode(question, memory), sample K latent chains from diffusion, decode them into structured evidence chains, ground them to concrete memory items, and let the verifier check support, contradiction, and missing transitions.

  • Paper claim: diffusion operates over latent evidence trajectories, not raw language.
  • Model choice: frozen VLM / embedding encoder + small DiT-style latent denoiser + structured chain decoder + verifier.
  • Safety boundary: diffusion is not inventing a story; it proposes multiple latent evidence chains.
  • Implementation advantage: large models handle perception and encoding, the small diffusion head handles multimodal trajectory proposal, and the verifier handles factual support.

Memory Representation

Show full description

The memory buffer stores fragments rather than full footage. A memory item may contain ObjectState, HumanState, ActionSketch, SceneRelation, TemporalAnchor, LowResVisualToken, and UncertaintyTag. These are enough to form constraints, but not enough to guarantee that an event transition is preserved.

Keep fragments, but change their role. Fragments are no longer the headline problem; the headline is answerability under lossy operational memory. A fragment is the concrete substrate of that operational memory, while an evidence anchor is the verifier-usable evidence unit inside it: a compressed fragment with provenance, time, entities, state, fidelity, and claim scope.

Term hierarchy.memory fragment means a compressed historical observation; evidence anchor means a fragment that preserves enough source, entity state, temporal location, and supported-claim type to constrain future answers. In other words, the system is not guessing deleted video from random fragments; it proposes possible evidence chains over verifiable anchors, then lets the verifier decide support.

A candidate chain has the form fragment_1 -> latent transition -> fragment_2 -> latent transition -> fragment_3. Each observed fragment must be grounded to a real retained item. Each latent transition is allowed as a hypothesis only until verified or marked unsupported.

  • Stored evidence: compressed state fragments with timestamps, entities, relations, and fidelity tags.
  • Anchorization: only fragments with provenance, claim scope, and verifier-checkable fields become evidence anchors.
  • Missing evidence: intermediate transitions between retained states.
  • Answer discipline: a chain can guide search, but only grounded memory can license a factual claim.
  • Method chain:compressed fragment -> evidence anchor -> latent evidence chain -> verified answer.

Buffer: Sparse Multi-Fidelity Evidence Substrate

Show full description

The old multi-level buffer remains feasible, but it must be narrowed. It should not be presented as a large general-purpose memory architecture. It should be reduced to a sparse multi-fidelity evidence substrate. In other words, the buffer does not try to understand, store, retrieve, and reason about everything; it keeps grounded evidence footholds so future answerability is still possible.

Three-layer structure.L0 Ephemeral Visual Cache stores recent-window keyframes, object crops, low-resolution visual tokens, ASR/OCR snippets, and a small short-clip cache for near-term grounding only; it is demoted or deleted after TTL. L1 Structured Evidence Anchors is the long-term substrate, storing anchorized EntityState, ObjectState, ActionSketch, SceneRelation, TemporalAnchor, supported StateTransition, and UncertaintyRecord. L2 Evidence Role Index is not another memory store; it organizes L1 anchors by evidence roles such as identity, object_state, location, action, interaction, temporal_order, count, text/OCR, and causal_transfer.

Multi-fidelity, not multi-storage. The same evidence anchors can exist at different fidelity tiers: raw/cache -> keyframe/token -> schema -> summary -> gist -> missing. The system can promote important anchors to higher fidelity, demote old cache into schema or summary, merge adjacent or duplicate anchors, split incorrect event boundaries, evict low-value anchors, or refresh low-fidelity but high-risk evidence at query time.

p_E × p_I is a learning-based memory writer, not a heuristic rule set.p_E(e | x_t, M_t; θ_E) learns anchor placement: whether a candidate event/span in the current streaming chunk should become an evidence anchor. p_I(f | e, x_t, M_t; θ_I) learns fidelity allocation: if the anchor is kept, which fidelity tier should survive. The joint write decision is p(e, f | x_t, M_t) = p_E(e | x_t, M_t) · p_I(f | e, x_t, M_t), where x_t denotes current VLM/ASR/OCR/metadata features and M_t denotes the existing buffer state.

BERT-style writer backbone.p_E and p_I can be parameterized by a small pretrained text encoder such as MiniLM, DistilBERT, BERT-base, or DeBERTa-v3-small. It does not read raw video directly; it consumes structured anchor descriptions: [BUDGET=5%], role tokens, and textual / schema evidence tokens such as [ANCHOR] t=12 person_A holds red_bag fidelity=F3 uncertainty=low. Visual information is first converted by the VLM/SigLIP into object labels, action labels, caption snippets, crop embeddings, and uncertainty, then fused with the BERT hidden state.

Writer heads as tools. For each [ANCHOR] token hidden state h_i, attach small heads: s_E(e_i)=W_E h_i outputs an anchor utility logit; s_I(e_i, f, r)=W_I[h_i, f_emb, role_emb, budget_emb] outputs a utility logit for a fidelity-role pair; optional role coverage and unsupported-risk heads can be added. Online, the 8B agent reads these logits, the budget state, and the graph/memory state, then chooses typed actions such as WRITE_ANCHOR, SET_FIDELITY, MERGE, DEMOTE, or EVICT. Thus the small writer heads are learned utility tools for the 8B agent, not replacements for the agent controller.

Rate-constrained objective. The buffer is not optimized to compress video nicely; it is optimized to maximize future answerability at compression rate R: max E_q[SupportCoverage(q, M_R) - λ UnsupportedRisk(q, M_R)] subject to Cost(M_R) / Cost(V) <= R. Here M_R is the operational memory at compression rate R, and V is the original video stream. Compression rate is therefore not an auxiliary metric; it is the central variable of the setting.

Training p_E: learn evidence survival with ranking. Do not regress absolute 8B scores, because values such as 0.83 drift across prompts, batches, and video distributions. Instead, construct pairwise preferences under the same video chunk, memory state, and compression budget: e_i ≻ e_j means e_i is more worth retaining than e_j. Preferences can come from oracle chains, where anchors in future evidence chains outrank unused or redundant anchors, from 8B pairwise choices, or from counterfactual memory evaluation. Train with L_rank_E = -log σ(s_E(e_i) - s_E(e_j)) or a margin ranking loss.

Training p_I: learn minimum sufficient fidelity with ranking. For the same anchor and evidence role, compare fidelity tiers (e, F1), ..., (e, F5). The preference is not simply higher fidelity is better; the lowest sufficient fidelity should beat both insufficient fidelity and unnecessarily expensive redundant fidelity. For example, for a handoff role, F4 ≻ F2 means F2 is insufficient; if F3 is already sufficient, F3 ≻ F4 means F3 is more budget-efficient. Train with L_rank_I = -log σ(s_I(e, f_preferred, r) - s_I(e, f_rejected, r)). Thus p_I learns support fidelity / cost tradeoff instead of always choosing maximum fidelity.

Counterfactual compression supervision.p_I labels can be obtained by counterfactual compression: for the same oracle evidence item, construct tiers full clip -> keyframe/crop -> visual token -> schema -> summary -> gist -> missing, then let the verifier judge whether a claim / role is still supported at each tier. The lowest tier that still supports the claim becomes the preferred fidelity; tiers below it are insufficient_fidelity, and tiers above it that add no support are redundant cost. This directly trains answer granularity to follow survivability: full supports precise, schema supports coarse, and gist supports only hypothesis or abstention.

Training the 8B agent / writer tools. During training, use a stronger teacher such as Llama3.3-70B or GPT-oss-120B with richer context, oracle chains, full-memory replay, and budget constraints to produce memory-control action traces: which anchor is more critical, which fidelity is minimum sufficient, which memory action is better, and which candidate chain is more grounded. Then perform on-policy distillation: the 8B agent rolls out on its own current memory states, and the teacher provides better typed actions / rankings / correction labels for those on-policy states. The small writer heads learn these utility preferences, and the 8B agent learns typed memory control through action-level distillation. At deployment, the 8B agent only sees the streaming chunk, current memory, budget, writer logits, and graph state; all factual writes remain constrained by evidence checks.

Reporting compression rate. The main experiment should report CR_storage = Cost(M_R) / Cost(raw video), with optional CR_token = Tokens(M_R) / Tokens(raw captions or dense frames) and CR_evidence = #retained anchors / #oracle evidence units. The key plot uses compression rate on the x-axis, for example 1%, 2%, 5%, 10%, 20%, and Answer Accuracy with Support, Evidence-Chain Recovery@K, or Unsupported Claim Rate on the y-axis. The important regime is the middle budget: high budgets approach full video, very low budgets leave everyone without evidence, and the sparse anchors + missing transitions regime determines the method's value.

Support collapse. Support collapse occurs when an anchor survives but its fidelity is insufficient for the required evidence role. For example, the system may remember that the red bag was later near the table and that B was near the window, but not retain the handoff or pickup process; the anchor exists, but fidelity is insufficient for the required evidence role.

Interface to diffusion. When a query arrives, the system first predicts required evidence roles and uses L2 to retrieve sparse anchors; diffusion samples K latent evidence chains between these disconnected anchors; chain waypoints are snapped back to L1/L0; the verifier checks support, conflict, and missing transitions; the answer gate chooses precise answer, conservative answer, or abstention.

  • 8B agent handles: memory action selection, tool calling, and answer policy.
  • Buffer handles: evidence survival and grounded evidence substrate.
  • Anchors handle: the definition of verifier-usable evidence units.
  • Diffusion handles: disconnected evidence reconstruction / navigation.
  • Verifier handles: answerability control and prevention of unsupported claims.
  • Minimum feasible version:8B agent + L0 recent cache + L1 structured anchors + L2 role index + BERT-style ranking-trained p_E/p_I tools + fidelity/uncertainty metadata.

Memory Manager: Write / Query / Update Loop

Show full description

The memory manager turns the 8B agent's typed actions into a writable, searchable, and updatable evidence substrate. It is not a static compressed file. It runs three paths: streaming write path, query-time retrieval path, and post-query update path. The core rule is: real observations become evidence anchors; diffusion / agent hypotheses become traces or gaps; verifier-supported claims become support records.

Evidence Anchor Graph. The system maintains G = (V_G, E_G) as a store / query substrate, not as the main reasoner. Graph nodes include EvidenceAnchor, SupportRecord, GapRecord, QueryTrace, and necessary entity/object/time nodes. Graph edges include temporal_before, same_entity, same_object_candidate, near_time, same_location, possible_interaction, verified_transition, missing_transition, contradiction, and insufficient_fidelity.

Verified edge vs hypothesis edge.verified_transition, verifier-approved same_object, and support-backed relations can act as evidence constraints. same_object_candidate, possible_interaction, and diffusion-proposed edges are only for retrieval / proposal and cannot license factual claims. The graph helps the 8B agent retrieve an evidence neighborhood; graph traversal alone is not allowed to answer the question.

Write path.write(video_chunk) first uses a VLM/SigLIP/ASR/OCR extractor to produce candidate anchors E_t. Each anchor includes time span, entity/object ids, event type, state/relation, text/visual embeddings, provenance, uncertainty, candidate roles, and cost-by-fidelity. The 8B agent reads p_E/p_I utility, budget state, current memory M_t, and graph neighborhood G_t, first executes BUDGET_SELECT to obtain an under-budget action set, then chooses WRITE_ANCHOR, SET_FIDELITY, ADD_EDGE, MERGE, DEMOTE, EVICT, or MARK_UNCERTAIN, finally updating L0 recent cache, L1 anchor store, L2 role index, and graph G.

Budgeted controller action. The budget objective is not an external oracle optimizer. It is a constrained action policy for the 8B controller: BUDGET_SELECT(E_t, M_t, G_t, R) outputs a set of typed memory actions. Its training/execution objective can be written as M_{t+1} = argmax Σ[s_E(e) + s_I(e,f,r) - λ Cost(f) - ρ Redundancy(e,M_t)] subject to Cost(M_{t+1}) / Cost(V_{1:t}) <= R. The formula defines the controller's action preference and budget legality: s_E/s_I rank actions, Cost provides a legality mask, and Redundancy penalizes repeated writes. This policy is learned through on-policy distillation: the 8B agent first proposes actions such as BUDGET_SELECT / WRITE_ANCHOR / SET_FIDELITY / EVICT / ADD_GAP_RECORD on real compressed memory states, and a 70B/120B teacher reranks, corrects, or rejects those actions on the same states, producing action-level supervision. Implementation can use top-k candidate actions plus constrained decoding, a knapsack-style action mask, or teacher-corrected preference learning followed by direct legal action-sequence generation from the 8B agent.

Query path.query(question) first has the 8B agent parse required evidence roles R(q), such as identity, object_state, location, interaction/handoff, temporal_order, and OCR/text. The system then uses the L2 role index and graph neighborhoods to retrieve sparse anchors, packages the question, anchors, fidelity metadata, uncertainty, and gap records for diffusion; diffusion samples K latent evidence chains; grounding snaps waypoints back to L1/L0/G; 8B verifier mode checks support; the answer gate outputs precise / conservative / abstain.

Post-query update actions.update_after_query(verified) is also not free-form memory writing. The 8B agent selects constrained update actions: if the verifier outputs supported, it may only execute ADD_SUPPORT_RECORD(claim, supporting_anchors, support_label); if the verifier outputs missing or insufficient_fidelity, it executes ADD_GAP_RECORD(role, missing_span, required_fidelity) and may append PROMOTE or SET_FIDELITY to increase future retention pressure; if the verifier outputs contradicted, it executes ADD_EDGE(type=contradiction); diffusion proposals and agent search traces may only execute ADD_QUERY_TRACE. Any unsupported or hypothesis transition is masked from WRITE_ANCHOR or factual ADD_EDGE.

  • Write:video_chunk -> candidate anchors -> 8B typed actions -> L0/L1/L2/G update.
  • Query:question -> evidence roles -> role/graph neighborhood -> diffusion -> grounding -> verifier -> answer gate.
  • Update:SupportRecord / GapRecord / QueryTrace update memory metadata without creating unverified facts.
  • Graph role: store/query substrate, not a replacement for diffusion or verification.

Verifier: 8B Evidence-Bounded Support Classifier

Show full description

The verifier is the 8B agent's evidence-bounded mode. In verifier mode, the same 8B agent is not an open-ended QA model and is not asked to answer what happened. It answers a restricted question: given a structured claim / transition and grounded anchors, does the retained memory support this claim? The 8B model is therefore used for evidence sufficiency / NLI-style judgment, not for generating new evidence chains.

Input schema. The verifier input contains claim_or_transition, grounded_anchors, and support_requirement. For example, the claim may be handoff(person_A, red_bag, person_B); grounded anchors may include a12: person_A held red_bag at t1, fidelity=F3_visual_token, a18: red_bag near table at t2, fidelity=F2_schema, and a24: person_B near window with red object at t3, identity_uncertain; support requirements include object_identity, temporal_order, and visual_transition.

Output schema. The 8B verifier must output fixed labels rather than free-form reasoning: supported, unsupported, missing, not_found_yet, contradicted, insufficient_fidelity, and ambiguous_identity. It also outputs support_score, supported_parts, unsupported_parts, missing_evidence, failure_code, and allowed_answer, such as precise, conservative, or abstain.

Missing-vs-not-found boundary.not_found_yet means the current retrieval / graph neighborhood has not found evidence yet, but memory may still contain it, so the system should continue searching or expand the neighborhood. missing means that under the current memory budget and visible index, the required evidence did not survive and the answer should be degraded or abstained. This distinction prevents the system from treating "not retrieved yet" as "not stored" and also prevents endless searching once the budget is exhausted.

Diagnostic failure codes. The verifier should also emit diagnostic failure codes such as NO_EVIDENCE_POINTER, MODALITY_MISSING, FIDELITY_TOO_LOW, ENTITY_AMBIGUOUS, TEMPORAL_ANCHOR_MISSING, TRANSITION_MISSING, CONTRADICTION_FOUND, and BUDGET_EXHAUSTED. Abstention is therefore not a generic "I don't know"; it reports which evidence role is missing, low-fidelity, or contradicted.

Hard prompt constraint. The verifier prompt must enforce: only use listed anchors; do not infer missing transitions; relevant is not supported; if transition evidence is absent, output missing or insufficient_fidelity. The key principle is that relevant anchors are not sufficient evidence unless the required transition, identity, and temporal constraints are supported by retained fidelity.

Chain-level verification. After diffusion generates a chain, the verifier checks nodes, edges, and identity links rather than only the final answer: node support checks whether anchors support states; transition support checks whether handoff / pickup / putdown edges have evidence; identity support checks whether red_bag and a later red object are the same object; chain support is summarized as supported, partially_supported, answer_insufficient, or contradicted.

Answer gate. The 8B verifier output directly constrains the backend answer. The LLM verbalizer only receives verified_facts, unsupported_transitions, missing_evidence, and allowed_answer, and cannot add unverified facts. If the handoff transition is missing or insufficient_fidelity, the final answer must be conservative or abstain.

  • 8B role: verifier mode of the agent core / evidence-bounded support classifier.
  • Not: open-ended QA, diffusion decoder, or free evidence-chain generator.
  • Anti-hallucination rule: relevant anchors are not sufficient evidence unless required constraints are supported.
  • Output to backend:verified_facts + unsupported_transitions + missing_evidence + answer_policy.

Answer Gate: Final Backend Policy

Show full description

The answer gate is the final policy layer after verification. It does not re-reason over the video and does not let the 8B agent fill evidence gaps freely. It only turns verifier-mode structured output into a precise answer, conservative answer, or abstention. The 8B agent's answer mode is therefore constrained as a verbalizer: it writes the verified support state in natural language instead of generating new evidence.

Inputs visible to 8B answer mode. The final answer mode only receives verified_facts, unsupported_transitions, missing_evidence, contradictions, insufficient_fidelity, and answer_policy. It cannot see unverified diffusion latent chains and cannot turn plausible transitions into confirmed facts.

Output policy.precise_answer is allowed only when all required evidence roles are supported and no key contradiction is present. conservative_answer is used when some facts are supported but a key transition, identity link, or temporal link is missing or has insufficient fidelity. abstain is used when evidence is missing, contradictory, identity is too ambiguous, or unsupported risk exceeds the threshold.

Formal rule. Write π_answer = Gate(S_chain, U_chain, C_chain, F_chain), where S_chain is verifier support, U_chain is unsupported-transition risk, C_chain is a contradiction flag, and F_chain is an insufficient-fidelity flag. If S_chain >= τ_s, U_chain <= τ_u, and there is no contradiction, output precise; if supported facts exist but missing / insufficient fidelity remains, output conservative; if contradiction or unsupported risk is high, abstain.

Red-bag example. If the verifier supports A held red_bag, red_bag near table, and B near window with red object, but labels A handed red_bag to B as missing or insufficient_fidelity, the answer gate must output a conservative answer: it can state the supported observations but cannot confirm the handoff.

  • 8B answer-mode input:verified_facts + unsupported_transitions + missing_evidence + answer_policy.
  • 8B answer mode forbidden: filling missing transitions freely or stating plausible chains as facts.
  • Three outputs:precise_answer, conservative_answer, and abstain.
  • Purpose: convert diffusion proposals and verifier labels into a risk-controlled final answer.

Evaluation Protocol

Show full description

Setting. Construct streaming video QA tasks where original videos are unavailable at answer time or only a tiny cached subset can be revisited. The benchmark should provide full-video oracle chains for labeling, then expose only compressed memory fragments to the model.

Metrics. Report Evidence-Chain Recovery@K, Grounded Chain Precision, Transition Support Recall, Unsupported Transition Rate, Answer Accuracy with Support, Conservative Answer Calibration, Abstention Quality, conflict detection, storage cost, latency, and risk-coverage curves across compression rates.

Main experimental hypothesis. The most important result is not full-memory QA accuracy. It is answerability gain in the tight-budget / lossy-fragment regime: when memory keeps only sparse anchors and many transitions are missing, the method should achieve higher grounded evidence-chain recovery, lower unsupported-claim rate, and better conservative / abstain calibration under the same compression rate. In other words, the core contribution should be shown as: under fragmented memory and tight storage budgets, the agent answers more questions only when current memory supports them, and refuses more appropriately when it does not.

Baselines. Compare ANN retrieval, caption-RAG, graph traversal over retained fragments, beam search over fragment graphs, LLM tool planners, RL or value-of-information navigators, autoregressive trajectory planners, and oracle reconstruction. Also compare 8B agent + ranking-trained p_E × p_I tools + diffusion + verifier, 8B agent + ranking-trained p_E × p_I tools + LLM planner + verifier, 8B agent without diffusion, BCE/CE score-regression p_E × p_I, learned p_E only + fixed fidelity, random/heuristic anchors, oracle p_E, oracle p_E + p_I, and a full-video upper bound. The important comparison is whether the 8B agent, when allowed to call diffusion, recovers missing-transition hypotheses that search or planner methods cannot create from absent edges under the same learned compressed memory.

Diffusion necessity test. To answer reviewer concerns about beam search, LLM planners, graph search, retrieval reranking, or MCTS, the experiment must fix the same memory buffer, retained anchors, verifier, and answer gate, and replace only the proposal mechanism. If diffusion is truly useful, it should produce higher proposal recall and chain diversity in the sparse-anchors + missing-transitions middle-budget regime, and after verification it should reduce unsupported transfer, handoff, causal, and object-continuity claims. If memory is wide, ordinary retrieval may already suffice; if memory is extremely narrow, no method has enough evidence. The convincing regime is the middle budget.

Decisive subset. In addition to average results, report a scattered multi-role / multimodal-evidence subset: questions that require connecting evidence across time, objects, and modalities, such as person identity, object continuity, handoff transition, OCR/text, and temporal order distributed across different anchors. This subset exposes the limits of greedy retrieval, beam search, and LLM planners, and is where diffusion trajectory proposal should win if it is necessary.

Attribution discipline. To avoid the "module stacking" critique, split ablations into three groups: retention/write experiments fix the query policy and compare FIFO, reservoir, saliency, heuristic anchors, learned p_E/p_I, and oracle retention; proposal/query experiments fix the same memory store and replace only diffusion, beam search, LLM planner, graph search, reranker, and MCTS; generation/gating experiments fix the evidence chain and compare direct answering, LLM+verifier, answer-level abstention, claim-level verifier gate, and oracle claim binding.

  • Hero result: higher grounded chain recovery and fewer unsupported claims under the same lossy fragment-memory budget.
  • Compression result: plot answerability and unsupported-claim curves across compression rates such as 1% to 20%, emphasizing the middle-budget regime.
  • Risk result: fewer unsupported transfer/causal claims when the middle transition is missing.
  • Ablation: fix the buffer, anchors, verifier, and answer gate, then replace diffusion with beam search / LLM planner / graph search / reranker / MCTS to show that the gain comes from the trajectory proposal prior.
  • Attribution: separately show the contribution of memory retention, trajectory proposal, and answer gating instead of reporting only end-to-end averages.

Contribution Statement

Show full description

We introduce fragmented-memory QA for 8B streaming video agents: the original video is unavailable, and answer evidence survives only as compressed, incomplete memory fragments. The core is an 8B Evidence-Memory Agent. It manages a rate-constrained evidence substrate through typed memory actions, uses p_E/p_I tools for anchor-survival and fidelity-cost recommendations, calls a diffusion evidence-trajectory proposal tool at query time to sample plausible chains connecting anchors, checks support, missing transitions, and insufficient fidelity with evidence-bounded verifier mode, and finally verbalizes only the verified state as a precise, conservative, or abstained answer. This enables uncertainty-aware QA when exact evidence paths are partially lost.

Tightened main contribution. This is not a large all-purpose memory architecture. The main contribution is a testable capability boundary: under lossy memory + fragmented evidence + tight budget, how an 8B agent turns limited memory into more reliable answerability through constrained memory actions, learned anchor/fidelity utilities, diffusion trajectory proposals, and verifier-gated answering. Each module has a narrow role: the buffer/graph provides the searchable evidence substrate; p_E/p_I provide budgeted anchor and fidelity preferences; diffusion proposes multiple missing-transition hypotheses between disconnected anchors; the verifier and answer gate prevent those hypotheses from becoming unsupported claims.

  • fragmented memory
  • evidence chain recovery
  • diffusion trajectory prior
  • streaming video QA
  • grounded verification

Notes: The stronger claim is that search assumes the path exists, while this setting requires reconstructing candidate paths through missing transitions before verification. The paper should succeed or fail on curves under the same tight compression budget: diffusion proposal + verifier must recover more verifiable chains than planner/search and produce fewer unsupported claims.
