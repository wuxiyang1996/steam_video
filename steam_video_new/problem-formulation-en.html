World-Model-Guided Multi-Hop Reasoning over Grounded Video Memory

Predict which reasoning hop will change future belief, execute one real evidence read, correct, and replan.

Current problem formulation · 2026-07-30 · 中文 · Baseline results · Repository overview · includes SelectStream + OVO/StreamingBench notes

Core thesis

Reasoning must genuinely depend on the world model

Before every multi-hop reasoning step, an implicit world model (IWM) predicts how legal evidence-acquisition actions may change the future belief. A preference planner compares complete short trajectories, executes only the first hop of a preferred trajectory, observes real evidence, corrects the belief, and replans.

grounded L1/L1.5 evidence memory → bounded candidate reasoning hops → IWM imagined observation and belief transitions → ordinal trajectory preference → execute first hop → real evidence correction → replan

Paper-level contribution: action-conditioned prediction and model-predictive navigation of reasoning dynamics in belief space—not graph construction, generic retrieval, or numeric reward modeling.

1. Problem setting

Online stream, bounded memory. Video clips x_1,x_2,… arrive sequentially and cannot all be retained. The agent has a fixed-capacity memory buffer M_t (at most K entries), so before any question is known it must continually decide when to write and what to write. A write may create a grounded entry, update or merge an existing entry, preserve a salient event at finer temporal resolution, or evict/consolidate less useful evidence; skipping a redundant clip is also an explicit decision. These decisions must be question-independent and may use only the visible prefix x_{1:t}.

M_t = Write(M_{t-1}, x_t, w_t), |M_t| ≤ K w_t ∈ {skip, append, update/merge, consolidate/evict}

Question arrival and evidence routing. A question q may arrive at time t_q, after some relevant event has already passed, while the relevant event is visible in the current clip, or before the decisive event occurs. The agent must infer what evidence the question requires and choose among three temporally distinct sources: (1) query the bounded memory for past evidence, (2) inspect the current clip, or (3) defer the answer and wait for future clips. It may combine evidence from multiple sources and perform multi-hop queries over memory, but it may not inspect unseen future video or treat a prediction as observed evidence.

Evidence location at query timeRequired behaviorMain failure
Past: event occurred before t_qForm a question-conditioned memory query and navigate to retained evidenceThe needed event was never written, was over-compressed, or was evicted
Current: evidence is in x_{t_q}Inspect the live clip and combine it with relevant memory when necessaryHistorical retrieval distracts from direct current evidence
Future: decisive evidence occurs after t_qReturn WAIT/DEFER, monitor subsequent clips, and answer only when evidence is sufficientPremature guessing, indefinite waiting, or missing the trigger event

Thus the problem couples two policies: a pre-query memory policy that allocates scarce storage without seeing the future question, and a post-query reasoning policy that decides what and where to query, whether the evidence is sufficient, and when to answer. Performance is constrained jointly by memory capacity, evidence-read/context budget, and—when waiting is legal—response latency.

s_t = (q, M_t, x_t, E_{1:t}, missing_t, alternatives_t, contradictions_t, read_budget_t, wait_budget_t) a_t ∈ {QUERY_MEMORY(node/relation), INSPECT_CURRENT, WAIT_FOR_FUTURE, ANSWER, ABSTAIN} z_t = Enc(s_t) T_θ(z_t,a_t) → (ô_{t+1}, Δẑ_{t+1}) Pref_φ(τ_i,τ_j | z_t) ∈ {prefer_left,tie,prefer_right,incomparable}

z_t is a latent, multi-token belief state. It need not be an explicit graph posterior. For a legal evidence action, the IWM predicts an observation descriptor and belief change—not the next reasoning sentence and not evidence that may be used directly in the final answer. Only retrieved memory grounded in previously observed clips or a real current/future read can support the answer.

Modeling assumption · active perception

1.1 Complex multi-hop video QA as navigation under partial observability

We model complex video question answering as goal-directed navigation in an initially unknown, partially observable evidence environment. The analogy is to a POMDP, SLAM, and probabilistic robotics: the question defines the goal, the structured video memory is an incomplete and possibly lossy map, legal reads are sensing/navigation actions, retrieved clips are observations, and the evolving latent belief summarizes where the answer may lie and which facts are still missing. This is a reasoning abstraction—not a claim that the video is a physical robot environment or that the memory graph is a metrically accurate map.

POMDP-QA = ⟨S, A, O, T, Ω, q, B⟩ initial information: query q + structured memory M action: navigate / retrieve / inspect current / wait / backtrack observation: one real, source-grounded piece of video evidence belief update: b_{t+1} = Update(b_t, a_t, o_{t+1}) termination: high-confidence answer | low-confidence answer | abstain

The agent does not begin with a complete evidence route. Starting from the query and the addresses exposed by structured memory, it selects an interaction, receives a real observation, updates competing answer hypotheses and missing-evidence requirements, and replans. As consistent clues accumulate, useful reasoning paths should contract toward an evidence-supported answer; contradictory or insufficient observations should keep alternatives open, trigger backtracking or additional sensing, and eventually support abstention. A low-confidence answer is appropriate only when the evaluation protocol requires an answer despite residual uncertainty; otherwise calibrated abstention is the safer terminal action.

Probabilistic-robotics conceptVideo-QA counterpart
Unknown environmentThe relevant evidence locations and multi-clue dependency chain are not known at query time
Map / SLAM stateStructured, bounded memory with temporal and soft semantic links; useful but incomplete and potentially lossy
Sensor actionRead a memory node, follow a relation, inspect the live clip, wait for a future observation, or backtrack
Observation modelPredict what a legal read may reveal, then replace that prediction with the real grounded read
Belief / localizationQuestion-conditioned hypotheses, acquired support/counterevidence, missing links, and answerability
Goal / stopping ruleReach sufficient evidence for a calibrated answer, or abstain when the route remains unresolved

This assumption is especially useful in three regimes:

  1. Evidence or context loss in long video: the relevant past is only partially preserved, so the agent must navigate an imperfect map, recover complementary clues, and recognize when missing evidence makes the answer unidentifiable.
  2. Streaming video with future evidence: the question can arrive before the decisive event, so waiting is an information-gathering action and premature answering is a planning failure.
  3. Complex multi-hop, multi-clue reasoning: no single clip is sufficient; the agent must compose temporally or semantically separated observations while maintaining alternative paths and correcting its belief after every real read.

The desired convergence is therefore evidence-driven rather than score-driven: confidence may be reported as a calibrated categorical outcome, but imagined observations, embedding similarity, or a model-invented numeric utility cannot by themselves justify the final answer.

Benchmark scope · streaming + multiple clues

1.2 We target multi-evidence streaming Video QA—not every benchmark item is multi-hop

Scope. Our target is streaming video QA in which an answer may require multiple distinct evidence moments and the agent must preserve, retrieve, observe, or wait for them under bounded memory. We use multi-clue or multi-evidence when an instance needs more than one frame/interval. We reserve multi-hop for cases where those clues participate in a dependent reasoning chain. Multiple clues do not by themselves prove an ordered hop structure: two intervals can provide complementary facts without annotating that clue A must be reasoned over before clue B.

Terminology · annotation vs. reasoning

1.3 Multi-clue and multi-evidence are related, but not identical

Multi-clue is an annotation-level property. A QA instance has two or more benchmark-annotated relevant frames, timestamps, or temporal intervals. Multi-evidence is a reasoning-level property. A justified answer requires two or more distinct grounded facts acquired and used by the agent, regardless of how many annotated intervals contain them.

TermOperational definitionLayer
ClueA benchmark-annotated relevant frame, timestamp, or temporal intervalDataset annotation
EvidenceA source-grounded fact actually read by the agent and used to update beliefReasoning/runtime
Multi-clueAt least two distinct annotated clue regionsDataset selection property
Multi-evidenceAt least two distinct evidence items are jointly necessary to justify the answerReasoning requirement
Multi-hopAn evidence item supports an intermediate conclusion or dependency that affects the next reasoning/evidence-acquisition stepReasoning-chain structure

One annotated clue interval can contain multiple evidence facts—for example, the same clip shows a person picking up a key and then opening a door. That instance can be single-clue but multi-evidence. Conversely, an instance may have two annotated clue intervals even though one clue alone suffices for a particular question or model execution; it is multi-clue, but multi-evidence necessity has not been established.

Project convention: multi-clue instances are an observable proxy for multi-evidence QA, but multi-clue does not guarantee that every clue is necessary or that an explicit multi-hop reasoning chain is annotated.
Key idea · Qwen-LoRA categorical dynamics + planning

2. All-node implicit world modeling for streaming Video QA

We treat question answering as a repeated active-evidence loop over fixed-capacity adaptive-length memory nodes. L1.5 is a question-independent attention-weighted navigation graph Acorr,Atemp∈RN×N. Each path takes two [N,1] rows from its active cursor and compiles structurally legal actions. One listwise Qwen-LoRA IWM pass combines question, acquired evidence, hypothesis, target descriptors, and graph signals to predict categorical effects for every legal action. A QA Planner executes one real interaction, corrects belief, and replans.

Question → missing-evidence belief → L1.5 A_corr/A_temp [N,N] → cursor rows [N,1] → legal actions → Qwen-LoRA IWM: interpret every legal path × node belief transition → QA Planner: choose one real read / wait / answer / abstain → observe grounded clue → correct belief → repeat
Related-work map

2.1 Related work: which “world” is being modeled?

Existing work falls into three nearby groups: structured research memory (AutoProf), executable research or scientific environments (ResearchGym, DiscoveryWorld), and learned action-consequence knowledge (WorldEvolver, WKM). Environment generators such as AWM/Agent-World and mechanistic world models instead construct the external world or explain the studied system.

Our target is the problem-solving world:

(B_t, H_t, E_t, A_t) —a_t→ (ô_{t+1}, ΔB_t, ΔH_t, answerability_{t+1}, frontier_{t+1})

Before a real evidence read, the IWM predicts how that action may change answer hypotheses, missing evidence, answerability, and future search; the real observation then corrects the prediction.

Module 0 · legal interaction interface

2.3 Reasoning actions and the Graph Action Compiler

An action is a reasoning/evidence query, not a physical action:

A = {start_at, temporal_before, temporal_after, follow_soft_correlation, backtrack, inspect_current, wait_for_future, stop, answer, abstain}

INSPECT_CURRENT is legal only when a live clip is available. WAIT_FOR_FUTURE is legal only in a future-evidence/proactive protocol, consumes latency or wait budget, advances the visible stream, and never reveals a future clip early. The active CG-Bench clue-navigation protocol uses the graph-navigation subset because it does not model free-running query arrival.

The main method has one active current-node cursor. Ordinary navigation actions use that cursor as their only source; acquired nodes remain in belief/frontier history and can be revisited through an explicit BACKTRACK/SHIFT_FOCUS operation.

A_t = outgoing_temporal(current) ∪ positive_direction_soft_correlation(current) ∪ backtrack(acquired frontier history) ∪ protocol_enabled{inspect_current, wait_for_future} ∪ {stop, answer, abstain}

A deterministic Graph Action Compiler enumerates actions from endpoint validity, streaming visibility, relation status, provenance, executor availability, and budget. It never filters by question relevance. A virtual query root exposes START_AT(node) for every retained node at the first step.

Output contract — complete legal action table: A_t = [{action_id, action_type, source_id, target_safe_address, relation/provenance, executor, protocol_gate, budget_cost}]

The current all-node method sends the complete structural legal set A_t to the IWM. Embedding Top-K remains a separate retrieval baseline; a learned bounded Frontier is an open efficiency design, not part of the current main path.

Component 1 · complete-buffer semantic context

2.4 L1.5 attention graph and path-local navigation rows

The fixed-capacity memory is M ∈ RN×F×D. L1.5 constructs two adjacency matrices from node timestamps and question-independent embedding/attention correlation. They describe node-to-node navigation, not question-to-node relevance.

A^temp, A^corr ∈ R^{N×N} G^temp_{p,t}=A^temp[cursor_{p,t},:] ∈ R^{N×1} G^corr_{p,t}=A^corr[cursor_{p,t},:] ∈ R^{N×1}

The legal compiler forms Ap,t from supported outgoing relations, backtrack, and terminal operations. This is structural executability rather than node dropping: every node remains in the buffer, and the virtual root exposes START_AT for every node. The first version uses only the active-cursor row. Revisiting an old evidence anchor requires explicit BACKTRACK/SHIFT_FOCUS before taking its row, avoiding provenance-free max pooling across sources.

Explicit all-node boundary: every real, available node already present in the current memory buffer remains in consideration; no node is dropped by semantic/temporal score, Top-K, or a threshold. Padding/unavailable masks denote invalid tensor slots rather than relevance pruning. Buffer eviction, node merging, and writer-side admission policies are outside the current reader proposal and must not be introduced implicitly.
Component 2 · predictive dynamics

2.5 Hypothesis-Effect IWM: what would using this clue change?

The Qwen-LoRA IWM makes one listwise pass per reasoning step over the question, acquired grounded evidence, hypotheses/missing roles, legal target descriptors, both cursor-local L1.5 rows, and action types. It emits a categorical belief effect for every legal action. Runtime may emit only compact effect tokens; numeric utility, long rationales, and exact imagined captions are unnecessary.

ΔB̂_{p,t} = IWM_Qwen-LoRA(q, E_{p,t}, H_{p,t}, legal_targets, G^corr_{p,t}, G^temp_{p,t}, action_types)

The first experiment compares frozen-Qwen prompting with rank-8/16 LoRA and does not full-finetune the backbone. Training randomizes node presentation order and tests permutation consistency. Per-node Qwen calls, exposing all source clips, and long JSON generation remain heavier standalone baselines.

Output contract — one predicted-only joint future per candidate: τ_t^a = {action_id, optional_coarse_observation_class, per_hypothesis{support|contradict|inconclusive, roles_resolved, roles_opened, contradiction_change, answerability_transition}, frontier_effect, optional_second_hop}

One physical read produces a joint future over all hypotheses; the planner must not compare a trajectory for one answer choice against an unrelated physical trajectory for another. Before execution, any visual clue or full caption is predicted only. After execution, the real visual/text observation and grounded caption replace the imagination through correction. Imagined evidence is never persisted or used directly to answer.

Component 3 · action and stopping

2.6 QA Planner: test one future, then decide whether evidence is sufficient

The QA Planner may initially use a frozen Qwen checkpoint without training. Its pre-read selector receives the question, accumulated grounded evidence, current belief, remaining budget, and categorical IWM effects for every legal path–node action, then emits one typed decision. After execution, a separate fixed post-read evidence-judge contract sees only the selected grounded observation, identifies the realized belief effect, and corrects state. Separating the two contracts makes Qwen selection and evidence judgment auditable and provides a prediction–observation target for the IWM.

Planner_φ(q, B_t, E_t, {τ_t^a}_{a∈A_t}, budget_t) ∈ {READ(a), INSPECT_CURRENT, WAIT_FOR_FUTURE, ANSWER_HIGH_CONFIDENCE, ANSWER_LOW_CONFIDENCE, ABSTAIN}
Output contract — exactly one decision: d_t = READ(action_id) | INSPECT_CURRENT | WAIT_FOR_FUTURE | ANSWER(answer, confidence_tier, grounded_evidence_refs) | ABSTAIN(reason)

ANSWER_HIGH_CONFIDENCE requires a grounded, sufficiently complete evidence chain. ANSWER_LOW_CONFIDENCE is reserved for protocols that force an answer under residual uncertainty; otherwise ABSTAIN is preferred. WAIT_FOR_FUTURE is legal only when the streaming protocol permits future evidence and consumes wait/latency budget.

Qwen-LoRA boundary: first establish a frozen-Qwen baseline with the identical all-node prompt, then train a rank-8/16 LoRA without full-backbone tuning. Only bounded L1 descriptors are memory-visible. Per-node Qwen calls, exposing all source clips, and long-rationale generation are heavier standalone baselines.
Closed-loop dynamics

2.7 Dynamic interpretation

The same candidate can have a different effect at different steps because the missing roles, hypothesis states, acquired clues, cursor, reachable frontier, and remaining budget have changed. The IWM therefore models a transition in reasoning state rather than static question–clip similarity. The planner tests the most useful predicted transition through one real read, corrects the state, and runs the two models again.

B_0 + read(search clue) → resolve search_event; open object_found B_1 + read(object clue) → resolve object_found; open object_use B_2 + read(door clue) → resolve instrument_identity; answer ready B_2 + reread(search clue) → redundant / unchanged

Core boundary: the L1.5 temporal/correlation graph provides stable navigation topology; the Qwen-LoRA IWM interprets each legal graph action under current evidence/hypothesis; the Planner chooses what to execute and whether grounded evidence is sufficient. None may convert an imagined clue into fact.

Implementation baseline · atomic skills

3.1.1 Video-to-L1 construction

visible video prefix → question-independent windowing → sampled-frame Qwen clip schemas → frozen evidence-construction atomic skills → neighbor-aware graph compose → integrity/trust gate → bounded keep/merge/evict → temporal rebuild → embedding refresh

The writer never receives the question, answer, clue interval, or relevance label. The intended adaptive policy combines question-independent attention deviation and feature change: s_t = λ·JSD(a_t || ā_t) + (1−λ)·(1−cos(x_t,x_{t−1})), and closes the active span when this surprise exceeds a rolling empirical-quantile threshold after the minimum duration. Stable content closes at the maximum duration or stream end. The checked-in smoke path is the feature-only special case λ=0: representations are sampled every 0.5 s and cosine change is compared with the 0.8 empirical quantile of the previous eight changes, with 2–12 s bounds. The attention-signature writer remains proposed, not implemented. Qwen then produces the existing grounded clip schema; no new node schema is required.

The graph composer uses bounded previous/current/next-clip context and may invoke only the following nine frozen Video_Skills construction skills. They are the complete L1 construction ontology; reasoning-graph skills do not manufacture L1 evidence. The atomic-planner path logs each invocation and dependency, while the active neighbor-aware composer logs equivalent typed create/link/skip operations with neighbor_vlm_l1_* trace IDs:

Open question · connectivity

3.1.2 Node context and temporal determination

A node's routing key contains its type, short grounded descriptor, modality, and interval. Its read-time grounded value contains the full caption/predicate/utterance/OCR/state tuple; clip and local IDs; local participants and visible attributes; state subject, attribute, value, polarity, and temporal scope; evidence-frame or subtitle/ASR references; provenance/trust/visibility; incident composition links; and consolidation lineage. Previous/current/next clip digests are construction-time composer context, not evidence copied into the node value; their effects appear only as grounded candidate edges and in the compose audit. This context supports audit and later reads but may not include an answer, motive, cross-clip identity, or causal conclusion.

Temporal relations are deterministic interval tests after sorting nodes by (start_s,end_s,node_id). Adjacent retained nodes receive temporal_next. before(u,v) holds when end(u) ≤ start(v)+10⁻³ s; during uses interval containment within the same tolerance; otherwise intersecting intervals receive overlaps. before is sparse over a bounded forward neighborhood, not a transitive closure. Consolidation removes orphans, rewires surviving non-temporal edges, and rebuilds this backbone from retained intervals. Time order never establishes identity, change, support, or causality.

The main L1 navigation structure is a deterministic temporal_next/before/overlaps/during backbone over grounded semantic nodes. Composition links such as derived_from, entity_mention, state_of, and located_in remain provenance/audit structure. Native same_entity, state_change, and causal_hint labels belong to an optional strict-relation path and never become navigation facts without their specific verifier.

The current repair enriches persisted visual L1 nodes with question-independent, time-aligned subtitles when available. The bounded address key supports routing, while the complete descriptor remains a grounded value revealed by a real read. Future visual extraction also requests a concise grounded caption and evidence-indexed visible text. Any descriptor change invalidates the old embedding reference; Qwen/Qwen3-VL-Embedding-2B embeddings must then be regenerated before rebuilding L1.5.

Implementation baseline · soft navigation graph

3.2 L1.5 correlation overlay

Design change: the earlier L1.5 design was an atomic-event causal-temporal belief overlay that attempted to admit typed explains/enables edges. It over-labeled narrative succession and its candidate-causal edges did not reliably pass independent grounding gates. That path is historical/optional strict-relation evaluation. The active L1.5 is now a question-independent correlation overlay over retained L1 IDs. Identity, state transition, and causality are separate typed layers and never enter L1.5 merely because two nodes correlate.

  1. Freeze enriched/consolidated L1 descriptors; every descriptor change invalidates its old embedding.
  2. Encode every node with Qwen/Qwen3-VL-Embedding-2B, L2-normalize, and compute cosine s(i,j)=eᵢ·eⱼ for every unordered pair.
  3. Exclude pairs already covered by the temporal backbone from nonlocal admission, but retain their audit rows.
  4. Union nodes with cosine ≥ 0.999 into semantic-equivalence classes. Preserve distinct recurrences as a time-ordered next-occurrence chain rather than a clique.
  5. Average and renormalize each class embedding. For every source class, standardize all positive class cosines by its within-video mean/variance and apply sparsemax; zero-mass pairs disappear without fixed Top-K.
  6. For each admitted class pair choose the endpoint pair with highest raw cosine, then smallest temporal separation, then stable ID. Sparsemax produces directional proposals, but because cosine is symmetric, the current emitted edge uses the maximum proposal mass as equal two-way navigation affinity rather than claiming a directional fact.
  7. Apply one frozen global channel/cosine/positive-affinity policy and record every pair's admission/exclusion reason, model/checksum, policy fingerprint, and frozen-L1 fingerprint.

Temporal edges are exact interval constraints. Correlation edges are sparse representation-supported proposals for where related evidence may reside. Temporal proximity alone does not create correlation, and cosine alone does not guarantee admission because temporal exclusion, equivalence-chain, sparsemax, and global policy gates still apply. Similarity/affinity is not probability, confidence, identity, state transition, support, causality, relevance, or action utility. Independently verified categorical facts are stored separately.

Boundary · topology is not policy

3.3 Correlation is not action preference

L1.5 correlation: determine supported node-to-node navigable adjacency → legal-action compiler: expose executable cursor-incident hops → IWM: predict each hop's categorical observation and belief effect → planner: choose the next hop from those predictions

This boundary is mandatory. Correlation constructs question-independent graph topology; it does not choose a winner for a question. The IWM/planner may consume fixed correlation edges but may not invent, verify, or reclassify them during action selection. Measured embedding similarity, directional affinity, calibration, and provenance may be numeric graph features. The no-numeric-model-output rule applies to invented reward, utility, Q-value, probability, or confidence used for planning, not to measured graph-construction features. Edge affinity must never directly rank the winning action.

L1/L1.5 never stores the correct answer, hidden clue identity, question-conditioned belief, IWM imagination, predicted belief delta, planner trajectory, reward/utility/Q-value, GTSAM posterior, or final claim. These belong to hidden evaluation, latent belief, or the executed L2 trace.

Implementation baseline · SelectStream

3.4 SelectStream: budgeted online latent evidence

Core idea. SelectStream (arXiv:2606.16353v1) is not about “how to store more video.” Under a fixed memory and context budget, it decides online when to write, what to keep, what to read at query time, and how much historical evidence to expose to the VLM.

Prior methods usually sit at two extremes:

  • Recent-window: only the latest video — sharp current perception, but early critical events are easy to forget.
  • Large memory / replay: store and inject lots of history — longer coverage, but irrelevant past dilutes the current scene and raises compute.

SelectStream’s fix: the current frame always goes straight into the VLM; history is compressed into a fixed-capacity latent evidence graph; only a small, query-relevant slice of historical evidence is retrieved and injected as a few latent tokens.

Streaming video ↓ 1. SAW — Surprise-driven Adaptive Windowing (when to write?) ↓ 2. LVM — Latent Visual Memory Graph (what to write / keep under capacity N?) ↓ 3. GAR — Query-conditioned Graph Reasoning (which historical evidence? budget B) ↓ 4. Latent Evidence Injection (expose M calibrated tokens to frozen VLM) ↓ Answer Budgets (paper defaults): N=256 memory nodes · B=64 routed subgraph · M=8 evidence tokens

What is stored is neither raw frames nor text summaries, but latent embeddings already passed through a frozen VLM visual encoder and multimodal projector. As of 2026-07-26, SelectStream.github.io returns 404 and no official code/weights were found—paper-level reimplementation only; published LR 2e-4 vs 2e-5 conflict.

One-liner: SelectStream uses surprise to set storage granularity, a fixed-capacity latent graph to merge/keep evidence, retrieves a small multi-hop evidence subgraph for the query, and compresses it into latent tokens injected into a frozen VLM.

Boundary vs. this IWM work: SelectStream navigates where evidence lives (addressable nodes + graph edges) and how much history a frozen decoder may see. This project keeps a grounded L1/L1.5 evidence substrate, then asks whether an IWM can predict how a legal hop changes future belief and whether a planner should execute that hop. Fixed-capacity surprise-written L1 is compatible infrastructure; latent-token injection into a frozen VLM is not our main claim. Historical “operation-conditioned soft read over continuous memory without nodes/edges” (dynamic-navigation text proxy) was a separate No-Go path—not the active CG-Bench IWM protocol.

4. Short-horizon model-predictive reasoning

  1. Compile every legal action from the single current-node cursor and fixed L1.5 graph.
  2. Build bounded descriptors for every retained node and compile path-local legal actions from the frozen L1.5 graph.
  3. Predict horizon-one or horizon-two categorical transitions for every legal path–node action.
  4. Compare complete candidate trajectories pairwise.
  5. Execute only the first action of a uniquely preferred trajectory.
  6. Discard imagined observations, read real evidence, update belief, and replan.
τ* = PreferredTrajectory({Rollout_T(z_t,a)}_a) a_t* = First(τ*) o_{t+1} = Execute(M,a_t*) z_{t+1} = Update(z_t,a_t*,o_{t+1})

The world model is useful when a low-immediate-gain bridge hop unlocks a decisive second hop. This delayed effect is the principal distinction from reactive retrieval or immediate information-gain ranking.

The current all-node IWM predicts every legal first hop in batched graph/tensor forwards. Chunking may split execution batches but may not prune actions. Horizon two may remove only strictly dominated first hops before expanding every second hop from the remaining partial-order set; it does not use fixed-K beam pruning. Frontier selection remains an optional future efficiency arm.

The current reasoning_v2 planner retains a forest of competing hypothesis-conditioned reasoning histories. A joint action tree must cover every surviving answer hypothesis under one shared physical first read. The planner schedules one real read, keeps unselected alternatives suspended rather than deleting them, applies the grounded correction separately to every path, and then replans from the corrected forest.

6. Keep the model input bounded

No model receives the entire video, hidden answers, or unconsolidated history. The Qwen-LoRA IWM receives compact current evidence/hypothesis, legal target descriptors, and cursor-local L1.5 rows, then emits all legal-action effects in one pass. It never receives unselected source clips or a mandatory bounded Frontier.

surprise-written, fixed-capacity L1 nodes + complete retained temporal/correlation graph + one current-node cursor → all legal actions in one batched IWM forward → partial-order planner

The displayed all-action path is the current plan. A future scalable Frontier may propose a bounded subset only as an explicit recall-audited efficiency arm matched against this all-node reference.

Unread target nodes expose compact key/address representations; their full evidence values are revealed only after execution. Qwen/Qwen3-VL-Embedding-2B vectors remain in sidecars and serve as semantic action features—not a main-arm ranking gate, reward, or supervision.

7. Belief correction and the GTSAM backup

The main method uses a latent belief update after each real observation. GTSAM/factor graph is retained as an optional correction backend, baseline, diagnostic oracle, teacher, and visualization tool.

default: iwm_belief_only optional correction: iwm_with_gtsam_backup baseline/ablation: gtsam_always

Only executed, provenance-bearing, categorically verified observations may become factors. Imagined rollouts never enter persistent belief. Backup activation uses explicit categorical conditions such as identity ambiguity, contradiction, state-history conflict, or failed correction—not a hand-set posterior threshold.

GTSAM does not generate actions, traverse the graph, rank candidates, predict transitions, or ground the final answer. The main contribution must survive without it.

Supervision and training · Qwen-LoRA IWM planned; Planner + Perception TBD

8. Learning signals and post-training strategy

We will craft training records from Video QA datasets that provide questions, answers, and localized or reconstructible evidence. CG-Bench supplies the cleanest human clue intervals and terminal answers; compatible multi-clue/readiness subsets from other streaming benchmarks can be added only when their evidence provenance can be reconstructed without leakage. Executing a clue read yields categorical progress such as advances_required_clue_coverage, partial, or complete. Complete-clue versus leave-one-clue-out trajectories provide an ordinal preference.

Crafted record = {question, visible memory state, legal actions, evidence-linked next clue/action, real observation, realized per-hypothesis effect, future usefulness, grounded terminal answer or abstention}
  • Unmatched L1.5 candidates remain unlabeled; they are not fabricated semantic negatives.
  • Qwen-VL produces grounded observation descriptors, not GT relation labels.
  • GPT-5.6 visual review is optional diagnosis and does not overwrite CG-Bench ground truth.
  • Identity, state-transition, causal, and counterevidence relations need their own trusted labels.
  • Validation/test videos are never used for training.

Sibling branches executed from the same immutable checkpoint supervise action-conditioned observation and belief-delta prediction, and give pairwise trajectory comparisons without assigning absolute utility.

Node-level SFT for the Qwen-LoRA IWM

The current 256 questions, 205 videos, and 672 grounded clue/read intervals support interface checks and a small learnability pilot, but intervals are not yet final node-level SFT examples. Each question must first be aligned with the adaptive segmentation and complete node tensor:

{question, acquired evidence, hypothesis, bounded descriptors [N], A_corr/A_temp references, cursor-local rows [N,1], legal actions, categorical belief effects [N,C], evidence groups, validity mask}

Each label is positive | trusted_negative | ignore. A clue-overlap node is positive. A semantically similar wrong occurrence/time, a node inconsistent with a before/after condition, or a grounded wrong-choice node may be a hard negative. Mere non-overlap is not a semantic negative: nearby context, coreference introductions, and possible bridge nodes remain ignored. Multiple nodes covering one clue form one positive evidence group. The loss may sample trusted negatives, but forward and runtime scoring still retain every valid node in the buffer.

The first pilot uses video-level splits and compares cosine/timestamp greedy retrieval, frozen-Qwen listwise prompting, and rank-8/16 LoRA SFT. Training randomizes node presentation order and reports permutation consistency. Q-Former/Set-Transformer readers remain latency, dense-token, and distillation ablations. LLM/VLM assistance may propose temporal types, paraphrases, or negative candidates, but generated numeric relevance/utility is not supervision.

Does the IWM need training?

The QA Planner need not be trained initially. It can remain a frozen deterministic typed comparator over categorical effects, budgets, and persistent paths, isolating Planner behavior from IWM quality. A prompted pretrained model is a useful zero-shot IWM baseline; the claimed IWM should be SFT-trained on real sibling executions unless the zero-shot model passes the same held-out transition gate.

input = question + acquired evidence + hypothesis + legal target descriptors + G^corr [N,1] + G^temp [N,1] target = realized categorical belief effect per legal action + answerability transition + contradiction/redundancy status

The primary target is the categorical effect realized after a real read, not an invented exact future caption. Data must include useful-now, useful-later, no-progress, redundant, contradictory, and ambiguous controls; positive clue reads alone cannot train or verify an IWM. Splits are video-disjoint, and the pre-read input never contains a hidden answer, clue identity, or post-read value.

Training route

  1. Establish frozen L1.5 graph-only and frozen-Qwen baselines under the same legal-action contract.
  2. LoRA-SFT the Qwen-IWM on realized action-conditioned categorical belief effects.
  3. Keep the Planner frozen for the first matched causal evaluation so search-policy changes cannot masquerade as IWM gains.
  4. Consider trajectory preference/post-training or low-learning-rate joint tuning only after SFT passes held-out transition and policy-value gates.

Decisive experiment

9. Prove causal dependence on the IWM

Verification has two independent gates. The model gate directly evaluates video-disjoint held-out executed transitions before planning: macro-F1/confusion by outcome class, answerability-transition accuracy, contradiction/no-progress false-positive rates, delayed-positive recall, and calibration, compared with a belief prior, question-node MLP, shuffled node/effect controls, and an oracle-effect ceiling.

The policy gate holds question, evidence memory, every legal node, Planner, and read budget fixed, changing only the world-model condition:

  1. full delayed-belief IWM;
  2. no world model;
  3. shuffled IWM predictions;
  4. frozen IWM;
  5. immediate-effect-only;
  6. oracle clue ceiling, reported only as a diagnostic upper bound.

Report answer accuracy, evidence completeness, read efficiency, action divergence, categorical transition accuracy, and delayed two-hop success separately. Full IWM must improve realized evidence-chain coverage, bridge acquisition, recovery, read efficiency, or answer accuracy over no-IWM and shuffled-IWM controls. Then hold the IWM fixed and compare greedy horizon one with persistent horizon two to test the Planner mechanism separately. If prediction improves but policy does not, the IWM is predictive but not decision-useful; if gains survive shuffled effects, they cannot be attributed to the IWM.

Go / No-Go

10. Evidence required for the claim

Go: the full IWM improves delayed multi-hop success under matched budgets; removing, freezing, or shuffling its predictions changes actions and hurts outcomes; prediction error correlates with navigation failure; and gains persist under candidate-order permutation.

No-Go: the same action sequence appears without the IWM, graph/embedding heuristics explain the gain, imagined evidence leaks into answers, candidate recall is too low to expose the required clue, or only immediate-gain cases improve.
