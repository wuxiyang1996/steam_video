Multi-step Evidence World Model for Grounded Video Reasoning

Predict the non-additive consequences of alternative multi-clue acquisition trajectories, then execute and answer from real evidence.

Current problem formulation · 2026-08-05 · 中文 · Previous formulation (c1829a0) · Baseline results · Repository overview

Challenge

Long-horizon streaming video reasoning under bounded memory and budget

  1. Incomplete bounded memory. Evidence is distributed across a long stream; earlier clues may be compressed, merged, evicted, or never retained.
  2. Temporal uncertainty and answerability. Decisive evidence may be in the past, current clip, or unseen future, so the system must choose among answering, continuing retrieval, waiting for more evidence, and abstaining.
  3. Budgeted multi-clue acquisition. Multiple clues must be retrieved and composed under limited response time, memory/context capacity, real-read budget, and large-model Reasoner calls.
  4. Competing reasoning trajectories. The system must decide which multi-step evidence path is worth executing without exhaustively reading every candidate or running every branch, while never treating a predicted consequence as observed evidence.
TL;DR

Problem: long-horizon streaming QA must recover multiple clues from bounded, possibly compressed or incomplete memory, sometimes wait for future evidence, and decide answerability under strict time and reasoning budgets.

Gap: single-step RAG and greedy reasoning miss conditional or delayed clue combinations; SelectStream improves online evidence allocation, but heuristic graph construction is costly, inflexible, and highly dependent on graph quality.

Our direction: use a graph-free, question-conditioned Q-Former to represent candidate nodes, then a lightweight IWM to preview the joint outcomes of multiple multi-clue and multi-hop trajectories without executing every expensive reasoning branch.

Grounding rule: an answerability-aware Reasoner uses these rollout priors to perform real reads, replan, answer, wait, or abstain; only actually observed evidence can support the final answer.

Core thesis

Reasoning must genuinely depend on the world model

Before every multi-hop reasoning step, an implicit world model (IWM) predicts how legal evidence-acquisition actions may change the future belief. A preference planner compares complete short trajectories, executes only the first hop of a preferred trajectory, observes real evidence, corrects the belief, and replans.

grounded L1/L1.5 evidence memory → bounded candidate reasoning hops → IWM imagined observation and belief transitions → ordinal trajectory preference → execute first hop → real evidence correction → replan

Paper-level contribution: action-conditioned prediction and model-predictive navigation of reasoning dynamics in belief space—not graph construction, generic retrieval, or numeric reward modeling.

1. Problem setting

Online stream, bounded memory. Video clips x_1,x_2,… arrive sequentially and cannot all be retained. The agent has a fixed-capacity memory buffer M_t (at most K entries), so before any question is known it must continually decide when to write and what to write. A write may create a grounded entry, update or merge an existing entry, preserve a salient event at finer temporal resolution, or evict/consolidate less useful evidence; skipping a redundant clip is also an explicit decision. These decisions must be question-independent and may use only the visible prefix x_{1:t}.

M_t = Write(M_{t-1}, x_t, w_t), |M_t| ≤ K w_t ∈ {skip, append, update/merge, consolidate/evict}

Question arrival and evidence routing. A question q may arrive at time t_q, after some relevant event has already passed, while the relevant event is visible in the current clip, or before the decisive event occurs. The agent must infer what evidence the question requires and choose among three temporally distinct sources: (1) query the bounded memory for past evidence, (2) inspect the current clip, or (3) defer the answer and wait for future clips. It may combine evidence from multiple sources and perform multi-hop queries over memory, but it may not inspect unseen future video or treat a prediction as observed evidence.

Evidence location at query timeRequired behaviorMain failure
Past: event occurred before t_qForm a question-conditioned memory query and navigate to retained evidenceThe needed event was never written, was over-compressed, or was evicted
Current: evidence is in x_{t_q}Inspect the live clip and combine it with relevant memory when necessaryHistorical retrieval distracts from direct current evidence
Future: decisive evidence occurs after t_qReturn WAIT/DEFER, monitor subsequent clips, and answer only when evidence is sufficientPremature guessing, indefinite waiting, or missing the trigger event

Thus the problem couples two policies: a pre-query memory policy that allocates scarce storage without seeing the future question, and a post-query reasoning policy that decides what and where to query, whether the evidence is sufficient, and when to answer. Performance is constrained jointly by memory capacity, evidence-read/context budget, and—when waiting is legal—response latency.

s_t = (q, M_t, x_t, E_{1:t}, missing_t, alternatives_t, contradictions_t, read_budget_t, wait_budget_t) a_t ∈ {QUERY_MEMORY(node/relation), INSPECT_CURRENT, WAIT_FOR_FUTURE, ANSWER, ABSTAIN} z_t = Enc(s_t) T_θ(z_t,a_t) → (ô_{t+1}, Δẑ_{t+1}) Pref_φ(τ_i,τ_j | z_t) ∈ {prefer_left,tie,prefer_right,incomparable}

z_t is a latent, multi-token belief state. It need not be an explicit graph posterior. For a legal evidence action, the IWM predicts an observation descriptor and belief change—not the next reasoning sentence and not evidence that may be used directly in the final answer. Only retrieved memory grounded in previously observed clips or a real current/future read can support the answer.

Revised decomposition: the state/action formulation is retained. The new IWM rolls out multi-step clue-combination consequences from Q-Former proposals, while the grounded Reasoner implements the planner/executor role represented above by Pref_φ and the real action loop.
Target regime

1.1 Multi-clue consequences the IWM must model

A relevance model assigns a context-local score r(i|q,z_t) to one candidate node. That score can estimate whether node i looks useful now, but it does not specify what the reasoning state will become after reading a set or sequence of clues. The IWM instead predicts a functional post-acquisition state:

r(i | q,z_t): current single-node relevance C(S_1,…,S_H | q,z_t): consequence of a multi-step acquisition trajectory Δ(i | S) = C(S ∪ {i}) − C(S): prefix-dependent marginal consequence

The marginal consequence Δ(i|S) changes with the acquired prefix S. Therefore a globally ranked node list, or a sum of independent node values, cannot represent all of the cases below.

CaseDetailed multi-clue behaviorIWM prediction target
SynergyClue A identifies an entity and clue B reveals its later state; neither alone determines the answer. A and B may each receive only moderate relevance despite being jointly decisive.Predict that A+B crosses an answerability threshold and resolves a missing evidence role.
Conditional relevanceAfter A identifies a person, object, or event, B becomes interpretable or searchable. Before A, B is ambiguous or appears irrelevant.Predict how the next evidence need and candidate distribution change after prefix A.
RedundancyA and B are both highly relevant but repeat the same observation, paraphrase, or visual state. Reading both wastes budget without increasing coverage.Predict little marginal state change for B after A and preserve budget for a complementary clue.
ContradictionA supports the current hypothesis, while B later supplies grounded counterevidence or invalidates the assumed temporal order.Predict hypothesis reversal, reopened alternatives, contradiction status, and a need to replan.
Delayed valueA does not improve the answer immediately but introduces an entity, location, or event boundary needed to understand C several steps later.Predict positive long-horizon value even when the immediate answerability delta is near zero.
Order sensitivityReading A then B can expose a useful dependency, while reading B first produces an ambiguous observation or consumes budget before its role is known.Distinguish C(A→B) from C(B→A) when the sequence is not exchangeable.
InsufficiencyAll currently visible clues leave a required role unresolved, or the decisive clue belongs to a future clip.Predict continue, wait, or abstain rather than manufacturing answer confidence.

Illustrative long-video trajectory

Suppose a question asks which object caused a later machine failure. An early clip A shows a worker picking up an unlabeled container; a middle clip B briefly reveals its label; a late clip C shows the same worker pouring it into the machine; and clip D shows the failure. A single-step retriever may rank D highest because it matches “failure,” retrieve several redundant failure shots, and miss A or B. The useful chain is A→B→C→D: identity from A+B, action from C, and outcome from D. The IWM should predict that the full chain can complete the causal evidence roles, while C+D remains insufficient and repeated D-like nodes are redundant.

Required prediction object

For each imagined prefix, the model should predict a compact functional state rather than an imagined caption:

r̂(S_1:h) = { answerability, filled and missing evidence roles, next evidence need, answer / read / wait / abstain, redundancy, contradiction, insufficiency }

Thus the core target is trajectory-level and non-additive: C(A,B) ≠ C(A)+C(B). The scientific question is not whether the model can rank relevant nodes, but whether it can predict how alternative clue combinations will change subsequent grounded reasoning before those reads are executed.

Benchmark scope · streaming + multiple clues

1.2 We target multi-evidence streaming Video QA—not every benchmark item is multi-hop

Scope. Our target is streaming video QA in which an answer may require multiple distinct evidence moments and the agent must preserve, retrieve, observe, or wait for them under bounded memory. We use multi-clue or multi-evidence when an instance needs more than one frame/interval. We reserve multi-hop for cases where those clues participate in a dependent reasoning chain. Multiple clues do not by themselves prove an ordered hop structure: two intervals can provide complementary facts without annotating that clue A must be reasoned over before clue B.

SelectStream debrief

1.3 Three research questions about online evidence allocation

SelectStream frames streaming-video memory as budgeted online latent evidence allocation. Its contribution can be summarized by three coordinated research questions:

Research questionSelectStream answerRole in this project
RQ1: When should the stream be written to memory?Use surprise-driven adaptive windowing to close a segment and write when the visual stream changes meaningfully, rather than sampling at a fixed interval.Defines candidate L1 temporal granularity and reduces redundant writes.
RQ2: What should be preserved under fixed capacity?Store latent evidence in a fixed-capacity memory and use priority-preserving consolidation or merging instead of keeping only the most recent observations.Determines which grounded history remains available for later questions; missing or over-compressed clues cannot be recovered by the IWM.
RQ3: What history should be retrieved and exposed for a query?Use query-conditioned routing to select a small evidence set and inject only a bounded number of calibrated latent tokens into the frozen VLM.Provides an efficiency baseline for evidence access, but does not predict the joint reasoning outcome of alternative multi-clue trajectories.

Limitations for flexible multi-clue reasoning

  1. Heuristic graph construction and updates are coarse and cumbersome. Query-time retrieval depends on a graph assembled and maintained through hand-designed surprise, similarity, merge, priority, and edge-update rules. These operations add engineering complexity and make the memory topology slow to adapt when a new question changes which clue relations matter.
  2. Multi-node and multi-subgraph reasoning is expensive. Covering several complementary clues may require retrieving, expanding, and encoding many nodes or multiple candidate subgraphs. The resulting graph reasoning and injected context grow costly and long, especially when several competing evidence chains must be compared.
  3. Performance depends heavily on graph quality. Missing nodes, incorrect merges, weak or spurious edges, and poor temporal/semantic connectivity directly limit what retrieval can reach. Once the required clue chain is absent or distorted in the graph, the downstream model has little opportunity to recover it.
Boundary: SelectStream asks where limited historical evidence should be allocated and how much of it the VLM should see. This work starts from a grounded candidate memory and asks a different downstream question: can a lightweight IWM predict the non-additive consequences of several possible multi-step evidence-acquisition paths before the Reasoner executes them?
Motivation

2. From graph-free proposals to answerability-aware grounded reasoning

The intended setup is a three-stage separation between candidate representation, counterfactual consequence prediction, and grounded execution:

  1. Graph-free, question-conditioned candidate representation. For every eligible node, Q-Former uses the question and the node's permitted pre-read features to generate fixed-size, node-aligned query/proposal tokens. These tokens encode coarse relevance, temporal position, and a possible evidence role. The system does not first build or update an explicit semantic correlation graph. Relations among nodes remain implicit and question-dependent, to be composed downstream rather than frozen as graph edges.
  2. Lightweight exploration of multi-clue and multi-hop outcomes. The IWM composes ordered proposal-token trajectories—one candidate node per imagined hop in the first version—and rolls out how alternative acquisitions may change answerability, missing evidence roles, contradiction, redundancy, and the need to continue or abstain. By previewing several possible reasoning paths in a lightweight model, it avoids paying for a full evidence read and a large-Reasoner execution on every branch.
  3. Grounded, answerability-aware Reasoner execution. The Reasoner receives the current grounded evidence state, candidate evidence trajectories, and IWM-predicted reasoning priors/status. It may execute multi-clue, multi-hop reads, stop early, deviate, or replan while explicitly tracking whether the evidence is sufficient to answer. Predictions guide acquisition, but the final answer and abstention decision must be justified by evidence that was actually read.
Q-Former: node-aligned candidate proposals conditioned on the question IWM: lightweight rollout of multi-clue / multi-hop consequence combinations Reasoner: grounded execution with explicit answerability awareness
Important correction: “implicit correlation” does not mean that Q-Former outputs a hidden adjacency matrix. Q-Former represents each candidate; the IWM models conditional, non-additive interactions among candidates and trajectory prefixes. This keeps the main method graph-free while still allowing question-dependent clue composition.

Factual substrate

3.1 L1 grounded evidence memory

SelectStream-like construction, grounded rather than purely latent. The L1 writer begins from short, fixed-duration video clips, then uses content change, temporal continuity, and memory pressure to merge adjacent clips or expand their scope into adaptive-length evidence nodes. Stable periods can be consolidated into a wider node, while rapid changes or salient events retain finer temporal resolution.

stream → short fixed-interval clips → caption / entity-state / embedding extraction → change- and continuity-aware merge or boundary decision → adaptive-scope grounded L1 nodes under fixed capacity

3.1.1 Online node update and capacity-aware consolidation

The writer makes a question-independent decision whenever a new short segment arrives. Following the useful mechanics of SelectStream, it combines attention drift with feature change: attention drift detects a change in what the segment encoder attends to, while cosine feature change detects a change in visual-semantic content. An exponential moving average provides the local baseline, so a segment boundary is triggered by a surprise spike, an accumulated-surprise budget, or the maximum segment length; the minimum length prevents noisy fragmentation.

s_t^attn = JS(A_t || A_{t-1}) s_t^feat = 1 - cos(g_t, g_{t-1}) s_t = λ s_t^attn + (1-λ) s_t^feat s̄_t = ρ s̄_{t-1} + (1-ρ)s_t

After the segment closes, a lightweight segment encoder produces candidate z_j. A learned write determiner uses its quality/grounding score, surprise, duration, temporal gap, capacity pressure, and similarity to active nodes. It predicts one typed action rather than a vague scalar:

d_j = D_ψ(z_j, quality_j, surprise_j, Δt, {cos(z_j,h_i)}, |M|/K) d_j ∈ {discard_low_quality, merge_update(i*), append_new, consolidate_then_append}

Low quality means unreliable or poorly grounded, not irrelevant to the present question. Because future questions are unknown, the determiner must not discard a valid event merely for low question relevance. If the best feature match exceeds a redundancy threshold and the candidate has low surprise, the writer updates that node; otherwise it creates a new node. A gate preserves history while admitting genuine change:

i* = argmax_i cos(z_j,h_i) γ_j = sigmoid(MLP([z_j; h_i*; s̄_j; Δt; quality_j])) h_i* ← (1-γ_j)h_i* + γ_j f_write(z_j,h_i*)

An update also unions the time span, performs a grounded merge of caption and entity/state fields, retains source provenance and lineage, and increments write/merge metadata. It then invalidates and recomputes the cached question-independent Q-Former tokens U_i in §3.2.1. If capacity would exceed K, the writer consolidates the safest pair: high feature redundancy favors merging, while surprise, access frequency, recency, and evidential quality protect valuable nodes. This adapts SelectStream's priority-preserving consolidation without constructing semantic graph edges.

(u,v) = argmin merge_cost(u,v) merge_cost = dissimilarity(u,v) + protection(u) + protection(v) M ← (M \ {u,v}) ∪ {GroundedMerge(u,v)}

3.1.2 Basic node content as feature embeddings

Caption, entity, visual embedding, and timestamps are the basic content of every L1 node. The node keeps the auditable source fields and also stores their model-facing representations as aligned feature embeddings:

M[i] = [ f_caption(i), f_entity/state(i), f_visual(i), f_time(t_start,t_end) ] f_caption = Proj(Encode(bounded grounded caption)) f_entity/state = Proj(Encode(grounded entities and states)) f_visual = Proj(visual or multimodal clip representation) f_time = temporal embedding of explicit start/end timestamps

All feature slots are projected to a shared dimension and carry explicit validity masks. The raw bounded caption, entity/state fields, and exact timestamps remain alongside the embeddings for provenance, debugging, and tool arguments. Timestamps are therefore stored twice by design: as exact metadata for temporal legality and audit, and as a learned feature embedding for Q-Former/IWM computation.

Each materialized node retains a stable node ID, exact source interval and timestamps, a bounded grounded caption, entities/states when supported, an embedding or embedding reference, provenance/evidence pointers, visibility, lineage/merge history, and read status. L1 is the factual substrate used to support the final answer.

L1 fieldPurposeAccess boundary
Node ID, time span, availability, lineageStable addressing, legality, and auditAlways memory-visible
Bounded caption, entity/state tags, embedding referenceCoarse candidate representation for Q-FormerVisible only under the declared pre-read contract; not sufficient by itself as final answer evidence
Detailed frames, full caption/dialogue, OCR/audio, verified provenanceAuthoritative grounded observationRevealed to the Reasoner only after a real READ(i) or typed evidence tool call

Optional information through tool calling. L1 does not need to precompute every entity relation, dialogue claim, temporal chain, or state change. When the Reasoner needs more detail, it can use the typed, executable infrastructure in Steam_Video_Agents/atomic-skill-decomposition-and-assembly. Available operations include event and entity-history retrieval, temporal-neighborhood lookup, clue/event localization, visual-evidence and dialogue extraction, entity tracking, event ordering, and state-change checks.

Every tool result must return timestamps and evidence references, pass its verifier, and fail closed when the requested information is unavailable. Tool calling is therefore an on-demand extension of grounded reading: it lets the Reasoner obtain the information it needs without storing all possible structure in every node. It does not create semantic graph edges for the main method, and it cannot turn an IWM prediction into a fact.

Before READ(i), downstream models receive only the bounded address/proposal view permitted by the pre-read contract. The authoritative source value remains hidden until execution.

Architecture change: the explicit L1.5 semantic/correlation graph is removed from the main method. Deterministic temporal, visibility, provenance, availability, and budget constraints remain valid masks, but the target design does not construct static semantic adjacency, cursor-local rows, or a graph action compiler.

Existing L1.5, cursor, complete-graph, and full_graph_iwm artifacts remain reproducible historical baselines and regression tools. They do not define the current paper method.

3.2.1 Question-independent node query tokens at craft/update time

To avoid repeatedly attending over the full token sequence X_i for every question, L1 may run a small Q-Former-style node compressor whenever a node is created, merged, or materially updated. A fixed set of learned node queries performs self-attention and cross-attention to the node features:

U_i = Q_base(Q_node, X_i, τ_i^abs) ∈ R^(m_0×d) Q_node: learned query tokens with self-attention Q_node → X_i: cross-attention to token-level node features

U_i is a cached, question-independent summary of node content and absolute time. It must not encode question relevance, answerability, a reasoning trajectory, or a node-to-node relation. It remains bound to node_i and is recomputed whenever the node's source span, caption/entity fields, feature embeddings, or merge lineage changes.

At question time, the question-conditioned Q-Former refines the cached node queries rather than reprocessing the entire clip:

P_i = Q_question(U_i, E_q(q), τ_i^rel) ∈ R^(m×d_w) τ_i^abs = [t_start/T, t_end/T, duration/T] τ_i^rel = [t_start−t_q, t_end−t_q]

This factorization separates node crafting from question-conditioned proposal generation. The first stage can run once when memory changes; the second remains lightweight at query time. Neither stage performs cross-node attention—multi-node and multi-clue interaction still belongs to the IWM.

Output contract

P_i = Q_φ(X_i,q,τ_i) ∈ R^(m×d_w), m = 4 or 8 P = [P_1,…,P_N] ∈ R^(N×m×d_w) P_i ↔ node_i

Each proposal may preserve coarse node content, question relevance, temporal position, and a possible evidence role—enough for the IWM to reason about its joint consequence with other clues. Every token group remains bound to its node ID; global mixing must not erase executable node identity.

Proposal tokens must not directly encode a full caption, final answer, imagined reasoning trace, answerability verdict, next-read decision, or multi-clue consequence. Synergy, conditional relevance, redundancy, ordering, and delayed consequences belong to the IWM.

V1 implementation: use a shared 4–6-layer BLIP-2-style cross-attention Transformer with hidden size 768/1024 and 4–8 queries per node. Precompute frozen node features, warm up representation/clue/time preservation, then freeze Q-Former while learning IWM dynamics. Evaluation in §7 covers clue recall, proposal-only QA leakage, token budget m∈{2,4,8,16}, and node-order consistency. The reference path includes every eligible unread node; any selector is a separately recall-audited optimization.

Counterfactual dynamics

3.3 Multi-step compositional IWM

Single responsibility: given the current real reasoning state and node-aligned Q-Former proposals, cheaply predict the joint reasoning consequences of reading several clues in sequence. The IWM supplies multi-step look-ahead to the Reasoner; it is neither a second Q-Former, a node-ranking policy, nor a QA model.

grounded memory nodes → Q-Former proposal tokens → IWM multi-step consequence rollouts → Reasoner grounded reads and QA / abstain / replan

Grounded initial state and bounded inputs

The initial state is projected from the Reasoner's representation of the question and evidence that has actually been read. A small number of state tokens captures what is known, what remains missing, which clues were read, and whether the answer is approaching sufficiency—without manually specifying a large belief schema.

Z_0 = S_η(H_R(q,E_t)) ∈ R^(M_s×d) P_i = Q_φ(q,X_i,τ_i) ∈ R^(M_p×d) IWM input = (Z_0, P_(1:N), mask_t, b_t)

Every P_i remains bound to its node ID and carries only low-bandwidth pre-read content and time information, not full grounded evidence. The mask enforces visibility, arrival time, already-read/visited status, and trajectory legality; b_t encodes remaining reads, rollout horizon, and wait budget. No L1.5 graph or semantic adjacency is required.

Action-conditioned shared transition

At imagined step h, the model asks what would happen if it next read node i_h. A small latent Transformer reuses the same transition cell across hops:

U_h = CrossAttn(Z_h,P_(i_h)) Z_(h+1) = LN(Z_h + TransitionBlock(Z_h,U_h,e_h)) ρ_k = (i_(k,1), …, i_(k,L_k)), L_k ≤ H

The first version adds one node per imagined hop and uses a small beam (for example H=3, B=4) with optional early halt. Thus A→B→C models a multi-clue combination without enumerating arbitrary node subsets in one action. Parallel clue sets can be added later only if the data requires them.

This transition must be non-additive: C(A,B) ≠ C(A)+C(B). It should distinguish complementary clues from redundant or contradictory ones, recognize when one clue makes another useful, and predict when a path remains incomplete or unrecoverable.

Potential JEPA-style implementation

JEPA is a plausible architectural reference for the IWM, because it predicts abstract target representations rather than reconstructing raw observations. A context encoder can represent Z_h; an action-conditioned predictor consumes READ(i_h) and P_(i_h); and a stop-gradient target encoder represents the teacher Reasoner's state after the evidence is actually read:

Ẑ_(h+1) = Predictor_θ(Z_h, READ(i_h), P_(i_h)) Z*_(h+1) = stopgrad(TargetEnc(H_R(q,E_t ∪ {o_(i_h)})))

This is an implementation option rather than a change to the IWM definition. Unlike a physical-video JEPA, the prediction target is the functional, question-conditioned consequence of evidence acquisition. Next-clue, answerability, contradiction, and insufficiency heads are still required, and the predicted representation still cannot serve as answer evidence.

Rollout output and factual boundary

R_t = {(ρ_k, C_k, u_k)}_(k=1)^B C_k = Pool(Z_(k,1:L_k)) u_k ∈ {CONTINUE, EXPECTED_ANSWERABLE, EXPECTED_ABSTAIN}

Each candidate contains node IDs, only a few latent consequence tokens, and an expected terminal status. These tokens summarize predicted progress, synergy, redundancy, contradiction, and remaining evidence need. They are planning context—not an imagined caption, numeric reward, Q-value, memory write, or final-answer evidence. The terminal label is also only a forecast; the Reasoner makes the real answer/abstain decision after grounded execution.

Training target: functional consequences produced when a frozen teacher Reasoner actually reads clue prefixes and combinations such as A, B, A+B, and A+C. Supervise next-clue distributions, terminal status, functional planning behavior, and every rollout horizon; do not treat the IWM's own imagined state as a factual target. At answer generation time, mask all consequence tokens so the answer depends only on q+E_grounded.

Grounded control

3.4 Reasoner execution and QA

Single responsibility: compare the IWM's predicted multi-step evidence trajectories, choose and execute real evidence reads, react to the observations, judge grounded answerability, and finally answer or abstain.

IWM predicts multi-step consequences. Reasoner performs grounded multi-step execution and QA.

The Reasoner does not encode proposals for every unread node, simulate a large counterfactual tree, predict the contents of unread nodes, or treat an IWM consequence as answer evidence. It is one multimodal tool-using model with two strictly separated runtime modes; a separate Planner LLM, post-read judge, and answerability model are not required.

Control mode: trajectory choice and grounded execution

a_t = R_ψ^control(q,E_t,R_t,m_t,b_t) a_t ∈ {READ(i), REPLAN, WAIT, ANSWER_READY, ABSTAIN}

Control mode receives the question, an evidence ledger containing only observations obtained by real reads, up to B IWM rollouts, execution state, remaining read/wait/replan budgets, and the tool schema. Each rollout exposes its node sequence, a few projected consequence tokens, and terminal prediction. The Reasoner should not receive the full Q-Former proposal bank; otherwise it could bypass the IWM and perform its own unrestricted retrieval.

Typed actionContract
READ(node_id, rollout_id)Read one visible node and append its timestamped observation, provenance, and read order to E_t. One node per call is the v1 default.
REPLAN(reason)Rerun the IWM from the updated grounded state after mismatch, contradiction, path exhaustion, or insufficient progress.
WAITAllowed only when the streaming protocol permits future evidence; disabled for ordinary clue-navigation evaluation.
ANSWER_READYDeclare that current grounded evidence may be sufficient, then switch to the isolated Answer mode.
ABSTAIN(reason)Terminate with a typed cause such as missing evidence, unresolved conflict, exhausted budget, or unrecoverable memory loss.

Multi-step execution means interleaved real tool calls within one continuing episode. After every READ(i), the Reasoner observes the actual result and may continue the predicted path, skip a now-redundant hop, stop early, or replan. It never commits to an entire imagined trajectory as an atomic batch.

READ(12) → grounded o_12 → READ(37) → grounded o_37 → ANSWER_READY or: READ(12) → prediction mismatch → REPLAN

Answer mode: grounded QA only

After ANSWER_READY, the same model performs an independent answer forward with IWM consequence tokens, unexecuted rollouts, Q-Former proposals, and unread-node information removed by the input/attention contract:

y = R_ψ^answer(q,E_grounded) output ∈ {ANSWER(y, evidence_refs), ABSTAIN(reason)}

Every evidence-ledger item retains node ID, timestamp, grounded visual/text content or an auditable feature reference, OCR/subtitles when available, provenance, and read order. The final answer must cite actually read node IDs. Free-form model summaries alone are not sufficient evidence, and fail-closed validation rejects any reference to an unread node.

Training uses complete grounded execution episodes with correct, redundant, contradictory, missing-evidence, and replan cases; the consolidated recipe is in §6.

4. Formal runtime contract

Z_t = S_η(H_R(q,E_t)) P_i = Q_φ(q,X_i,τ_i), i ∈ U_t R_t = Rollout_θ(Z_t,{P_i},H,B) a_t = R_ψ^control(q,E_t,R_t,m_t,b_t) if READ(i): o_i = Execute(READ(i)); E_(t+1) = E_t ∪ {o_i} if REPLAN: recompute Z_(t+1), P, and R_(t+1) if ANSWER_READY: y = R_ψ^answer(q,E_grounded) terminate on grounded ANSWER or ABSTAIN

Every model input is bounded. No model receives the complete video, hidden answers, unselected source clips, or unconsolidated history. Predictions may influence which evidence is acquired, but they can never cross the factual boundary into the answer.

5. Why an action-conditioned world model is necessary

A reactive Reasoner can read and replan by itself, so “supports multi-step reasoning” is not sufficient justification. The IWM must cheaply preview several counterfactual branches such as A→B, A→C, and D→E, avoiding the cost of executing every branch with real reads and large-model calls.

A deep Q-Former or iterative module only refines already supplied features:

z_(h+1) = F(z_h, P)

Depth alone is not a world model. Every IWM step corresponds to a legal evidence intervention and is supervised by the consequence after the teacher executes that same prefix on real evidence:

READ(i_(1:h)) → r*(i_(1:h))

Ordinary iterative reasoning learns how to compute over available features; the IWM learns what an unexecuted acquisition would do to subsequent reasoning. Its value must appear as fewer reads/calls, stronger chain completion, or better grounded QA and abstention under matched budgets.

Go/No-Go: if a reactive Reasoner produces the same trajectories and outcomes under the same budgets, or parameter-matched extra depth explains the gain, the IWM is unnecessary.
Dynamics supervision

6. Training and V1 implementation

Final QA loss alone cannot demonstrate learned dynamics. From the same immutable initial state, the data pipeline executes real clue combinations such as ∅, A, B, A+B, and A+C.

r*(S) = R_teacher(q, E_0 ∪ E_S) r̂(S) = D(T_θ(P,S))

A frozen teacher Reasoner produces functional targets after reading the real evidence. Targets may include answerability, next evidence need, subsequent read distribution, answer distribution, continue | answer | abstain, contradiction, and insufficiency.

Training must cover clue synergy, leave-one-clue-out, redundancy, contradiction, conditional relevance, different prefixes, exchangeable and order-sensitive sequences, missing-key-evidence abstention, and surface-similar hard negatives with no realized clue gain.

Splits are video-disjoint. Candidate order is randomized, teacher branches start from immutable checkpoints, and hidden grounded values never appear in pre-read proposal inputs.

Reasoner model and interface

The recommended main Reasoner is the open-weight multimodal Qwen3.5-9B adapted with LoRA. This is a working implementation choice, not part of the scientific definition; a smaller model and frozen prompting remain necessary scale and adaptation controls.

Execution episodes and trusted labels

(q,R_0) → a_0 → o_1 → a_1 → o_2 → … → y

Next-read supervision must be multi-positive when several clue orders are valid: optimize marginal likelihood over the legal action set instead of marking an alternative valid clue as wrong. A trusted ANSWER_READY label requires grounded evidence on which a frozen teacher answers stably and consistently with the full-video reference, preferably supported by evidence-removal or counterfactual checks. Uncertain states are ignored rather than forced into an answerability class.

ABSTAIN targets come from deliberately removed necessary clues, exhausted budgets, unresolved contradictions, benchmark-unanswerable cases, and leave-one-clue-out states that the teacher judges insufficient. Multiple annotated clue intervals do not automatically imply that every clue is necessary or that their order is unique.

Matched causal evaluation

7. Evaluation and causal gates

Under the same Q-Former, Reasoner, L1 memory, real-read budget, and large-model call budget, compare:

  1. Q-Former proposal tokens directly to the Reasoner;
  2. a parameter-matched deep Transformer or iterative module;
  3. a reactive Reasoner that replans after every real read;
  4. a single-step consequence model;
  5. additive independent-node consequences;
  6. the multi-step compositional IWM;
  7. IWM node sequences without consequence tokens;
  8. IWM consequence tokens without node sequences;
  9. shuffled IWM rollouts;
  10. oracle real post-read consequences;
  11. Answer mode with IWM tokens visible versus the required masked Answer mode.

Run model-scale controls with the smaller Reasoner, the 9B main model, and frozen-9B prompting. Historical graph navigation and explicit planners are optional legacy baselines, not replacements for these matched controls.
