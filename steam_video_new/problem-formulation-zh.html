基于真实视频证据记忆的世界模型引导多跳推理

预测下一跳推理会如何改变未来 belief，执行一次真实证据读取，修正并重新规划。

当前问题定义 · 2026-07-30 · English · Baseline results · 仓库总览 · 已合并 SelectStream + OVO/StreamingBench 讨论

核心命题

推理必须真正依赖 world model

每一步多跳推理之前，implicit world model（IWM）预测各个合法证据获取 action 将怎样改变未来 belief。Preference planner 比较完整的短轨迹，只执行获偏好轨迹的第一跳；获得真实证据后修正 belief，再重新规划。

问题无关的 L1/L1.5 evidence memory → 有界候选 reasoning hops → IWM 想象 observation 与 belief transition → 序数 trajectory preference → 只执行第一跳 → 真实 evidence correction → 重新规划

论文级贡献：在 belief space 中预测 action-conditioned reasoning dynamics，并用 model-predictive planning 导航下一跳；不是 graph construction、普通 retrieval 或数字 reward modeling。

1. 问题设定

在线流与有限记忆。视频片段 x_1,x_2,… 按时间顺序到达，系统无法保留全部历史。Agent 只有固定容量的 memory buffer M_t（最多 K 个条目），因此在尚不知道问题时，就必须持续决定何时写入和写入什么。一次写入可以新建 grounded entry，更新或合并已有 entry，以更细时间粒度保留显著事件，或淘汰/压缩较低价值的旧证据；跳过重复片段也是一种显式决策。所有这些决策必须 question-independent，并且只能使用当时已经可见的视频前缀 x_{1:t}。

M_t = Write(M_{t-1}, x_t, w_t), |M_t| ≤ K w_t ∈ {skip, append, update/merge, consolidate/evict}

问题到达与证据路由。问题 q 可能在时刻 t_q 到达，而相关事件可能已经发生在过去、正出现在当前片段，或尚未在未来出现。Agent 必须先判断问题需要什么证据，再在三个时间位置不同的来源之间选择：（1）查询有限 memory 中的过去证据；（2）检查当前视频片段；（3）暂缓作答并等待未来片段。它可以组合多个来源，并在 memory 上执行 multi-hop query；但不能偷看尚未到达的视频，也不能把预测结果当成已观察证据。

问题到达时证据所在位置Agent 应执行的行为主要失败模式
过去：事件早于 t_q根据问题构造 memory query，导航到已保留的证据关键事件从未写入、被过度压缩或已被淘汰
当前：证据位于 x_{t_q}检查 live clip，必要时与相关历史记忆结合无关历史检索干扰直接可见的当前证据
未来：决定性证据晚于 t_q输出 WAIT/DEFER，继续监测后续片段，证据充分后再回答过早猜测、无限等待或漏掉触发事件

因此，该任务联合了两个 policy：问题到达前的 memory policy 在看不到未来问题的情况下分配稀缺存储；问题到达后的 reasoning policy 决定查询什么、去哪里查询、证据是否充分以及何时回答。系统同时受 memory capacity、evidence-read/context budget 约束；允许等待时，还受 response latency / wait budget 约束。

s_t = (q, M_t, x_t, E_{1:t}, missing_t, alternatives_t, contradictions_t, read_budget_t, wait_budget_t) a_t ∈ {QUERY_MEMORY(node/relation), INSPECT_CURRENT, WAIT_FOR_FUTURE, ANSWER, ABSTAIN} z_t = Enc(s_t) T_θ(z_t,a_t) → (ô_{t+1}, Δẑ_{t+1}) Pref_φ(τ_i,τ_j | z_t) ∈ {prefer_left,tie,prefer_right,incomparable}

z_t 是 multi-token latent belief state，不必等同于显式 graph posterior。对于合法 evidence action，IWM 预测 observation descriptor 和 belief change，不预测下一句 reasoning text，也不能生成直接进入最终答案的想象证据。只有来自已观察历史片段的 grounded memory，或对当前/未来片段的真实读取，才能作为答案依据。

建模假设 · Active perception

1.1 将复杂多跳 Video QA 建模为部分可观测环境中的导航

我们把复杂 video question answering 建模为在初始未知、部分可观测 evidence environment 中进行目标驱动导航。其类比来自 POMDP、SLAM 和 probabilistic robotics：question 定义目标，structured video memory 是不完整且可能有损的地图，合法 read 是 sensing/navigation action，读到的视频片段是 observation，持续变化的 latent belief 则概括答案可能位于何处以及仍缺少哪些事实。这是一种 reasoning abstraction，并不声称视频本身是物理机器人环境，也不把 memory graph 当作度量精确的地图。

POMDP-QA = ⟨S, A, O, T, Ω, q, B⟩ 初始信息：query q + structured memory M action：navigate / retrieve / inspect current / wait / backtrack observation：一条真实、可追溯来源的视频证据 belief update：b_{t+1} = Update(b_t, a_t, o_{t+1}) 终止状态：high-confidence answer | low-confidence answer | abstain

Agent 开始时并不知道完整 evidence route。它从 query 和 structured memory 暴露的地址出发，选择一次交互，接收真实 observation，更新 competing answer hypotheses 与 missing-evidence requirements，然后重新规划。随着一致线索不断累积，有效 reasoning paths 应逐步收缩并汇聚到 evidence-supported answer；如果 observation 相互矛盾或仍不充分，则应保留多个候选、触发 backtracking 或额外 sensing，并最终允许 abstain。只有当评测协议强制要求在残余不确定性下作答时，low-confidence answer 才是合理终点；否则 calibrated abstention 更安全。

Probabilistic robotics 概念Video QA 中的对应项
Unknown environment问题到达时，相关证据的位置和 multi-clue dependency chain 都未知
Map / SLAM state带 temporal 与 soft semantic links 的有界 structured memory；可用于导航，但不完整且可能有损
Sensor action读取 memory node、沿 relation 跳转、检查 live clip、等待未来 observation 或 backtrack
Observation model先预测合法 read 可能揭示什么，再用真实 grounded read 替换预测
Belief / localizationQuestion-conditioned hypotheses、已获得的 support/counterevidence、missing links 和 answerability
Goal / stopping rule获得足够证据后输出 calibrated answer；路径仍无法确定时 abstain

该假设尤其适用于三类场景：

  1. 长视频中的 evidence loss 或 context loss：相关历史只被部分保留，因此 agent 必须在不完美地图上导航、补齐互补线索，并识别证据缺失是否已使答案不可辨识。
  2. 带未来证据的 streaming video：question 可能早于决定性事件到达，因此等待本身是 information-gathering action，过早回答则是一种 planning failure。
  3. 复杂 multi-hop、multi-clue reasoning：任何单个 clip 都不足以回答问题；agent 必须组合时间或语义上分离的 observations，同时保留 alternative paths，并在每次真实 read 后修正 belief。

因此，我们希望得到的是由证据驱动，而不是由分数驱动的 convergence：confidence 可以作为经过校准的 categorical outcome 报告，但 imagined observation、embedding similarity 或模型虚构的 numeric utility 都不能单独为最终答案提供依据。

Benchmark 范围 · Streaming + multiple clues

1.2 我们聚焦 multi-evidence streaming Video QA——并非每个 benchmark 样本都是 multi-hop

任务范围。我们的目标是 streaming video QA：答案可能依赖多个彼此分离的 evidence moments，agent 必须在有限 memory 下保存、检索、观察或等待这些证据。当一个样本需要多个 frame/interval 时，我们称其为 multi-clue 或 multi-evidence；只有当这些线索构成相互依赖的 reasoning chain 时，才称为 multi-hop。多个线索本身不能证明存在有序 hop：两个 interval 可以只提供互补事实，而 annotation 并未规定必须先推理 clue A，再推理 clue B。

multiple clues ≠ necessarily multiple reasoning hops multi-evidence supervision：获得 clue A + 获得 clue B → 证据充分 explicit multi-hop supervision：clue A → intermediate dependency → clue B → answer
Benchmark / 选定子集是否真正 multi-hop？对本项目最合适的监督
完整 CG-Bench否。它覆盖 perception、reasoning 和 hallucination QA；benchmark 提供 clue intervals，但单个样本可能只有一个 clue。通用 clue grounding 与 long-video QA

Benchmark 分工。这些数据集监督 IWM/planner 的不同部分，应使用 dataset-specific masks 组合，而不是强迫它们提供同一种标签：

术语说明 · Annotation vs. reasoning

1.3 Multi-clue 与 multi-evidence 相关，但并不等同

Multi-clue 是 annotation-level property：一个 QA 样本具有两个或更多由 benchmark 标注的相关 frames、timestamps 或 temporal intervals。Multi-evidence 是 reasoning-level property：一个有充分依据的答案需要 agent 获取并共同使用至少两条不同的 grounded facts，与这些事实分布在多少个标注 interval 中无关。

术语可操作定义所属层级
ClueBenchmark 标注的相关 frame、timestamp 或 temporal intervalDataset annotation
EvidenceAgent 真实读取、具有来源依据并用于更新 belief 的事实Reasoning/runtime
Multi-clue至少存在两个不同的 annotated clue regionsDataset selection property
Multi-evidence至少两条不同 evidence items 必须共同出现，才能为答案提供充分依据Reasoning requirement
Multi-hop一条 evidence 支持某个 intermediate conclusion 或 dependency，并影响下一步 reasoning/evidence-acquisition actionReasoning-chain structure

一个 annotated clue interval 可以包含多条 evidence facts。例如，同一个 clip 同时展示人物拿起钥匙，随后用它打开门；该样本可能是 single-clue but multi-evidence。反过来，一个样本可能包含两个 annotated clue intervals，但对于某个具体问题或某次 model execution，其中一个 clue 已经足够；此时它是 multi-clue，但尚不能证明存在 multi-evidence necessity。

本项目约定： 使用 multi-clue instances 作为 multi-evidence QA 的可观测 proxy， 但 multi-clue 不保证每个 clue 都是答案所必需， 也不保证 annotation 中存在显式 multi-hop reasoning chain。
核心方法 · 两个预测模型 + 一个决策模型

2. 面向 Streaming Video QA 的 Frontier-guided Implicit World Model

我们把 question answering 表述为反复执行的 active-evidence loop。首先将 question 转换为 answer hypotheses、required evidence roles、temporal constraints 和初始 missing-evidence state。每一步中，Frontier Model 从当前合法 graph actions 中提出可能包含下一条 clue 的位置；Hypothesis-Effect IWM 想象每个候选 read 可能揭示什么，以及立即或延迟使用它会怎样改变所有 active answer hypotheses；QA Planner 选择一次真实交互，只累积执行后得到的 grounded evidence，并决定继续、回答、等待或 abstain。

Question → missing-evidence belief → Frontier Model：识别可能的 next clue reads → Hypothesis-Effect IWM：想象 observation + 即时/延迟 belief effect → QA Planner：选择一次真实 read / wait / answer / abstain → 观察 grounded clue → 修正 belief → repeat
Related-work map

2.1 Related work：究竟在建模哪个“世界”？

现有工作可压缩为三个相邻方向：结构化 research memory（AutoProf）、可执行 research/science environment（ResearchGym、DiscoveryWorld），以及 learned action-consequence knowledge（WorldEvolver、WKM）。AWM/Agent-World 等 environment generators 与 mechanistic world models 则分别构造外部世界或解释被研究系统。

我们的目标是 problem-solving world：

(B_t, H_t, E_t, A_t) —a_t→ (ô_{t+1}, ΔB_t, ΔH_t, answerability_{t+1}, frontier_{t+1})

IWM 在真实 evidence read 前预测该 action 对 answer hypotheses、missing evidence、answerability 和 future search 的影响，再用真实 observation 修正预测。

问题求解中的既有 Frontier Exploration

2.2 IWM 之前的显式问题空间导航

近期 problem-solving agents 已明显吸收导航思想，但通常显式表示这些结构，而不是学习完整的局部 dynamics：

机制代表工作主要贡献
Persistent map + frontierArbor、PathWise、TREX用 hypothesis/evidence graph 或 search tree 显式记录当前状态，并选择下一个可扩展节点。
Belief-guided explorationBayesEvolve、Evidence-Informed Beliefs用 uncertainty-aware belief update 聚焦探索并减少重复发现。
Search、feedback 与 repairLATS、GATS、SERP引入 tree/graph search、environment feedback、backtracking 与 failure-aware replanning。

二者互补：显式 graph 避免重复探索，并支持可审计的局部修复；IWM 则跨 latent states 泛化，并想象一次 read 的长期效果。在 streaming Video QA 中，L1/L1.5 与 hypothesis/evidence graph 构成 map，Frontier Model 选择可到达边界，真实 read 后再依据 prediction–observation mismatch 修复 belief。据我们所知，既有工作尚未在 multi-clue streaming Video QA 中统一这套完整导航栈。

Module 0 · 合法交互接口

2.3 Reasoning actions 与 Graph Action Compiler

Action 表示 reasoning/evidence query，不是机器人在物理世界中的动作：

A = {start_at, temporal_before, temporal_after, follow_soft_correlation, backtrack, inspect_current, wait_for_future, stop, answer, abstain}

只有存在 live clip 时，INSPECT_CURRENT 才是合法 action。只有 future-evidence/proactive protocol 才允许 WAIT_FOR_FUTURE；它会消耗 latency 或 wait budget，并推进 visible stream，绝不能提前暴露未来片段。当前 CG-Bench clue-navigation protocol 不模拟 free-running query arrival，因此只使用 graph-navigation 子集。

主方法维护一个 active current-node cursor。普通 navigation action 只以该 cursor 为 source；已读取 nodes 保留在 belief/frontier history，需要时通过显式 BACKTRACK/SHIFT_FOCUS 返回。

A_t = outgoing_temporal(current) ∪ positive_direction_soft_correlation(current) ∪ backtrack(acquired frontier history) ∪ protocol_enabled{inspect_current, wait_for_future} ∪ {stop, answer, abstain}

确定性的 Graph Action Compiler 只根据 endpoint validity、streaming visibility、relation status、provenance、executor availability 和 budget 枚举 actions，不按 question relevance 过滤。初始步骤使用 virtual query root，为每个 retained node 提供 START_AT(node)。

输出契约——完整合法动作表： A_t = [{action_id, action_type, source_id, target_safe_address, relation/provenance, executor, protocol_gate, budget_cost}]

Frontier Model 必须接收这个完整集合。Full-IWM control 评估全部 A_t；embedding Top-K 仍是独立 retrieval baseline。

Component 1 · Candidate proposal

2.4 Frontier Model：下一条有用 clue 可能在哪里？

Structural action compiler 首先根据 streaming visibility、graph topology、acquired state 和 budget 枚举全部可执行 actions。Learned Frontier Model 再使用 question、missing evidence roles、已经获得的 clues/evidence、current cursor，以及安全的 temporal/correlation/semantic graph context，从中识别一个有界的 plausible next-clue read 集合。初始步骤可以提出 START_AT(node) anchors；后续则提出合法的 temporal、correlation、backtrack、current-clip 或 wait actions。

Graph input encoding。对 learned model 而言，temporal 和 correlation context 通过可见 node embeddings 之间的 attention scores 编码。Relation type 与 relative time 是 pairwise attention 的输入；legal graph 与 streaming mask 决定哪些 node pairs 可以互相 attention。因此，attention 表示 navigational connectivity，但不能创建非法 edge，也不能暴露 hidden/future node value。

e_i = NodeEmbed(safe_descriptor_i) α_{ij} = Attn(e_i, e_j, TimeEmbed(Δt_{ij}), RelationEmbed(r_{ij})) g_i = Σ_{j ∈ legal_visible_neighbors(i)} α_{ij}[e_j; Δt_{ij}; r_{ij}]
A_t = CompileLegal(M_t, graph, cursor_t, acquired_t, budget_t) C_t = Frontier_ψ(q, B_t, E_t, {e_i, g_i, α_{ij}}, A_t), C_t ⊆ A_t
输出契约——显式 candidate subset： C_t = [{action_id, proposed_missing_role, proposal_rationale, optional_continuation_hint}], C_t ⊆ A_t

该模型回答的是下一步可能值得去哪里看，而不是哪个 candidate 已知就是 clue，也不决定最终获胜 action。它可以读取 safe node addresses、question-independent semantic captions/keys、timestamps 和 typed temporal/correlation proposals；不能读取未执行 node 的 hidden grounded value、未来 frames、answer labels 或 clue annotations。Compiler 仍是确定性的；Frontier Model 是显式 learned proposal stage，其 recall 及其对 planner 的影响必须单独评测。

Component 2 · Predictive dynamics

2.5 Hypothesis-Effect IWM：在 reasoning 中使用这条 clue 会改变什么？

对每个 candidate physical read a ∈ C_t，IWM 做两个相互耦合的预测。Observation head 根据 question、current belief、已获得的真实 evidence、target safe address 以及局部 temporal/correlation/semantic graph context，预测该 read 可能揭示的 categorical descriptor。Effect head 再投影这一可能 observation 将如何改变每个 active answer hypothesis：support/counterevidence/inconclusive status、resolved/opened evidence roles、contradiction change、frontier change 和 answerability。Horizon-two rollout 用于识别立即作用不完整、但下一跳 continuation 可能有用的 clue。

IWM 使用同一组由 attention 得到的 node/edge embeddings {e_i,g_i,α_{ij}}。这里的 temporal/correlation attention pattern 只是描述证据可能如何连接的输入，本身不是 evidence、relevance 或 action utility。

ô_{t+1}^{a} = ObsIWM_θ(q, B_t^{shared}, E_t, a, safe_address(a), {e_i,g_i,α_{ij}}) Δẑ_{t+1}^{a,h} = EffectIWM_θ(B_t^h, h, ô_{t+1}^{a}) τ_t^a = [a, ô^{a}, Δẑ^{a,*}, optional_second_hop]
输出契约——每个 candidate 对应一个 predicted-only joint future： τ_t^a = {action_id, predicted_observation_descriptor, per_hypothesis{support|contradict|inconclusive, roles_resolved, roles_opened, contradiction_change, answerability_transition}, frontier_effect, optional_second_hop}

一次 physical read 必须生成覆盖所有 hypotheses 的 joint future；planner 不能拿某个 answer choice 的 trajectory 与另一个 choice 的无关 physical trajectory 比较。执行前，任何 visual clue 或完整 caption 都只能是 predicted-only；执行后，真实 visual/text observation 与 grounded caption 通过 correction 替换 imagination。Imagined evidence 永不持久化，也不能直接用于回答。

Component 3 · Action and stopping

2.6 QA Planner：测试一个未来，再判断证据是否充分

QA Planner 接收 question、累积的 grounded evidence、current belief、remaining budget 和 IWM 产生的 joint candidate futures。它对完整短轨迹做 categorical comparison，最多选择一个真实 evidence-acquisition action，并丢弃所有未执行的 imagined observations。用真实 clue 修正 belief 后，它只在少量已获得证据上 reasoning，并输出一个 terminal/control decision：

Planner_φ(q, B_t, E_t, {τ_t^a}_{a∈C_t}, budget_t) ∈ {READ(a), INSPECT_CURRENT, WAIT_FOR_FUTURE, ANSWER_HIGH_CONFIDENCE, ANSWER_LOW_CONFIDENCE, ABSTAIN}
输出契约——严格输出一个 decision： d_t = READ(action_id) | INSPECT_CURRENT | WAIT_FOR_FUTURE | ANSWER(answer, confidence_tier, grounded_evidence_refs) | ABSTAIN(reason)

ANSWER_HIGH_CONFIDENCE 要求 grounded 且足够完整的 evidence chain。ANSWER_LOW_CONFIDENCE 只用于评测协议强制在残余不确定性下作答的情况；否则优先 ABSTAIN。只有允许 future evidence 的 streaming protocol 才能使用 WAIT_FOR_FUTURE，并且它会消耗 wait/latency budget。

Closed-loop dynamics

2.7 Dynamic interpretation

同一个 candidate 在不同步骤可能产生不同 effect，因为 missing roles、hypothesis states、acquired clues、cursor、reachable frontier 和 remaining budget 已经变化。因此，IWM 建模的是 reasoning state transition，而不是静态 question–clip similarity。Planner 通过一次真实 read 测试预测中最有价值的 transition，修正状态，再重新运行两个模型。

B_0 + read(search clue) → resolve search_event；open object_found B_1 + read(object clue) → resolve object_found；open object_use B_2 + read(door clue) → resolve instrument_identity；answer ready B_2 + reread(search clue) → redundant / unchanged

核心边界：Frontier Model 提出去哪里检查；IWM 预测该检查可能改变什么；Planner 决定实际执行什么，以及真实累积证据是否充分。三者都不能把 imagined clue 转换成事实。

3.1.1 从视频到 L1 的构建流程

开放问题 · Connectivity

3.1.2 Node context 和 temporal 判定

Node 的 routing key 包含 type、短 grounded descriptor、modality 和 interval。真实 read 返回的 grounded value 还包含完整 caption/predicate/utterance/OCR/state tuple、clip/local IDs、local participants 和 visible attributes、state subject/attribute/value/polarity/temporal scope、evidence-frame 或 subtitle/ASR references、provenance/trust/visibility、incident composition links 和 consolidation lineage。Previous/current/next clip digest 只是 construction-time composer context，不会被复制到 node value；它们的影响只体现在 grounded candidate edges 和 compose audit 中。这些 context 用于 audit 和后续 read，不得包含 answer、motive、跨 clip identity 或 causal conclusion。

Temporal relation 来自确定性 interval test。Node 按 (start_s,end_s,node_id) 排序，相邻 retained nodes 连 temporal_next；若 end(u) ≤ start(v)+10⁻³ s 则为 before(u,v)；during 使用同一 tolerance 的 interval containment；其他相交 interval 为 overlaps。before 只在有界 forward neighborhood 内保存，不建 dense transitive closure。Consolidation 会删除 orphan、rewire 存活非 temporal edges，并按 retained intervals 重建 backbone。时间顺序不证明 identity、change、support 或 causality。

L1 的主导航结构是 grounded semantic nodes 上确定性的 temporal_next/before/overlaps/during backbone。derived_from、entity_mention、state_of、located_in 等 composition links 只保留为 provenance/audit structure。Native same_entity、state_change、causal_hint 属于可选 strict-relation 路径，未通过各自 verifier 绝不成为 navigation fact。

当前修复会在存在字幕时，用 question-independent、time-aligned subtitle 丰富已持久化的 visual L1 node。有限长度的 address key 用于导航，完整 descriptor 仍是执行真实 read 后才获得的 grounded value。未来 visual extraction 还会请求简洁 grounded caption 和带 evidence frame 的 visible text。Descriptor 一旦变化，旧 embedding reference 必须失效；重建 L1.5 前必须重新生成 Qwen/Qwen3-VL-Embedding-2B embedding。

Implementation baseline · Soft navigation graph

3.2 L1.5 correlation overlay

设计变更：早期 L1.5 是 atomic-event causal-temporal belief overlay，尝试接纳 typed explains/enables edges。它容易把 narrative succession 误标为 causality，candidate-causal edges 也未能稳定通过独立 grounding gates。该路径现只作为历史/可选 strict-relation evaluation。当前 L1.5 是 correlation，不是 causality：它在 retained L1 IDs 上建立 question-independent soft navigation overlay。Identity、state transition 和 causality 属于独立 typed layers，不会因为两个 node 相关就进入 L1.5。

  1. 冻结 enriched/consolidated L1 descriptor；descriptor 一旦改变，旧 embedding 立即失效。
  2. 用 Qwen/Qwen3-VL-Embedding-2B 编码所有 node，L2 normalize，并对每个 unordered pair 计算 cosine s(i,j)=eᵢ·eⱼ。
  3. 已被 temporal backbone 覆盖的 pair 不再作为 nonlocal correlation 接纳，但仍保留完整 audit row。
  4. Cosine ≥ 0.999 的 nodes 归并为 semantic-equivalence class。不合并的不同时刻 recurrence 只按时间连下一次 occurrence，不建 clique。
  5. 对 class 内 embedding 求均值后重新 normalize。对每个 source class，将全部 positive class cosine 按该 source 在当前视频内的 mean/variance standardize，再应用 sparsemax；zero-mass pair 不输出，全程没有 fixed Top-K。
  6. 对 admitted class pair，先选 raw cosine 最高的 endpoint pair，再以最小 temporal separation 和 stable ID 破同分。Sparsemax 会从两个 source direction 产生 proposal，但 cosine 是 symmetric signal，当前 edge 取两个 proposal mass 的最大值作为相同的双向 navigation affinity，不伪造 directional semantic fact。
  7. 应用一个冻结的 global channel/cosine/positive-affinity policy，并记录每个 pair 的 admission/exclusion reason、model/checksum、policy fingerprint 和 frozen-L1 fingerprint。

Temporal edge 是精确 interval constraint；correlation edge 是有 representation 支持的稀疏候选导航路径。Temporal proximity 不会单独创建 correlation，cosine 也不能单独保证 admission，因为还要经过 temporal exclusion、equivalence-chain、sparsemax 和 global-policy gates。Similarity/affinity 不是 probability、confidence、identity、state transition、support、causality、relevance 或 action utility；独立验证过的 categorical facts 单独保存。

边界 · Topology 不是 Policy

3.3 Correlation 不是 action preference

L1.5 correlation：确定有支持的 node-to-node 可导航邻接 → legal-action compiler：暴露可执行的 cursor-incident hops → IWM：预测每一跳的 categorical observation 和 belief effect → planner：根据这些预测选择下一跳

这条边界是强制的。Correlation 负责构建 question-independent graph topology，不负责针对问题选出 winner。IWM/planner 可以消费固定 correlation edges，但不能在 action selection 时创建、验证或重分类这些 edges。来自测量的 embedding similarity、directional affinity、calibration 和 provenance 可以是数值 graph features。“模型不输出数字”的规则限制的是用于 planning 的虚构 reward、utility、Q-value、probability 或 confidence，不是这些可测量的建图特征。Edge affinity 绝不能直接排序并决定获胜 action。

L1/L1.5 永不保存 correct answer、hidden clue identity、question-conditioned belief、IWM imagination、predicted belief delta、planner trajectory、reward/utility/Q-value、GTSAM posterior 或 final claim。这些分别属于 hidden evaluation、latent belief 或 executed L2 trace。

Implementation baseline · SelectStream

3.4 SelectStream：有预算的在线潜在证据分配

核心想法。SelectStream（arXiv:2606.16353v1）的核心不是“如何保存更多视频”，而是：在固定的 memory 和 context budget 下，在线决定何时写入、保留什么、查询时读取什么，以及最终向 VLM 暴露多少历史证据。

传统方法通常走两个极端：

  • Recent-window：只看最近的视频，当前感知清晰，但容易忘掉早期关键事件。
  • Large memory / replay：保存并注入大量历史，虽然覆盖更长，但无关历史会稀释当前场景，并增加计算量。

SelectStream 的解法：当前画面始终直接输入 VLM；历史压缩成固定容量 latent evidence graph；只有与当前问题相关的一小部分历史证据被取出，并以少量 latent tokens 注入。

Streaming video ↓ 1. SAW — Surprise-driven Adaptive Windowing （何时写入？） ↓ 2. LVM — Latent Visual Memory Graph （写什么 / 容量 N 下保留什么？） ↓ 3. GAR — Query-conditioned Graph Reasoning （读哪些历史证据？预算 B） ↓ 4. Latent Evidence Injection （向冻结 VLM 暴露 M 个校准 token） ↓ Answer 论文默认预算：N=256 memory nodes · B=64 routed subgraph · M=8 evidence tokens

与本 IWM 工作的边界：SelectStream 导航的是证据存在哪里（可寻址 nodes + graph edges），以及冻结 decoder 能看到多少历史。本项目保留 grounded L1/L1.5 作为证据底物，进一步问：IWM 能否预测合法 hop 如何改变未来 belief，以及 planner 是否应执行该 hop。固定容量、surprise 写入的 L1 是兼容基础设施；把 latent tokens 注入冻结 VLM 不是我们的主 claim。历史的“无 nodes/edges、对连续语义状态做 operation-conditioned soft read”（dynamic-navigation 文本 proxy）是另一条已 No-Go 的路径，不是当前 CG-Bench IWM 协议。

4. 短视界 model-predictive reasoning

  1. 从单一 current-node cursor 和固定 L1.5 graph 枚举全部合法 actions；
  2. Frontier Model 从完整合法集合中提出 plausible candidates；
  3. 为每个 frontier candidate 想象 horizon-one 或 horizon-two categorical transition；
  4. 对完整候选轨迹做 pairwise comparison；
  5. 只执行唯一获偏好轨迹的第一跳；
  6. 丢弃 imagined observation，读取真实证据，更新 belief，再规划。
τ* = PreferredTrajectory({Rollout_T(z_t,a)}_a) a_t* = First(τ*) o_{t+1} = Execute(M,a_t*) z_{t+1} = Update(z_t,a_t*,o_{t+1})

World model 的价值体现在 delayed effect：第一跳可能几乎没有即时收益，却能打开一个 bridge，让第二跳补全关键证据。这是它区别于 reactive retrieval 或 immediate information-gain ranking 的核心。

Learned IWM 在一次 batched graph/tensor forward 中预测全部 frontier first hops；Full-IWM control 则预测全部合法 first hops。Horizon two 只能先移除 strictly dominated first hops，再为剩余 partial-order set 展开全部 second hops；不能使用 fixed-K beam pruning。

当前 reasoning_v2 planner 保留由不同 hypothesis 与 action history 构成的竞争路径森林。一个 joint action tree 必须在同一个 shared physical first read 下覆盖所有仍存活的 answer hypotheses。Planner 每轮只调度一次真实 read，未选路径保持 suspended 而不是被删除；grounded correction 分别作用于每条路径，然后从修正后的森林重新规划。

6. 控制模型输入大小

任何模型都不接收整个视频、raw embedding matrix、hidden answer 或未 consolidation 的全部历史。由于 L1 memory 容量固定，Frontier Model 可以在不做 Top-K truncation 的情况下检查完整 retained safe graph：question/belief tokens、全部 retained node keys、temporal/correlation edges、全部合法 actions、recent history 和 budget status。IWM/planner 随后只接收显式有界 frontier、已获得的真实 evidence，以及想象和比较这些 actions 所需的局部 graph context。Full-IWM control 则把全部合法 actions 传给下游。

7. Belief correction 与 GTSAM backup

主方法在每次真实 observation 后更新 latent belief。GTSAM/factor graph 保留为可选 correction backend、baseline、diagnostic oracle、teacher 和 visualization 工具。

默认主方法： iwm_belief_only 可选纠错： iwm_with_gtsam_backup baseline/ablation：gtsam_always

只有真实执行、带 provenance、经过 categorical verification 的 observation 才能成为 factor；imagined rollout 永远不能写入 persistent belief。Backup 只由 identity ambiguity、contradiction、state-history conflict 或 correction failure 等显式 categorical condition 触发，不依赖手设 posterior threshold。

GTSAM 不生成 action、不遍历 graph、不排序候选、不预测 transition，也不为最终答案提供 grounding。主方法贡献必须在不使用 GTSAM 时仍然成立。

8. Learning signal 与 Post-training 策略

我们将从同时提供 question、answer 与可定位或可重建 evidence 的 Video QA datasets 中构造训练数据。CG-Bench 提供最干净的人工 clue intervals 与 terminal answers；其他 streaming benchmarks 的 multi-clue/readiness subsets 只有在 evidence provenance 可无泄漏重建时才加入。执行一个 clue read 可以得到 advances_required_clue_coverage、partial 或 complete 等 categorical progress；完整 clue 轨迹与 leave-one-clue-out 轨迹提供 ordinal preference。

Crafted record = {question, visible memory state, legal actions, evidence-linked next clue/action, real observation, realized per-hypothesis effect, future usefulness, grounded terminal answer or abstention}
  • 未匹配的 L1.5 candidate 保持 unlabeled，不能伪造成 semantic negative；
  • Qwen-VL 生成 grounded observation descriptor，不冒充 GT relation label；
  • GPT-5.6 visual review 只是可选诊断，不能覆盖 CG-Bench ground truth；
  • Identity、state-transition、causal 和 counterevidence 需要各自可信的标注来源；
  • Validation/test 视频永不参与训练。

从同一 immutable checkpoint 执行 sibling branches，可以监督 action-conditioned observation、belief-delta prediction 和 pairwise trajectory comparison，而不必给任何轨迹赋绝对 utility。

Training route

  1. 对 Frontier Model 做 SFT：使用从 evidence-annotated Video QA 构造的 evidence-linked next-action/candidate targets 与 proposal rationales。
  2. 对 IWM 做 SFT：学习真实 action-conditioned observation descriptor、逐 hypothesis belief effect，以及 delayed/future usefulness。
  3. 对 Frontier + IWM 做 GRPO：SFT 后，从同一 immutable state 组成 legal candidate action 或 sibling-trajectory groups，并根据 grounded evidence coverage、transition correctness 与 terminal QA outcome 计算 group-relative advantage。

决定性实验

9. 证明 planner 因果性依赖 IWM

固定 question、evidence memory、candidate set、planner 和 read budget，只改变 world-model condition：

  1. 完整 delayed-belief IWM；
  2. no world model；
  3. shuffled IWM predictions；
  4. frozen IWM；
  5. immediate-effect-only；
  6. oracle clue ceiling，只作为诊断上界。

Answer accuracy、evidence completeness、read efficiency、action divergence、categorical transition accuracy 和 delayed two-hop success 必须分开报告，不能压成一个 lexicographic gate 或 scalar utility。

Go / No-Go

10. 支撑研究结论所需证据

Go：在 matched budget 下，完整 IWM 提升 delayed multi-hop success；移除、冻结或打乱预测会改变 action 并降低结果；prediction error 与 navigation failure 相关；收益在 candidate-order permutation 下仍存在。

No-Go：没有 IWM 仍产生相同 action sequence；收益可由 graph/embedding heuristic 解释；imagined evidence 泄漏进答案；candidate recall 太低而无法暴露所需 clue；或只有 immediate-gain case 获益。
