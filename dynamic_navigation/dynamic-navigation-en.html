Dynamic Navigation in Semantic Space

Operation-conditioned reads over fixed latent memory

Discussion notes · 2026-07-14 · 中文 · aligned with steam_video_new

Narrow definition

Not embedding retrieval — previous-step-conditioned semantic read actions

Feasible, but define it narrowly: not nearest-neighbor search in embedding space, and not an implicit graph. The query state executes a sequence of semantic read actions over fixed latent memory tokens, each conditioned on the previous step (test-time latent reasoning).

previous-step-conditioned action policy + action-specific read over fixed semantic memory + support-progress reward

Dynamics live in the query state and action / reader control, not in the memory structure: M_t is fixed — no nodes, edges, timestamps, or Top-K evidence items.

SelectStream · Key Idea

0. SelectStream — Core Idea

EN — Core idea. SelectStream is not about “how to store more video.” Under a fixed memory and context budget, it decides online when to write, what to keep, what to read at query time, and how much historical evidence to expose to the VLM.

ZH — 核心想法。 SelectStream 的核心不是“如何保存更多视频”，而是：在固定的 memory 和 context budget 下，在线决定何时写入、保留什么、查询时读取什么，以及最终向 VLM 暴露多少历史证据。

Prior methods usually sit at two extremes:

  • Recent-window: only the latest video — sharp current perception, but early critical events are easy to forget.
  • Large memory / replay: store and inject lots of history — longer coverage, but irrelevant past dilutes the current scene and raises compute.

SelectStream’s fix: the current frame always goes straight into the VLM; history is compressed into a fixed-capacity latent evidence graph; only a small, query-relevant slice of historical evidence is retrieved.

current frame → VLM (full perception, always) history → fixed-capacity latent evidence graph → query-conditioned retrieve small evidence → inject few latent tokens into frozen VLM
SelectStream · Method

0b. SelectStream — Overall Method

Streaming video ↓ 1. Surprise-driven Adaptive Windowing — When to write? ↓ 2. Latent Visual Memory Graph — What to write / keep under capacity? ↓ 3. Query-conditioned Graph Reasoning — Which historical evidence for this query? ↓ 4. Latent Evidence Injection — Compress & inject into frozen VLM ↓ Answer

The system maintains a dynamic memory graph G_t = (M_t, E_t):

  • M_t: fixed-capacity memory nodes;
  • E_t: temporal and semantic relations among nodes;
  • each node stores projected visual embeddings for a video segment, plus time range, surprise, and other metadata.

What is stored is neither raw frames nor text summaries, but latent embeddings already passed through a frozen VLM visual encoder and multimodal projector — so they live directly in the language model’s embedding space.

1. Surprise-driven Adaptive Windowing — when to write

Not every moment in a continuous video is equally important: ten seconds of a static scene need not become ten memory entries; a person entering, an object-state change, or a scene cut should be stored at finer grain. Per-timestep surprise:

s_t = λ s_t^attn + (1−λ) s_t^feat s_t^attn = JS(A_t ∥ A_{t−1}) # attention shift s_t^feat = 1 − cos(g_t, g_{t−1}) # feature change

Low surprise → longer windows that fuse stable content into one memory entry; high surprise → early window close and finer nodes near the change. Result: coarse for stable segments, fine for critical turns — not “pick the top-k surprise frames,” but surprise-driven temporal segmentation and memory resolution.

2. Latent Visual Memory — what to keep when full

When an adaptive window ends, visual tokens are aggregated into the graph. A node may be a stable interval, an important state change, or a short high-surprise event. Capacity N is fixed, so SelectStream does priority-aware consolidation: keep / merge / evict.

Priority mixes surprise, novelty, temporal relevance / recency, redundancy with other nodes, and whether a node already carries important relations. Low-priority similar nodes merge more readily; high-surprise, unique, or well-connected nodes are protected. Not FIFO and not “last N segments only”:

new evidence ↓ compare with existing nodes ↓ preserve important nodes merge redundant nodes remove low-value evidence

Long video is compressed into a non-uniform-resolution latent evidence graph: dense on important events, sparse on stable background.

3. Graph Attention Reasoning — what to read after a question

The full memory graph is not fed to the VLM. The question is encoded as a query; nodes are scored in a query-conditioned way to find seed nodes; then graph relations expand them into a small evidence subgraph under budget B.

Example: “Where did this person put down the cup earlier?” may seed on “cup reappears,” then expand to earlier cup appearance, picking up the cup, and putting it down. Relations include temporal adjacency / overlap, semantic similarity, and event or state continuity.

Key difference: top-k retrieval finds several independent similar clips; GAR tries to find a related set that forms an evidence chain — more important for multi-hop and temporal reasoning.

4. Latent Evidence Injection — how a frozen VLM uses history

Retrieved nodes are graph-aware aggregated, compressed to a fixed count M of evidence tokens, calibrated by query and evidence confidence, then injected into the frozen VLM input embedding sequence:

[query tokens] [current visual tokens] [small set of retrieved historical latent tokens] # NOT: [query] + [all previous frames] + [current frames]

Design rule: the current frame stays fully visible (not replaced by memory compression); history is selectively visible only via a few query-conditioned latent tokens — less historical noise on the current scene.

The real contribution is not only “graph memory,” but casting streaming memory as a budgeted online evidence allocation problem under budgets N (memory), B (subgraph), and M (injected tokens).

One-liner / 一句话： SelectStream uses surprise to set storage granularity, a fixed-capacity latent graph to merge/keep evidence, retrieves a small multi-hop evidence subgraph for the query, and compresses it into latent tokens injected into a frozen VLM. SelectStream 用 surprise 决定视频历史的存储粒度，用固定容量 latent graph 动态合并和保留证据， 再根据问题检索一个小型多跳证据子图，并将其压缩成 latent tokens 注入冻结 VLM。

Boundary vs. this dynamic-navigation work: SelectStream navigates where evidence lives (addressable nodes + graph edges); this work navigates which transformation to apply over a fixed continuous semantic state (no nodes/edges; operation-conditioned soft read).

1. Most stable implementation path

context / stream → fixed memory M ∈ R^{N×d} u_0 = E_Q(q) r_0 = ∅; a_0 = START for k = 1..K: # test-time unrolling choose action a_k | (u_{k-1}, r_{k-1}, a_{k-1}, q) action-specific read of fixed M → r_k update query state → u_k optional: if a_k = STOP: break answer from u_K

What changes at each step:

  • u_{k-1}: current question state
  • a_k: semantic read action conditioned on the previous step
  • reader: action-specific CrossAttn / FiLM / LoRA
  • u_k: updated question state after the read
Encoder

1b. Text embeddings: frozen Qwen3-Embedding-2B

For the multi-hop Text QA proxy, all context / question embeddings come from frozen Qwen3-Embedding-2B (HF: Qwen/Qwen3-VL-Embedding-2B, text mode; dim = 2048). The encoder is an implementation choice, not the contribution; trainable parts are the resampler / navigator / answer head.

E = Qwen3-Embedding-2B # frozen # paragraph- or sentence-level tokens → fixed memory Z = E(context paragraphs) M = Resampler(Z) ∈ R^{N×2048} # N fixed, e.g. 16/32/64 u_0 = Proj(E(q)) # same frozen encoder a_emb = E(answer candidates) # for m_k scoring
  • Week 0.5: keep the encoder fully frozen; first verify EM/F1, m_k, and hop/type breakdown are computable.
  • Do not collapse memory to a single mean-pooled vector; keep N latent tokens.
  • No Top-K passage retrieval; compress the full distractor context into fixed M.
  • Later video work can stay in the same Qwen embedding family so text-proxy gains transfer cleanly.

Action policy backbone (separate from frozen encoder):

  • MLP (default / Week 0.5): small π(a|u,r) head.
  • BERT: good lightweight choice for the discrete-action main method.
  • Qwen3.5-2B: optional stronger policy; usually overkill once state is already continuous embeddings — use as a control, prefer BERT/MLP by default.

2. Two-phase method: Week 0.5 soft mixture → main action policy

Week 0.5 (metric smoke) — soft action mixture

First use a differentiable soft mixture to verify the data pipeline, EM/F1, m_k, and hop/type breakdown. No hard discrete decisions yet.

u_0 = E_Q(q) π_k = softmax(g(u_{k-1}, r_{k-1}, q)) e_k = Σ_a π_{k,a} e_a α_k = softmax(Q(u_{k-1}+e_k) K(M)^T / √d) r_k = α_k V(M) u_k = GRU(u_{k-1}, r_k, e_k)

Main method (paper claim) — action policy + action-specific read + progress reward

After metrics work, upgrade to previous-step-conditioned discrete read actions (optional STOP). This is test-time latent reasoning — not text CoT, not a retrieval agent.

A = {GROUND_ENTITY, RESOLVE_EVENT, TRACE_STATE, LINK_TEMPORAL, CHECK_CONFLICT, COMPOSE, STOP} state_k = [u_{k-1}; r_{k-1}; a_{k-1}; E(q)] π_k = softmax(W state_k) a_k ~ π_k # train: soft / ST-Gumbel; test: argmax or sample K_k, V_k = FiLM_{a_k}(K(M), V(M)) # or LoRA_{a_k} r_k = CrossAttn(Q(u_{k-1}), K_k, V_k) u_k = GRU(u_{k-1}, r_k, e_{a_k}) # if a_k = STOP: break

Actions only decide how to read fixed M — not which passage to retrieve, and not external tools.

3. Training signal: progress reward drives action switches

Do not claim “multi-step attention” alone. Each step must make the answer more discriminable; that is also the main reason to switch actions.

m_k = s(a⁺ | u_k) − max s(a⁻ | u_k) L_progress = Σ_k max(0, m_{k-1} + δ − m_k) # progress reward / hinge L = L_QA + λ_p L_progress + λ_a L_action + λ_c L_comp
  1. L_action: weak imitation from question type / teacher sketches (bridge: GROUND→TRACE→COMPOSE; comparison: GROUND→CHECK→COMPOSE). Shuffled sketches are negatives.
  2. L_progress: force rising m_k; encourage switching after new useful semantics are read.
  3. L_comp: discourage repeating the same action / latent direction.

Key interventions: shuffle actions, force one action, remove action-specific FiLM/LoRA. If these do not hurt, the action claim fails.

4. Correct claim in our setting

Dynamic navigation = previous-step-conditioned semantic read actions over fixed latent history — not path search in embedding space, and not text CoT.

  • fixed history semantic state;
  • action policy conditioned on (u_{k-1}, r_{k-1}, a_{k-1}, q);
  • action-specific reader over the same M;
  • progress reward drives step-wise answer support.
M = fixed semantic memory tokens u_0 = question embedding a_1=GROUND, u_1 = read(M, u_0, a_1) a_2=TRACE, u_2 = read(M, u_1, a_2) # conditioned on step 1 a_3=LINK, u_3 = read(M, u_2, a_3) a_4=COMPOSE, u_4 = read(M, u_3, a_4)
Support-progressive semantic navigation via previous-step-conditioned read actions over fixed latent history

5. Video example

Question: Who finally took the red bag that was initially on the table?

  1. GROUND_ENTITY: bind the latent “red bag” entity.
  2. RESOLVE_EVENT: recover early on-table state and later moves.
  3. TRACE_STATE: track possession / location changes.
  4. LINK_TEMPORAL: lock the last handoff / pickup.
  5. COMPOSE: assemble person, object, and order into the answer.

Not retrieving a “red-bag frame,” but recovering complementary latent semantics from M_t.

The navigator progressively transforms the query state to extract complementary answer-supporting semantics from a fixed latent history state.

Do not say: The navigator retrieves evidence chains.
Return answer-supporting latent semantics, not source-traceable evidence.

Risks & gates

8. Three real risks + Go / No-Go

  1. If shuffling operations does not hurt, operations are decoration.
  2. If a deeper one-shot reader matches, navigation is unnecessary.
  3. If fixed M_t already lost temporal handoff / object continuity, no navigator recovers it.

Go: full navigator > plain recurrent > one-shot; shuffle hurts; margins rise step-wise; gains concentrate on multi-hop / temporal / distractor cases.

No-Go: deeper one-shot matches full navigator; shuffle is harmless; progress loss adds nothing; only synthetic text works and image proxy fails completely.

Hard bar: matched FLOPs, full navigator must beat deeper one-shot, plain recurrent attention, and latent deliberation; and m_0…m_K must show rising step-wise support margin. Otherwise the idea collapses to “Qwen embedding + recurrent attention.”

Causal Navigation

9. Counterfactual causal navigation (V3 implemented)

V3 preserves frozen token hidden states and writes them into 32 fixed latent slots with a masked Perceiver. It replaces discrete actions with answer-contrast-conditioned continuous directions and uses low-temperature cosine routing, making direction the only addressing signal:

d_k = E(a_k^1) − E(a_k^2) z_k = Policy(u_{k-1}, r_{k-1}, d_k, C_{k-1}) r_k = softmax(cos(z_k, K(M))/τ)V(M)

Training includes do-removal causal necessity and a contrastive intervention requiring a learned direction to beat a random direction from the same state. Evaluation also uses in-distribution batch-shuffled learned directions.

Final Hotpot 8-candidate result (4096 train / 512 validation): causal navigator 65.04%, token one-shot 63.09%; four-step margin rises from 1.951 to 2.089. do(r=0) collapses accuracy to 0.39%, proving that reads are necessary for the trained mechanism. But shuffled directions retain 64.45%, a drop of only 0.59 points, below the preregistered 2-point gate. The gain therefore comes mainly from recurrent contextual reading, not causally necessary semantic direction selection. Verdict: NO-GO for causal navigation.

Prior Work

10. MERLIN: from interactive embedding refinement to autonomous evidence-space navigation

MERLIN (Han et al., EMNLP Industry 2024) is close prior work. For text-video retrieval, it generates a clarification question from current top-1 anchor-video metadata; a human-simulating agent that can observe the user's “video in mind” answers it. The answer embedding is merged with the previous query by SLERP:

e_answer^r = Enc(answer_r) θ = arccos(e_answer^r · e^{r-1}) e^r = sin((1−α)θ)/sinθ · e_answer^r + sin(αθ)/sinθ · e^{r-1}, α = 0.8

A high α preserves earlier query semantics and mitigates drift. MERLIN is training-free and fixed-round: no learned transition, reward, stopping, branching/backtracking, or cross-step credit assignment. It reports five-round R@1 gains of 44.40→78.00 on MSR-VTT, 52.39→77.61 on MSVD, and 56.58→68.44 on ActivityNet. However, candidate pools contain only 500 / 670 / 919 videos, and each round receives new information from an oracle-like agent observing the ground-truth target. The evidence therefore supports continuous aggregation for interactive single-target reranking, not autonomous evidence-chain discovery; its ablation also does not fully isolate SLERP from question selection and repeated feedback.

Boundary relative to our work

  • MERLIN: one fixed hidden target; feedback progressively completes its description; an external user injects information.
  • Multi-hop QA: the evidence target changes by hop; the system must derive the next subgoal from evidence already read; no oracle user exists.
  • Novelty boundary: iterative movement of an embedding is already prior work. A defensible claim requires learned autonomous transitions across multiple evidence targets with causal direction/path interventions.

Direct insight for the failed V3 experiment

Every MERLIN move is anchored by a semantically grounded external answer. V3 generates direction mainly from its own state and candidate contrast, without hop-specific grounded feedback, so direction can collapse into a shared step code. This matches the observation that Gaussian noise lowers margin while shuffling valid directions across examples barely changes accuracy.

r_k = Read(M, z_k) f_k = EncodeEvidence(r_k / bridge entity) η_k = Trust(state, entropy, consistency) z_{k+1} = GeoUpdate(z_k, f_k; η_k) operation_k ∈ {REFINE, TRANSITION, BRANCH, BACKTRACK, VERIFY, STOP}
  1. Add matched-feedback baselines: one-shot, passage-concatenation re-encoding, query rewriting, linear interpolation, MERLIN-style SLERP, and learned transition.
  2. Use direction only for addressing; do not feed it directly into the answer GRU. State should change through evidence actually read.
  3. Train with in-distribution counterfactuals: another example's same-hop direction, a wrong support paragraph, or a wrong bridge entity—not Gaussian noise alone.
  4. Learn a trust weight η_k and retain an original-query anchor to control drift and permit backtracking.
  5. Condition operations on top-k disagreement and entropy rather than one anchor, enabling branch and verify behavior.
  6. Evaluate hop support recall, bridge-entity accuracy, wrong→correct transitions, and path validity; rising answer margin alone is insufficient.

Research shift: preserve MERLIN's causal pattern of grounded feedback followed by conservative geometric update, but replace its oracle user with source-locatable, intervenable evidence read autonomously from memory. This moves from interactive embedding refinement to autonomous evidence-space navigation.

One-liner

MERLIN shows that external feedback can refine one target embedding; we still need to show that, without an oracle, real evidence drives transitions across changing targets rather than direction becoming a fixed step code.
