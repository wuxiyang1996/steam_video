World-Model-Guided Multi-Hop Reasoning over Grounded Video Memory

Predict which reasoning hop will change future belief, execute one real evidence read, correct, and replan.

Current problem formulation · 2026-07-30 · 中文 · Repository overview · includes SelectStream + OVO/StreamingBench notes

Core thesis

Reasoning must genuinely depend on the world model

Before every multi-hop reasoning step, an implicit world model (IWM) predicts how legal evidence-acquisition actions may change the future belief. A preference planner compares complete short trajectories, executes only the first hop of a preferred trajectory, observes real evidence, corrects the belief, and replans.

grounded L1/L1.5 evidence memory → bounded candidate reasoning hops → IWM imagined observation and belief transitions → ordinal trajectory preference → execute first hop → real evidence correction → replan

Paper-level contribution: action-conditioned prediction and model-predictive navigation of reasoning dynamics in belief space—not graph construction, generic retrieval, or numeric reward modeling.

1. Problem setting

Online stream, bounded memory. Video clips x_1,x_2,… arrive sequentially and cannot all be retained. The agent has a fixed-capacity memory buffer M_t (at most K entries), so before any question is known it must continually decide when to write and what to write. A write may create a grounded entry, update or merge an existing entry, preserve a salient event at finer temporal resolution, or evict/consolidate less useful evidence; skipping a redundant clip is also an explicit decision. These decisions must be question-independent and may use only the visible prefix x_{1:t}.

M_t = Write(M_{t-1}, x_t, w_t), |M_t| ≤ K w_t ∈ {skip, append, update/merge, consolidate/evict}

Question arrival and evidence routing. A question q may arrive at time t_q, after some relevant event has already passed, while the relevant event is visible in the current clip, or before the decisive event occurs. The agent must infer what evidence the question requires and choose among three temporally distinct sources: (1) query the bounded memory for past evidence, (2) inspect the current clip, or (3) defer the answer and wait for future clips. It may combine evidence from multiple sources and perform multi-hop queries over memory, but it may not inspect unseen future video or treat a prediction as observed evidence.

Evidence location at query timeRequired behaviorMain failure
Past: event occurred before t_qForm a question-conditioned memory query and navigate to retained evidenceThe needed event was never written, was over-compressed, or was evicted
Current: evidence is in x_{t_q}Inspect the live clip and combine it with relevant memory when necessaryHistorical retrieval distracts from direct current evidence
Future: decisive evidence occurs after t_qReturn WAIT/DEFER, monitor subsequent clips, and answer only when evidence is sufficientPremature guessing, indefinite waiting, or missing the trigger event

Thus the problem couples two policies: a pre-query memory policy that allocates scarce storage without seeing the future question, and a post-query reasoning policy that decides what and where to query, whether the evidence is sufficient, and when to answer. Performance is constrained jointly by memory capacity, evidence-read/context budget, and—when waiting is legal—response latency.

s_t = (q, M_t, x_t, E_{1:t}, missing_t, alternatives_t, contradictions_t, read_budget_t, wait_budget_t) a_t ∈ {QUERY_MEMORY(node/relation), INSPECT_CURRENT, WAIT_FOR_FUTURE, ANSWER, ABSTAIN} z_t = Enc(s_t) T_θ(z_t,a_t) → (ô_{t+1}, Δẑ_{t+1}) Pref_φ(τ_i,τ_j | z_t) ∈ {prefer_left,tie,prefer_right,incomparable}

z_t is a latent, multi-token belief state. It need not be an explicit graph posterior. For a legal evidence action, the IWM predicts an observation descriptor and belief change—not the next reasoning sentence and not evidence that may be used directly in the final answer. Only retrieved memory grounded in previously observed clips or a real current/future read can support the answer.

2. Evidence memory: keep L1/L1.5

The current memory graph remains the evidence substrate because it provides addressable, source-traceable video observations. It is built without the future question or answer.

LayerRoleResearch status
L1Grounded visual/text observations, timestamps, provenance, embeddingsInfrastructure
L1.5Question-independent soft node-to-node navigation correlations over L1 IDs; optional verified typed relations are stored separatelyNavigation topology/candidate generation
Latent beliefQuestion-conditioned competing interpretations, missing links, and answerabilityMain method state
L2Executed actions, real observations, realized deltas, and decision auditTrace, not a world model

Identity, state, and candidate-causal relations belong to an optional strict layer and remain candidates unless admitted by their required evidence gates. They are not the definition of the generic L1.5 correlation overlay and must not be treated as truth merely because they were proposed.

2.1 L1 storage contract

L1 is a question-independent Video_Skills-compatible ClueMemoryGraph. Each node stores one local, time-scoped observation rather than a reasoning conclusion.

Node/fieldStored content
Common fieldsStable node/video IDs, node type, grounded text descriptor, modality, time span, clip/local ID, evidence refs, source, producer, provenance, visibility, and optional embedding sidecar reference
clipAddressable video span, granularity, and segmentation policy
observation/eventDirectly visible/readable local description or atomic action, never an inferred motive
entity_mentionLocal mention ID, entity type, visible attributes, time, and evidence; no automatic cross-clip identity
stateSubject, attribute, value, polarity, temporal scope, and evidence
dialogue_span/OCRTime-aligned text with its true modality; subtitles do not claim direct audio observation

The main L1 navigation structure is a deterministic temporal_next/before/overlaps/during backbone over grounded semantic nodes. Composition links such as derived_from, entity_mention, state_of, and located_in remain provenance/audit structure. Native same_entity, state_change, and causal_hint labels belong to an optional strict-relation path and never become navigation facts without their specific verifier.

The current repair enriches persisted visual L1 nodes with question-independent, time-aligned subtitles when available. The bounded address key supports routing, while the complete descriptor remains a grounded value revealed by a real read. Future visual extraction also requests a concise grounded caption and evidence-indexed visible text. Any descriptor change invalidates the old embedding reference; Qwen/Qwen3-VL-Embedding-2B embeddings must then be regenerated before rebuilding L1.5.

2.2 L1.5 correlation overlay

L1.5 reuses the same L1 node IDs and adds question-independent soft nonlocal navigation correlations from Qwen/Qwen3-VL-Embedding-2B. Every non-temporal pair is scored; adjacent near-duplicate semantics are coalesced, remaining near-identical occurrences form a temporal recurrence chain rather than a clique, and class-level standardized sparsemax emits directional affinities without fixed Top-K. Similarity/affinity is not probability, confidence, identity, state transition, support, or causality. Independently verified categorical fact relations are stored separately.

2.3 Correlation is not action preference

L1.5 correlation: determine supported node-to-node navigable adjacency → legal-action compiler: expose executable cursor-incident hops → IWM: predict each hop's categorical observation and belief effect → planner: choose the next hop from those predictions

This boundary is mandatory. Correlation constructs question-independent graph topology; it does not choose a winner for a question. The IWM/planner may consume fixed correlation edges but may not invent, verify, or reclassify them during action selection. Measured embedding similarity, directional affinity, calibration, and provenance may be numeric graph features. The no-numeric-model-output rule applies to invented reward, utility, Q-value, probability, or confidence used for planning, not to measured graph-construction features. Edge affinity must never directly rank the winning action.

L1/L1.5 never stores the correct answer, hidden clue identity, question-conditioned belief, IWM imagination, predicted belief delta, planner trajectory, reward/utility/Q-value, GTSAM posterior, or final claim. These belong to hidden evaluation, latent belief, or the executed L2 trace.

2.4 SelectStream: budgeted online latent evidence

Core idea. SelectStream (arXiv:2606.16353v1) is not about “how to store more video.” Under a fixed memory and context budget, it decides online when to write, what to keep, what to read at query time, and how much historical evidence to expose to the VLM.

Prior methods usually sit at two extremes:

  • Recent-window: only the latest video — sharp current perception, but early critical events are easy to forget.
  • Large memory / replay: store and inject lots of history — longer coverage, but irrelevant past dilutes the current scene and raises compute.

SelectStream’s fix: the current frame always goes straight into the VLM; history is compressed into a fixed-capacity latent evidence graph; only a small, query-relevant slice of historical evidence is retrieved and injected as a few latent tokens.

Streaming video ↓ 1. SAW — Surprise-driven Adaptive Windowing (when to write?) ↓ 2. LVM — Latent Visual Memory Graph (what to write / keep under capacity N?) ↓ 3. GAR — Query-conditioned Graph Reasoning (which historical evidence? budget B) ↓ 4. Latent Evidence Injection (expose M calibrated tokens to frozen VLM) ↓ Answer Budgets (paper defaults): N=256 memory nodes · B=64 routed subgraph · M=8 evidence tokens

Modules

ModuleDecisionRole
SAWWhen to writeSurprise s_t = λ s_t^attn + (1−λ) s_t^feat closes variable-length segments (coarse on stable intervals, fine near changes)
LVM + mergeWhat to preserveGated write or new node; priority-aware consolidation keeps capacity at N (not FIFO / last-N only)
Route + GARWhat to retrieveTop seeds expand over temporal/semantic edges into B≤64, then graph attention — an evidence chain, not independent top-k clips
Calibrate / injectHow much to exposeX = [prompt; current; e₁…e_M]; history context does not grow with stream length T

What is stored is neither raw frames nor text summaries, but latent embeddings already passed through a frozen VLM visual encoder and multimodal projector. As of 2026-07-26, SelectStream.github.io returns 404 and no official code/weights were found—paper-level reimplementation only; published LR 2e-4 vs 2e-5 conflict.

One-liner: SelectStream uses surprise to set storage granularity, a fixed-capacity latent graph to merge/keep evidence, retrieves a small multi-hop evidence subgraph for the query, and compresses it into latent tokens injected into a frozen VLM.

Boundary vs. this IWM work: SelectStream navigates where evidence lives (addressable nodes + graph edges) and how much history a frozen decoder may see. This project keeps a grounded L1/L1.5 evidence substrate, then asks whether an IWM can predict how a legal hop changes future belief and whether a planner should execute that hop. Fixed-capacity surprise-written L1 is compatible infrastructure; latent-token injection into a frozen VLM is not our main claim. Historical “operation-conditioned soft read over continuous memory without nodes/edges” (dynamic-navigation text proxy) was a separate No-Go path—not the active CG-Bench IWM protocol.

3. Reasoning actions

An action is a reasoning/evidence query, not a physical action:

A = {start_at, temporal_before, temporal_after, follow_soft_correlation, backtrack, inspect_current, wait_for_future, stop, answer, abstain}

INSPECT_CURRENT is legal only when a live clip is available. WAIT_FOR_FUTURE is legal only in a future-evidence/proactive protocol, consumes latency or wait budget, advances the visible stream, and never reveals a future clip early. The active CG-Bench clue-navigation protocol uses the graph-navigation subset because it does not model free-running query arrival.

The main method has one active current-node cursor. Ordinary navigation actions use that cursor as their only source; acquired nodes remain in belief/frontier history and can be revisited through an explicit BACKTRACK/SHIFT_FOCUS operation. This avoids expanding all frontier sources against all graph targets.

A_t = outgoing_temporal(current) ∪ positive_direction_soft_correlation(current) ∪ backtrack(acquired frontier history) ∪ protocol_enabled{inspect_current, wait_for_future} ∪ {stop, answer, abstain}

A deterministic Graph Action Compiler enumerates actions from endpoint validity, streaming visibility, relation status, provenance, executor availability, and budget. It never filters by question relevance. A virtual query root exposes START_AT(node) for every retained node at the first step. Fixed-capacity L1 keeps this set bounded, so the Full-IWM arm uses no embedding Top-K; Top-K is an explicit retrieval baseline only.

4. Short-horizon model-predictive reasoning

  1. Compile every legal action from the single current-node cursor and fixed L1.5 graph.
  2. Imagine horizon-one or horizon-two categorical transitions for each action.
  3. Compare complete candidate trajectories pairwise.
  4. Execute only the first action of a uniquely preferred trajectory.
  5. Discard imagined observations, read real evidence, update belief, and replan.
τ* = PreferredTrajectory({Rollout_T(z_t,a)}_a) a_t* = First(τ*) o_{t+1} = Execute(M,a_t*) z_{t+1} = Update(z_t,a_t*,o_{t+1})

The world model is useful when a low-immediate-gain bridge hop unlocks a decisive second hop. This delayed effect is the principal distinction from reactive retrieval or immediate information-gain ranking.

The learned IWM predicts all legal first hops in one batched graph/tensor forward. Horizon two may remove only strictly dominated first hops before expanding every second hop from the remaining partial-order set; it does not use fixed-K beam pruning.

The current reasoning_v2 planner retains a forest of competing hypothesis-conditioned reasoning histories. A joint action tree must cover every surviving answer hypothesis under one shared physical first read. The planner schedules one real read, keeps unselected alternatives suspended rather than deleting them, applies the grounded correction separately to every path, and then replans from the corrected forest.

5. What may and may not choose the next hop

Allowed roleForbidden role in the main arm
Embedding similarity proposes candidatesHighest similarity automatically wins
Graph/factor constraints reject illegal or unsupported hopsFactor posterior or edge priority ranks the winner
Lexical/temporal rules define explicit baselinesHidden fallback decides ties in the IWM arm
IWM predicts categorical future belief effectsModel emits scalar reward, utility, Q-value, confidence, or probability

tie and incomparable must trigger further evidence, additional comparison, or abstention. Candidate order must be permutation invariant.

6. Keep the model input bounded

The IWM/planner does not receive the entire video, raw embedding matrix, hidden answers, or unconsolidated history. Because L1 memory has fixed capacity, it consumes the complete retained graph without Top-K truncation: question and belief tokens, the current cursor node's key and acquired value, every retained node key, all retained temporal/correlation edges, all legal cursor actions, recent history, and budget status.

surprise-written, fixed-capacity L1 nodes + complete retained temporal/correlation graph + one current-node cursor → all legal actions in one batched IWM forward → partial-order planner

Unread target nodes expose compact key/address representations; their full evidence values are revealed only after execution. Qwen/Qwen3-VL-Embedding-2B vectors remain in sidecars and serve as semantic action features—not a main-arm ranking gate, reward, or supervision.

7. Belief correction and the GTSAM backup

The main method uses a latent belief update after each real observation. GTSAM/factor graph is retained as an optional correction backend, baseline, diagnostic oracle, teacher, and visualization tool.

default: iwm_belief_only optional correction: iwm_with_gtsam_backup baseline/ablation: gtsam_always

Only executed, provenance-bearing, categorically verified observations may become factors. Imagined rollouts never enter persistent belief. Backup activation uses explicit categorical conditions such as identity ambiguity, contradiction, state-history conflict, or failed correction—not a hand-set posterior threshold.

GTSAM does not generate actions, traverse the graph, rank candidates, predict transitions, or ground the final answer. The main contribution must survive without it.

Supervision

8. Where the learning signal comes from

CG-Bench supplies human clue intervals and terminal answers. Executing a clue read yields categorical progress such as advances_required_clue_coverage, partial, or complete. Complete-clue versus leave-one-clue-out trajectories provide an ordinal preference.

  • Unmatched L1.5 candidates remain unlabeled; they are not fabricated semantic negatives.
  • Qwen-VL produces grounded observation descriptors, not GT relation labels.
  • GPT-5.6 visual review is optional diagnosis and does not overwrite CG-Bench ground truth.
  • Identity, state-transition, causal, and counterevidence relations need their own trusted labels.
  • Validation/test videos are never used for training.

Sibling branches executed from the same immutable checkpoint supervise action-conditioned observation and belief-delta prediction, and give pairwise trajectory comparisons without assigning absolute utility.

9. Post-training strategy

  1. SFT on reviewed categorical observation descriptors and realized belief deltas.
  2. Pairwise preference optimization on locked sibling trajectories.
  3. Only after label quality is established, optionally test group-relative ordinal optimization.

No LLM/VLM produces a numeric reward. A future GRPO-style optimizer may derive internal group-relative advantages from categorical ordering, but the data contract contains no weighted heuristic reward and no model-generated score. GPT-OSS-120B is currently an inference/data-gathering baseline; training has intentionally not started.

Decisive experiment

10. Prove causal dependence on the IWM

Hold question, evidence memory, candidate set, planner, and read budget fixed. Change only the world-model condition:

  1. full delayed-belief IWM;
  2. no world model;
  3. shuffled IWM predictions;
  4. frozen IWM;
  5. immediate-effect-only;
  6. oracle clue ceiling, reported only as a diagnostic upper bound.

Report answer accuracy, evidence completeness, read efficiency, action divergence, categorical transition accuracy, and delayed two-hop success separately. Do not collapse them into one lexicographic gate or scalar utility.

Go / No-Go

11. Evidence required for the claim

Go: the full IWM improves delayed multi-hop success under matched budgets; removing, freezing, or shuffling its predictions changes actions and hurts outcomes; prediction error correlates with navigation failure; and gains persist under candidate-order permutation.

No-Go: the same action sequence appears without the IWM, graph/embedding heuristics explain the gain, imagined evidence leaks into answers, candidate recall is too low to expose the required clue, or only immediate-gain cases improve.

13. What happens next

  1. Freeze a multi-video cohort whose exact complete-graph oracle paths fit the declared matched read budget; entry itself counts as one read.
  2. Independently calibrate executed observation transitions and hypothesis-conditioned belief effects, including surface-correlation hard negatives.
  3. Run matched IWM, no-WM, shuffled-IWM, immediate-only, and oracle arms over that fixed cohort.
  4. Report answer accuracy, read efficiency, action divergence, strict interval localization, abstention, delayed success, and latency as separate metric families.
  5. Train or distill a 9B IWM only after intact predictions outperform no-WM and shuffled-IWM on delayed, budget-feasible cases.

The code and repaired evidence substrate now work end to end. Training remains blocked because transition calibration and a fixed multi-video, budget-feasible matched experiment are still missing, and the current correct learned-entry answer is also obtained by the immediate-only arm.
