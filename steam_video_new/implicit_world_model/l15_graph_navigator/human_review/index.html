标注任务与判断标准

你的任务不是给 planner 打分或提供 reward，而是判断执行这一步 reasoning action 后，真实证据是否支持它声称的 observation、relation 和 belief change。

Ground truth 在这里如何使用

已有的 terminal QA ground truth

当前 9 个视频共有 58 条 Video-Holmes QA GT，包含 Question、Options、Answer 和 Explanation。它可用于判断完整 trajectory 最终是否答对，并产生非数字的 pairwise preference。

缺少的 transition ground truth

QA GT 没有当前 node pair 的 identity、同属性 before/after state、action execution 或 belief delta 标签，因此不能自动填写本页五个字段。

本次人工审核建立什么

你的 blind video judgment 将建立独立的 transition-level GT；审核锁定后，才会与 terminal QA GT 联合分析。

防止 label leakage： 审核期间不展示正确答案、GT explanation、stored verifier outcome 或 hidden target。最终答案正确也不能证明中间 relation 正确，因为模型可能猜对或使用 shortcut。

推荐判断顺序

  1. 视频是否展示描述内容？→ Observation validity
  2. 系统是否正确完成搜索或验证？→ Action execution validity
  3. 证据支持、反驳还是无法决定关系？→ Relation outcome
  4. 证据是否足以改变当前 belief？→ Belief delta validity
  5. 整条记录是否适合作为训练数据？→ Record admissibility

五个分类字段

Record admissibility
Accept 表示整条记录证据充分且可用于训练；存在错误或关键证据不足时选 Reject。
Observation validity
判断画面是否真的展示声称的人物、动作、物体或状态。
Action execution validity
判断 reasoning operation 是否被正确执行；没有找到反证仍可能是一次有效搜索。
Belief delta validity
判断证据是否足以补全、推翻、解决矛盾或合理地保持不确定。
Relation outcome
Supports=明确支持；Rejects=明确反驳；Inconclusive=证据不足；Not applicable=没有具体待验证关系。

严格关系规则

Identity / same_entity

只有外貌、服装、时空连续或同镜头跟踪等身份连续性证据才能选 Supports；仅仅都是“man/woman”不够。

State transition

必须是同一实体、同一属性、明确 before/after value、顺序明确且确实发生变化。

Counterevidence

只有直接反驳 hypothesis 才选 Rejects；相关内容或空搜索通常是 Inconclusive，不能自动算 Supports。

重要： Relation outcome=Rejects 不等于拒绝记录。若系统正确找到了反证，整条记录仍可 Accept。证据不足时请选择 Inconclusive，不要猜测。

完成后统计什么

我们会分别报告 observation/action/belief validity、relation confusion matrix、record acceptance rate、隐藏重复条目一致性，以及 identity/state strict precision；不会把它们压成单一数字 reward。

  • Validity distribution：分别统计 Valid / Invalid / Inconclusive 的数量与比例，用于定位 evidence、executor 或 belief target 的问题。
  • Relation confusion matrix：人工结论为行、现有 verifier 结论为列，观察 Supports / Rejects / Inconclusive 的具体混淆。
  • Record acceptance rate = Accept 条目数 / 53；表示可进入后续训练集的比例。
  • Duplicate consistency：隐藏重复条目的五个分类判断是否完全一致，用于检查 reviewer 稳定性。
  • Identity/state strict precision = 系统 admitted 且人工确认 Supports 的关系数 / 系统 admitted 的关系数；identity 与 state 分开计算。

用简单语言理解这一条

SOURCE：推理从哪里开始

TARGET：action 想检查什么
OBSERVATION：执行后实际返回什么

同一个节点可以同时是 TARGET 和 OBSERVATION：这表示系统请求检查它，并且执行后确实返回了它。
