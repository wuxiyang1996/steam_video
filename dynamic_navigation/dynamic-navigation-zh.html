语义空间中的动态导航

Dynamic Navigation in Semantic Space over Fixed Latent Memory

Discussion notes · 2026-07-14 · English · 对齐 steam_video_new

窄定义

不是 embedding 检索，而是 previous-step-conditioned semantic read actions

可以做，但定义必须非常窄：不是在 embedding space 里“检索最近邻”，也不是构建隐式 graph，而是让 query state 在固定 latent memory tokens 上执行一串依赖上一步的 semantic read actions（test-time latent reasoning）。

previous-step-conditioned action policy + action-specific read over fixed semantic memory + support-progress reward

动态发生在 query state 与 action / reader control 上，不发生在 memory structure 上：M_t 不变，没有 node、edge、timestamp、Top-K evidence item。

SelectStream · Key Idea

0. SelectStream 核心想法

EN — Core idea. SelectStream is not about “how to store more video.” Under a fixed memory and context budget, it decides online when to write, what to keep, what to read at query time, and how much historical evidence to expose to the VLM.

ZH — 核心想法。 SelectStream 的核心不是“如何保存更多视频”，而是：在固定的 memory 和 context budget 下，在线决定何时写入、保留什么、查询时读取什么，以及最终向 VLM 暴露多少历史证据。

传统方法通常走两个极端：

  • Recent-window：只看最近的视频，当前感知清晰，但容易忘掉早期关键事件。
  • Large memory / replay：保存并注入大量历史，虽然覆盖更长，但无关历史会稀释当前场景，并增加计算量。

SelectStream 的解决方案是：当前画面始终直接输入 VLM，历史信息则被压缩为固定容量的 latent evidence graph；只有与当前问题相关的一小部分历史证据才会被取出。

current frame → VLM (full perception, always) history → fixed-capacity latent evidence graph → query-conditioned retrieve small evidence → inject few latent tokens into frozen VLM
SelectStream · Method

0b. SelectStream 整体方法

Streaming video ↓ 1. Surprise-driven Adaptive Windowing — When to write? ↓ 2. Latent Visual Memory Graph — What to write / keep under capacity? ↓ 3. Query-conditioned Graph Reasoning — Which historical evidence for this query? ↓ 4. Latent Evidence Injection — Compress & inject into frozen VLM ↓ Answer

系统维护一个动态 memory graph G_t = (M_t, E_t)：

  • M_t：固定容量的 memory nodes；
  • E_t：节点之间的时间和语义关系；
  • 每个 node 保存一段视频对应的 projected visual embeddings、时间范围、surprise 等 metadata。

它保存的不是原始帧，也不是文本摘要，而是已经经过冻结 VLM visual encoder 和 multimodal projector 的 latent embeddings，因此可以直接进入语言模型的 embedding space。

1. Surprise-driven Adaptive Windowing：什么时候写入

连续视频并不是每个时刻都同等重要：静态场景持续十秒，没有必要写十条 memory；人物突然进入、物体状态改变或场景切换，则应该更细粒度保存。因此计算每个时刻的 surprise：

s_t = λ s_t^attn + (1−λ) s_t^feat s_t^attn = JS(A_t ∥ A_{t−1}) # attention shift s_t^feat = 1 − cos(g_t, g_{t−1}) # feature change

surprise 低 → 较长窗口，稳定内容合成一个 memory entry；surprise 高 → 窗口提前关闭，在变化附近生成更细的 memory node。实现的是稳定片段粗粒度、关键转折细粒度——不是简单选 surprise 最高的若干帧，而是用 surprise 动态决定 temporal segmentation 与 memory resolution。

2. Latent Visual Memory：容量满了保留什么

每个 adaptive window 结束后，视觉 token 聚合并写入 memory graph。节点可表示稳定区间、重要状态变化、或短暂高-surprise 事件。容量 N 固定，因此做 priority-aware consolidation：保留 / 合并 / 淘汰。

优先级综合：surprise、novelty、temporal relevance / recency、冗余程度、是否已承载重要关系。低优先级且相似的节点更易合并；高-surprise、独特或有重要连接的节点受更强保护。不是 FIFO，也不是纯最近 N 段：

new evidence ↓ compare with existing nodes ↓ preserve important nodes merge redundant nodes remove low-value evidence

最终长期视频被压缩成非均匀分辨率的 latent evidence graph：重要事件密集、稳定背景稀疏。

3. Graph Attention Reasoning：问题来了之后读取什么

不会把整个 memory graph 输入 VLM。先把问题编码为 query，对 memory nodes 做 query-conditioned scoring，找到 seed nodes，再沿图关系扩展成小型 evidence subgraph（budget B）。

例：“这个人此前在哪里放下了杯子？”可能先检索“杯子再次出现”，再扩展到更早杯子出现、拿杯子、放下杯子的节点。关系包括 temporal adjacency / overlap、semantic similarity、event or state continuity。

核心区别：Top-k retrieval 找若干独立相似片段；GAR 找彼此相关、能组成证据链的一组节点——对 multi-hop / temporal reasoning 更关键。

4. Latent Evidence Injection：如何让冻结 VLM 使用历史

对检索节点做 graph-aware aggregation，压缩为固定数量 M 的 evidence tokens，按 query 与 evidence confidence calibration 后注入 frozen VLM 的输入 embedding sequence：

[query tokens] [current visual tokens] [small set of retrieved historical latent tokens] # NOT: [query] + [all previous frames] + [current frames]

关键设计：当前画面直接可见，不被 memory compression 替代；历史画面选择性可见，只通过少量 query-conditioned latent tokens 提供——减少历史噪声干扰当前场景。

最本质的三个决策

真正贡献不只是“graph memory”，而是把 streaming memory 统一成一个 budgeted online evidence allocation problem，在预算 N（memory）、B（subgraph）、M（injected tokens）下协调。

One-liner / 一句话： SelectStream uses surprise to set storage granularity, a fixed-capacity latent graph to merge/keep evidence, retrieves a small multi-hop evidence subgraph for the query, and compresses it into latent tokens injected into a frozen VLM. SelectStream 用 surprise 决定视频历史的存储粒度，用固定容量 latent graph 动态合并和保留证据， 再根据问题检索一个小型多跳证据子图，并将其压缩成 latent tokens 注入冻结 VLM。

与本文 dynamic navigation 的边界：SelectStream 导航“证据存在哪里”（addressable nodes + graph edges）；本文导航“对固定连续语义状态执行什么变换”（no nodes/edges；operation-conditioned soft read）。

1. 最稳实现路径

context / stream → fixed memory M ∈ R^{N×d} u_0 = E_Q(q) r_0 = ∅; a_0 = START for k = 1..K: # test-time unrolling choose action a_k | (u_{k-1}, r_{k-1}, a_{k-1}, q) action-specific read of fixed M → r_k update query state → u_k optional: if a_k = STOP: break answer from u_K

每一步变的是：

  • u_{k-1}：当前问题状态
  • a_k：依赖上一步的 semantic read action
  • reader：action-specific CrossAttn / FiLM / LoRA
  • u_k：读完以后更新的问题状态
Encoder

1b. Text embeddings：frozen Qwen3-Embedding-2B

Multi-hop Text QA proxy 统一用 frozen Qwen3-Embedding-2B（HF：Qwen/Qwen3-VL-Embedding-2B，text 模式；embedding dim = 2048）生成 context / question embeddings。Encoder 是 implementation choice，不是 contribution；trainable 的是 resampler / navigator / answer head。

E = Qwen3-Embedding-2B # frozen # paragraph- or sentence-level tokens → fixed memory Z = E(context paragraphs) M = Resampler(Z) ∈ R^{N×2048} # N fixed, e.g. 16/32/64 u_0 = Proj(E(q)) # same frozen encoder a_emb = E(answer candidates) # for m_k scoring
  • Week 0.5：encoder 全程冻结；先确认 EM/F1、m_k、hop/type breakdown 可算。
  • 不做 mean-pool 成单向量当唯一 memory；保留 N 个 latent tokens。
  • 不做 Top-K passage retrieval；整段 distractor context 压进固定 M。
  • 后续 video 路径可复用同一 Qwen embedding family，保证 text proxy → multimodal 连续。

Action policy backbone（与 frozen encoder 分开）：

  • MLP（默认 / Week 0.5）：π(a|u,r) 小头，最快跑通。
  • BERT：可用；适合离散 action 主方法，轻量、好训。
  • Qwen3.5-2B：可用作更强 policy，但通常过重；state 已是 continuous embedding 时优先 BERT/MLP，Qwen3.5-2B 作可选对照。

2. 两阶段方法：Week 0.5 soft mixture → 主方法 action policy

Week 0.5（先跑通 metric）— soft action mixture

先用可微 soft mixture 确认数据管线、EM/F1、m_k、hop/type breakdown 都能算。此时不做硬离散决策。

u_0 = E_Q(q) π_k = softmax(g(u_{k-1}, r_{k-1}, q)) e_k = Σ_a π_{k,a} e_a α_k = softmax(Q(u_{k-1}+e_k) K(M)^T / √d) r_k = α_k V(M) u_k = GRU(u_{k-1}, r_k, e_k)

主方法（论文主 claim）— action policy + action-specific read + progress reward

metric 通了之后，升级为 previous-step-conditioned discrete read actions（可含 STOP）。这是 test-time latent reasoning，不是 text CoT，也不是 retrieval agent。

A = {GROUND_ENTITY, RESOLVE_EVENT, TRACE_STATE, LINK_TEMPORAL, CHECK_CONFLICT, COMPOSE, STOP} state_k = [u_{k-1}; r_{k-1}; a_{k-1}; E(q)] π_k = softmax(W state_k) a_k ~ π_k # train: soft / ST-Gumbel; test: argmax or sample K_k, V_k = FiLM_{a_k}(K(M), V(M)) # or LoRA_{a_k} r_k = CrossAttn(Q(u_{k-1}), K_k, V_k) u_k = GRU(u_{k-1}, r_k, e_{a_k}) # if a_k = STOP: break

Action 只决定 怎么读固定 M，不决定检索哪个 passage，不调用外部工具。

3. 训练信号：progress reward 驱动换 action

不能只说“多步 attention”。每一步必须让答案更可判别；这也是 action 切换的主信号。

m_k = s(a⁺ | u_k) − max s(a⁻ | u_k) L_progress = Σ_k max(0, m_{k-1} + δ − m_k) # progress reward / hinge L = L_QA + λ_p L_progress + λ_a L_action + λ_c L_comp
  1. L_action：question type / teacher sketch 弱模仿（bridge: GROUND→TRACE→COMPOSE；comparison: GROUND→CHECK→COMPOSE）。可打乱作负例。
  2. L_progress：逼 m_k 逐步上升；鼓励“读到新语义后再换 action”。
  3. L_comp：防止每步重复同一 action / 同一 latent direction。

关键干预：shuffle actions、force 同一 action、remove action-specific FiLM/LoRA。若不掉点，action claim 失败。

4. 我们 setting 里的正确说法

dynamic navigation = previous-step-conditioned semantic read actions over fixed latent history，不是 embedding 搜路，也不是 text CoT。

  • 固定的 history semantic state 不动；
  • action policy 条件于 (u_{k-1}, r_{k-1}, a_{k-1}, q)；
  • action-specific reader 对同一 M 做不同读法；
  • progress reward 驱动每一步提高 answer support。
M = fixed semantic memory tokens u_0 = question embedding a_1=GROUND, u_1 = read(M, u_0, a_1) a_2=TRACE, u_2 = read(M, u_1, a_2) # conditioned on step 1 a_3=LINK, u_3 = read(M, u_2, a_3) a_4=COMPOSE, u_4 = read(M, u_3, a_4)

推荐 formulation：

Support-progressive semantic navigation via previous-step-conditioned read actions over fixed latent history

5. 视频场景示例

Question：谁最后拿走了一开始在桌上的红色包？

  1. GROUND_ENTITY：找到“红色包”这个 latent entity。
  2. RESOLVE_EVENT：读出它最早在桌上，后面被移动。
  3. TRACE_STATE：追踪 possession / location 的变化。
  4. LINK_TEMPORAL：锁定最后一次 handoff / pickup。
  5. COMPOSE：把人物、物体、时间顺序组合成答案。

不是检索“红色包 frame”，而是在 M_t 里逐步恢复：entity identity → event transition → state continuity → temporal ordering → answer relation。

The navigator progressively transforms the query state to extract complementary answer-supporting semantics from a fixed latent history state.

不要说： The navigator retrieves evidence chains.
返回的是 answer-supporting latent semantics，不是 source-traceable evidence。

6. Multi-hop QA plan（HF benchmark + Qwen3-Embedding-2B）

先不要上真实 Video QA。主数据直接用 Hugging Face multi-hop QA；text embeddings 一律由 frozen Qwen3-Embedding-2B 生成。

Stage 1：HF Multi-hop Text QA

数据：优先 hotpotqa/hotpot_qa（distractor）；再加 2WikiMultihopQA；MuSiQue 作 hard set。

context paragraphs --[frozen Qwen3-Embedding-2B]→ Z → Resampler → M question --[frozen Qwen3-Embedding-2B]→ u_0 candidates --[frozen Qwen3-Embedding-2B]→ {a⁺, a⁻} Week 0.5: soft action mixture → score(a | u_K) Main: action policy + action-specific read → score(a | u_K)

对照（同 N、同 FLOPs）：one-shot / deeper one-shot / plain recurrent / soft mixture / full action policy / shuffle actions。

指标：EM/F1、m_k 曲线、hop/type breakdown。最重要的是 m_0 < m_1 < … < m_K，不是只看 overall accuracy。

Stage 2：Action intervention

在同一 Hotpot/2Wiki 设置上做：shuffle actions、replace TRACE_STATE、remove action-specific FiLM/LoRA、force same action every step。若干预不掉点，action claim 失败。

Stage 3：Image QA Proxy → Video

过 Go 门槛后再上：caption-memory Image QA → image embedding QA → streaming video QA。尽量保持同一 Qwen embedding family，避免 encoder 换代混淆 navigation 收益。

HF multi-hop Text QA (Qwen3-Embedding-2B) → caption-based image QA → real image embedding QA → streaming video QA

风险与门槛

8. 三个真正风险 + Go / No-Go

  1. 若 operation 打乱后性能不掉，operation 只是装饰。
  2. 若 one-shot deeper reader 表现一样好，navigation 没有必要性。
  3. 若 fixed M_t 已丢失 temporal handoff / object continuity，navigator 再聪明也恢复不了。

Go：full navigator > plain recurrent > one-shot；shuffle ops 掉点；progress margin 逐步上升；收益集中在 multi-hop / temporal / distractor。

No-Go：deeper one-shot 追平 full navigator；operation shuffle 不掉点；progress loss 无额外信号；只在 synthetic text 上工作、image proxy 完全失败。

实验门槛必须硬：同 FLOPs 下 full navigator 必须赢 deeper one-shot、plain recurrent attention、latent deliberation；并且 m_0…m_K 要显示 step-wise support margin 上升。否则 idea 退化成“Qwen embedding + recurrent attention”，novelty 不够硬。

Causal Navigation

9. Counterfactual causal navigation（V3 已实现）

为避免 paragraph pooling 的信息瓶颈，V3 保留 frozen encoder 的 token hidden states，并用 masked Perceiver 写入 32 个固定 latent slots。离散 action 被替换为 answer-contrast-conditioned 连续方向；reader 使用低温 cosine routing，使方向成为唯一寻址信号。每一步根据上一轮状态、上一轮 read、当前 top-2 答案差异和上一轮 causal gain 生成导航方向：

d_k = E(a_k^1) − E(a_k^2) z_k = Policy(u_{k-1}, r_{k-1}, d_k, C_{k-1}) r_k = softmax(cos(z_k, K(M))/τ)V(M)

对本步执行 do-removal，保持状态和方向不变，只令 do(r_k=0)：

C_k = margin(factual r_k) − margin(do(r_k=0)) g_k = sigmoid(τ C_k) u_k = g_k·u_k^factual + (1−g_k)·u_{k-1}

训练额外加入 learned direction 必须优于同状态 random direction 的对比干预损失。测试使用 zero-read、Gaussian random direction、batch-shuffled learned direction、reject-all 和 accept-all。

最终 Hotpot 8-candidate（4096 train / 512 val）结果：causal navigator 65.04%，token one-shot 63.09%，高 1.95 点；四步 margin 从 1.951 升至 2.089。do(r=0) 后仅 0.39%，说明 read 对当前决策机制确实必要。但 batch-shuffled direction 仍有 64.45%，只降 0.59 点，未达到预设 2 点门槛。

MuSiQue 3–4 hop 迁移结果：causal navigator 61.13%，低于 token one-shot 的 63.28%；random direction 为 62.30%，shuffled direction 为 61.72%。四步 margin 从 1.425 大幅升至 3.363，但准确率没有同步改善，说明它主要是 recurrent confidence amplification，而不是正确的 semantic navigation。两个 benchmark 均未通过方向因果门槛，最终结论仍是 No-Go for causal navigation。

Prior Work

10. MERLIN：从交互式 embedding refinement 到自主 evidence-space navigation

MERLIN（Han et al., EMNLP Industry 2024）是与本方向最接近的前置工作之一。它面向 text-video retrieval：用当前 top-1 anchor video 的 metadata 让 LLM 生成澄清问题，再由能观察用户“video in mind”的 human-simulating agent 回答；回答 embedding 与上一轮 query embedding 通过 SLERP 聚合：

e_answer^r = Enc(answer_r) θ = arccos(e_answer^r · e^{r-1}) e^r = sin((1−α)θ)/sinθ · e_answer^r + sin(αθ)/sinθ · e^{r-1}, α = 0.8

较大的 α 保留较多旧 query，以减轻 query drift。该方法是 training-free、固定轮数，没有 learned transition、reward、stop、branch/backtrack 或跨步 credit assignment。论文报告五轮后 R@1：MSR-VTT 44.40→78.00、MSVD 52.39→77.61、ActivityNet 56.58→68.44；但候选集合仅为 500 / 670 / 919 个视频，且每轮从可观察 ground-truth target video 的 oracle-like agent 获得新增信息。因此它证明的是有外部目标反馈时，连续 embedding 聚合可有效改善单目标 reranking，不能证明 agent 在无 oracle 情况下会自主发现证据链，也没有隔离 SLERP、多轮问答和问题选择各自的贡献。

与我们的实质区别

  • MERLIN：固定隐藏目标视频；每轮补全同一目标的描述；外部用户注入新信息；目标是最终单点 retrieval。
  • Multi-hop QA：目标证据随 hop 改变；系统必须从已读证据产生下一子目标；没有 oracle user；目标是有效的 evidence transition 与最终 composition。
  • 我们的 novelty 边界：“多轮移动 embedding”已被 MERLIN 覆盖。可成立的 claim 必须是 learned autonomous transition across multiple evidence targets，并通过 direction / path intervention 验证，而不是 generic iterative refinement。

对当前失败实验的直接启示

MERLIN 每次移动都有一个语义落地的外部回答 e_answer^r；当前 V3 的方向主要由自身 state 和候选 contrast 生成，没有 hop-specific grounded feedback，因此很容易退化成跨样本共享的 step code。这解释了为什么 Gaussian random direction 会降低 margin，而 batch-shuffled valid direction 几乎不影响 accuracy。

# MERLIN-inspired but autonomous r_k = Read(M, z_k) # 从固定 memory 得到本步证据 f_k = EncodeEvidence(r_k / bridge entity) # 语义落地的 feedback η_k = Trust(state, entropy, consistency) # 动态吸收强度 z_{k+1} = GeoUpdate(z_k, f_k; η_k) # SLERP 或 anchored residual operation_k ∈ {REFINE, TRANSITION, BRANCH, BACKTRACK, VERIFY, STOP}
  1. 先加入强 baseline：原问题 one-shot、passage 拼接重编码、query rewriting、固定线性插值、MERLIN-style SLERP、learned transition；所有方法必须使用完全相同的 feedback。
  2. 让 direction 只负责寻址：不要把 direction 直接送入 answer GRU；状态只能通过实际 read evidence 改变，堵住“方向作为 step embedding”的旁路。
  3. 用分布内错误反馈训练：负例应是其他样本同 hop 的 valid direction、错误 supporting paragraph 或错误 bridge entity，而不是只用 Gaussian noise。
  4. 显式控制 drift：学习 η_k，同时约束与原问题的一致性；允许低置信 read 时少更新、矛盾时 backtrack。
  5. 从 retrieval landscape 决策：不要只看 top-1；利用 top-k disagreement / entropy 决定 REFINE、BRANCH 或 VERIFY，避免围绕错误 anchor 持续 exploitation。
  6. 评价 evidence transition：报告每 hop supporting-paragraph recall、bridge-entity accuracy、wrong→correct transition、path validity；只有 answer margin 上升不够。

最关键的研究转向：MERLIN 的成功来自“grounded feedback → conservative geometric update”。我们应保留这个因果结构，但把 oracle user 替换为系统自己读到、可定位且可干预的证据；从 interactive embedding refinement 推进到 autonomous evidence-space navigation。

一句话

MERLIN 已证明外部反馈可以持续 refine 单一目标 embedding；我们尚需证明 agent 能在没有 oracle 的情况下，用每一步真实证据驱动跨目标 transition，而不是把 direction 学成固定 step code。
