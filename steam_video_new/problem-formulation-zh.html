面向真实视频推理的多步 Evidence World Model

预测不同多 clue 获取轨迹的非加性后果，再依据真实读取执行推理与作答。

当前问题定义 · 2026-08-05 · English · 上一版问题定义（c1829a0） · Baseline results · 仓库总览

核心挑战

长时程流式视频、有限记忆与有限推理预算

  1. 有限记忆不完整。Evidence 分散在长时程 stream 中，较早 clues 可能被压缩、合并、淘汰，或从未被保留。
  2. 证据时序与 answerability 不确定。决定性 evidence 可能位于过去、当前片段或尚未出现的未来，因此系统必须在立即回答、继续检索、等待更多证据和 abstain 之间选择。
  3. 有限预算下的 multi-clue acquisition。系统必须在有限 response time、memory/context capacity、真实 read budget 和大模型 Reasoner calls 下检索并组合多个 clues。
  4. 多条竞争 reasoning trajectories。系统需要判断哪条多步 evidence path 值得真实执行，不能穷举读取所有 candidates 或运行所有 branches，也不能把 predicted consequence 当作已观察 evidence。
TL;DR

问题：长时程 streaming QA 必须从有限、可能被压缩或缺失的 memory 中恢复多个 clues，有时还要等待 future evidence，并在严格 time 与 reasoning budgets 下判断 answerability。

现有缺口：Single-step RAG 与 greedy reasoning 容易漏掉 conditional 或 delayed clue combinations；SelectStream 改善了 online evidence allocation，但 heuristic graph construction 成本高、灵活性不足，并严重依赖 graph quality。

我们的方向：用 graph-free、question-conditioned Q-Former 表示 candidate nodes，再用轻量 IWM 预演多条 multi-clue、multi-hop trajectories 的联合 outcomes，而不必真实执行所有昂贵 reasoning branches。

Grounding rule：Answerability-aware Reasoner 使用这些 rollout priors 执行真实 reads、replan、answer、wait 或 abstain；最终答案只能由真正观察到的 evidence 支持。

核心命题

推理必须真正依赖 world model

每一步多跳推理之前，implicit world model（IWM）预测各个合法证据获取 action 将怎样改变未来 belief。Preference planner 比较完整的短轨迹，只执行获偏好轨迹的第一跳；获得真实证据后修正 belief，再重新规划。

问题无关的 L1/L1.5 evidence memory → 有界候选 reasoning hops → IWM 想象 observation 与 belief transition → 序数 trajectory preference → 只执行第一跳 → 真实 evidence correction → 重新规划

论文级贡献：在 belief space 中预测 action-conditioned reasoning dynamics，并用 model-predictive planning 导航下一跳；不是 graph construction、普通 retrieval 或数字 reward modeling。

为什么常见 baseline 不够

Baseline在长时程 multi-clue reasoning 中的失败IWM 必须提供的能力
Single-step RAG / fixed Top-K retrieval只按当前相关性选择 evidence，容易漏掉暂时较弱的早期 clue、分散的互补 clues，或取回多个重复 nodes，却丢失真正使问题变得可回答的 clue combination。分析每次 evidence acquisition 可能产生的 reasoning outcome，而不只计算当前 similarity。
Greedy iterative reasoning每轮读取一个 candidate、更新一次，并立即提交到局部最优 continuation。早期错误会丢失仍有价值的 evidence needs 或竞争 paths；恢复时还需要额外的真实 reads 和昂贵 Reasoner calls。在提交真实 action 前保留多条 plausible reasoning paths，并比较其 predicted downstream consequences。
Independent / additive node scoring把每个 clue 的价值视为相互独立，无法表达 synergy、redundancy、contradiction、conditional relevance 或顺序敏感的 clue combinations。在同一次 planning iteration 中整合多个 clues，并预测它们联合、非加性的 consequence。
大 Reasoner 穷举 branch search理论上可以测试多条 chain，但对每个 branch 反复执行真实 evidence read 和大模型推理，在 streaming 场景下过慢且成本过高。使用轻量、快速的 world model 预演 multi-hop reasoning-chain outcomes，并在 grounded execution 前跟踪多条 reasoning trajectories。
当前架构映射：这里保留的是“推理必须因果依赖 world model”的核心命题。在新版实现中，“L1/L1.5”表示 grounded L1 加确定性执行约束，而不是 semantic navigation graph；Q-Former 准备有界的 node-aligned proposals，multi-step IWM 预测组合后果，Reasoner 负责 trajectory choice 与 grounded execution。

1. 问题设定

在线流与有限记忆。视频片段 x_1,x_2,… 按时间顺序到达，系统无法保留全部历史。Agent 只有固定容量的 memory buffer M_t（最多 K 个条目），因此在尚不知道问题时，就必须持续决定何时写入和写入什么。一次写入可以新建 grounded entry，更新或合并已有 entry，以更细时间粒度保留显著事件，或淘汰/压缩较低价值的旧证据；跳过重复片段也是一种显式决策。所有这些决策必须 question-independent，并且只能使用当时已经可见的视频前缀 x_{1:t}。

M_t = Write(M_{t-1}, x_t, w_t), |M_t| ≤ K w_t ∈ {skip, append, update/merge, consolidate/evict}

问题到达与证据路由。问题 q 可能在时刻 t_q 到达，而相关事件可能已经发生在过去、正出现在当前片段，或尚未在未来出现。Agent 必须先判断问题需要什么证据，再在三个时间位置不同的来源之间选择：（1）查询有限 memory 中的过去证据；（2）检查当前视频片段；（3）暂缓作答并等待未来片段。它可以组合多个来源，并在 memory 上执行 multi-hop query；但不能偷看尚未到达的视频，也不能把预测结果当成已观察证据。

问题到达时证据所在位置Agent 应执行的行为主要失败模式
过去：事件早于 t_q根据问题构造 memory query，导航到已保留的证据关键事件从未写入、被过度压缩或已被淘汰
当前：证据位于 x_{t_q}检查 live clip，必要时与相关历史记忆结合无关历史检索干扰直接可见的当前证据
未来：决定性证据晚于 t_q输出 WAIT/DEFER，继续监测后续片段，证据充分后再回答过早猜测、无限等待或漏掉触发事件

因此，该任务联合了两个 policy：问题到达前的 memory policy 在看不到未来问题的情况下分配稀缺存储；问题到达后的 reasoning policy 决定查询什么、去哪里查询、证据是否充分以及何时回答。系统同时受 memory capacity、evidence-read/context budget 约束；允许等待时，还受 response latency / wait budget 约束。

s_t = (q, M_t, x_t, E_{1:t}, missing_t, alternatives_t, contradictions_t, read_budget_t, wait_budget_t) a_t ∈ {QUERY_MEMORY(node/relation), INSPECT_CURRENT, WAIT_FOR_FUTURE, ANSWER, ABSTAIN} z_t = Enc(s_t) T_θ(z_t,a_t) → (ô_{t+1}, Δẑ_{t+1}) Pref_φ(τ_i,τ_j | z_t) ∈ {prefer_left,tie,prefer_right,incomparable}

z_t 是 multi-token latent belief state，不必等同于显式 graph posterior。对于合法 evidence action，IWM 预测 observation descriptor 和 belief change，不预测下一句 reasoning text，也不能生成直接进入最终答案的想象证据。只有来自已观察历史片段的 grounded memory，或对当前/未来片段的真实读取，才能作为答案依据。

新版职责映射：这里的 state/action formulation 保持不变。新版 IWM 从 Q-Former proposals 预演 multi-step clue-combination consequences，而 grounded Reasoner 承担上述 Pref_φ 与真实 action loop 所表达的 planner/executor 职责。
目标场景

1.1 IWM 必须建模的 multi-clue consequences

Relevance model 为单个 candidate node 分配当前上下文下的分数 r(i|q,z_t)。它可以估计 node i 现在看起来是否有用，却不能说明读取一组或一串 clues 后，reasoning state 会变成什么。IWM 要预测的是 functional post-acquisition state：

r(i | q,z_t)：当前 single-node relevance C(S_1,…,S_H | q,z_t)：multi-step acquisition trajectory 的 consequence Δ(i | S) = C(S ∪ {i}) − C(S)：依赖 prefix 的 marginal consequence

Marginal consequence Δ(i|S) 会随着已经取得的 prefix S 改变。因此，全局排序的 node list 或独立 node value 的加和无法表达下面所有情况。

情况详细的 multi-clue 行为IWM 的预测目标
SynergyClue A 识别 entity，clue B 揭示其后续状态；二者单独都无法确定答案。即使 A、B 各自 relevance 只属中等，组合后也可能是决定性的。预测 A+B 会跨过 answerability threshold，并补全缺失的 evidence role。
Conditional relevanceA 识别人、物体或事件后，B 才变得可解释或可检索；在 A 之前，B 含义模糊，甚至看似无关。预测 prefix A 之后 next evidence need 与 candidate distribution 如何变化。
RedundancyA、B 都高度相关，但重复同一个 observation、paraphrase 或 visual state。两者都读会浪费预算，却不增加 evidence coverage。预测在已经读取 A 后，B 的 marginal state change 很小，把预算留给互补 clue。
ContradictionA 支持当前 hypothesis，而稍后的 B 提供 grounded counterevidence，或推翻假设的 temporal order。预测 hypothesis reversal、alternatives 重新打开、contradiction status 与 replanning need。
Delayed valueA 不会立即提高 answerability，但它引入理解数步之后 clue C 所需的 entity、location 或 event boundary。即使 immediate answerability delta 接近零，也预测其具有正的 long-horizon value。
Order sensitivity先读 A 再读 B 可以建立有效 dependency；先读 B 则 observation 含义模糊，或在尚不知道其角色时提前消耗预算。当 sequence 不可交换时，区分 C(A→B) 与 C(B→A)。
Insufficiency当前可见的所有 clues 仍无法补全必要 role，或者决定性 clue 位于 future clip。预测 continue、wait 或 abstain，而不是制造 answer confidence。

长视频中的示例 trajectory

假设问题询问“什么物体导致了后来机器故障”。早期片段 A 显示工人拿起一个没有清晰标签的容器；中间片段 B 短暂显示容器标签；后期片段 C 显示同一工人把其中物质倒入机器；片段 D 显示机器故障。Single-step retriever 可能因为“故障”字面匹配而把 D 排在最前，取回多个重复的故障画面，却漏掉 A 或 B。真正有用的是 A→B→C→D：A+B 确认 identity，C 确认 action，D 确认 outcome。IWM 应预测完整 chain 可以补全因果 evidence roles，而 C+D 仍不充分，重复的 D 类 nodes 则是 redundant。

所需的 prediction object

对于每个 imagined prefix，模型应预测紧凑的 functional state，而不是 imagined caption：

r̂(S_1:h) = { answerability, 已补全与缺失的 evidence roles, next evidence need, answer / read / wait / abstain, redundancy, contradiction, insufficiency }

因此，核心 target 是 trajectory-level 且 non-additive：C(A,B) ≠ C(A)+C(B)。科学问题不是模型能否对 relevant nodes 排序，而是它能否在执行真实 reads 之前，预测不同 clue combinations 会如何改变后续 grounded reasoning。

Benchmark 范围 · Streaming + multiple clues

1.2 我们聚焦 multi-evidence streaming Video QA——并非每个 benchmark 样本都是 multi-hop

任务范围。我们的目标是 streaming video QA：答案可能依赖多个彼此分离的 evidence moments，agent 必须在有限 memory 下保存、检索、观察或等待这些证据。当一个样本需要多个 frame/interval 时，我们称其为 multi-clue 或 multi-evidence；只有当这些线索构成相互依赖的 reasoning chain 时，才称为 multi-hop。多个线索本身不能证明存在有序 hop：两个 interval 可以只提供互补事实，而 annotation 并未规定必须先推理 clue A，再推理 clue B。

multiple clues ≠ necessarily multiple reasoning hops multi-evidence supervision：获得 clue A + 获得 clue B → 证据充分 explicit multi-hop supervision：clue A → intermediate dependency → clue B → answer
Benchmark / 选定子集是否真正 multi-hop？对本项目最合适的监督
完整 CG-Bench否。它覆盖 perception、reasoning 和 hallucination QA；benchmark 提供 clue intervals，但单个样本可能只有一个 clue。通用 clue grounding 与 long-video QA
本项目 CG-Bench 子集

StreamingBench Multiple-Clues属于 multi-evidence，但不是统一的显式 graph-hop reasoning。论文在 4,300 个分析样本中标出 2,778 个 Multiple-Clues 和 1,522 个 Single-Clue，multi-clue 约占 64.6%。扩展 streaming multi-evidence QA 的最大候选；clue decomposition/localization 可能需要重建

Benchmark 分工。这些数据集监督 IWM/planner 的不同部分，应使用 dataset-specific masks 组合，而不是强迫它们提供同一种标签：

CG-Bench filtered multi-clue subset → 主要 hypothesis-effect 与 clue-progress supervision StreamingBench Multiple-Clues + SQA → multi-evidence streaming QA + persistent belief/context OVO-Bench，特别是 CRR / SSR / REC → temporal readiness、state transition 与 planner control

结论。带 min_clues ≥ 2 过滤的 CG-Bench 仍是最干净的显式 clue-acquisition supervision 来源。StreamingBench 的 2,778 个 Multiple-Clues 样本是向 streaming multi-evidence QA 扩展的首选。OVO-Bench 则更适合补充 RETRIEVE_PAST、OBSERVE_CURRENT、WAIT 与 ANSWER 的 planner supervision，尤其是 readiness transition，而不应被当作主要的通用 multi-hop corpus。

SelectStream debrief

1.3 关于 online evidence allocation 的三个 RQ

SelectStream 把 streaming-video memory 定义为有预算的 online latent evidence allocation。它的贡献可以简化为三个相互配合的 research questions：

Research questionSelectStream 的回答在本项目中的作用
RQ1：什么时候应该把 stream 写入 memory？使用 surprise-driven adaptive windowing，在视觉流发生有意义变化时结束 segment 并写入，而不是按固定时间间隔采样。决定候选 L1 的时间粒度，并减少重复写入。
RQ2：固定容量下应该保留什么？把 latent evidence 保存在固定容量 memory 中，通过 priority-preserving consolidation 或 merge 管理历史，而不是只保留最近 observations。决定哪些 grounded history 能为未来问题继续使用；缺失或过度压缩的 clue 无法由 IWM 恢复。
RQ3：问题到来后应该检索并暴露哪些历史？用 query-conditioned routing 选取一个小型 evidence set，只向冻结 VLM 注入数量有界、经过 calibration 的 latent tokens。提供 evidence access 的效率 baseline，但不预测不同 multi-clue trajectories 的联合 reasoning outcome。

面向灵活 multi-clue reasoning 的局限

  1. Heuristic graph 构建与更新过于笨重、粗糙。Query-time retrieval 依赖由人工设计的 surprise、similarity、merge、priority 和 edge-update rules 构建并维护的 graph。这些操作增加工程复杂度；当新问题改变哪些 clue relations 更重要时，固定 topology 也缺少灵活适应能力。
  2. Multi-node、multi-subgraph reasoning cost 较高。为了覆盖多个互补 clues，系统可能需要检索、扩展并编码大量 nodes 或多个 candidate subgraphs。当多条竞争 evidence chains 需要同时比较时，graph reasoning cost 和注入 VLM 的上下文长度都会明显增加。
  3. 系统严重依赖 graph quality。Node 缺失、错误 merge、虚假或较弱 edges，以及不充分的 temporal/semantic connectivity 都会直接限制 retrieval reachability。一旦必要 clue chain 没有被正确写入 graph，或在 graph 中被扭曲，下游模型很难恢复。
边界：SelectStream 研究有限历史证据应如何分配，以及 VLM 应看到多少。本项目从 grounded candidate memory 出发，进一步提出不同的 downstream question：轻量 IWM 能否在 Reasoner 执行之前，预测多个 multi-step evidence-acquisition paths 的非加性后果？
Motivation

2. 从 graph-free proposals 到 answerability-aware grounded reasoning

目标 setup 将 candidate representation、counterfactual consequence prediction 与 grounded execution 分为三个阶段：

  1. Graph-free、question-conditioned candidate representation。对于每个合法 node，Q-Former 根据问题和该 node 在 pre-read contract 下允许暴露的 features，生成固定大小、node-aligned 的 query/proposal tokens。这些 tokens 编码粗粒度 relevance、时间位置与可能的 evidence role。系统不再首先构建或更新显式 semantic correlation graph；node 之间的关系保持 implicit 且依赖当前问题，由下游进行组合，而不是预先固定成 graph edges。
  2. 轻量预演 multi-clue、multi-hop outcomes。IWM 组合有序的 proposal-token trajectories——第一版每个 imagined hop 只加入一个 candidate node——并 roll out 不同 acquisitions 可能如何改变 answerability、missing evidence roles、contradiction、redundancy，以及是否应继续或 abstain。通过轻量模型预演多条可能 reasoning paths，系统不必为每个 branch 都支付完整 evidence read 和大 Reasoner execution 的成本。
  3. Grounded、answerability-aware Reasoner execution。Reasoner 接收当前 grounded evidence state、candidate evidence trajectories，以及 IWM 预测的 reasoning prior/status。它可以执行 multi-clue、multi-hop reads，提前停止、偏离或 replan，并持续判断 evidence 是否足以回答。Prediction 只用于引导 acquisition；最终 answer 与 abstention decision 必须由真正读取过的 evidence 支持。
Q-Former：根据问题生成 node-aligned candidate proposals IWM：轻量预演 multi-clue / multi-hop consequence combinations Reasoner：带显式 answerability awareness 的 grounded execution
关键修正：“implicit correlation”不表示 Q-Former 输出一张隐藏 adjacency matrix。Q-Former 负责表示各个 candidates；IWM 负责建模 candidates 与 trajectory prefixes 之间 conditional、non-additive 的 interaction。这样主方法保持 graph-free，同时仍能进行 question-dependent clue composition。
Related work 与方法定位

2.1 从高效 visual reasoning、latent world model 到 streaming evidence planning

本方案位于 lightweight visual reasoning、latent world-model supervision 与 bounded streaming-video memory 的交叉位置。以下最相关工作分别提供了互补的设计依据，但都没有从 grounded streaming memory 出发，预测 action-conditioned、multi-clue evidence-acquisition consequences。

工作核心思想本方案保留什么尚未解决的问题 / 本方案区别
IPRM
Jaiswal et al., NeurIPS 2024		用轻量、fully differentiable module 结合 iterative computation 与 parallel computation：前者处理 compositional steps，后者同时探索相互独立的 reasoning paths，应用于 image/video VQA。多 clue 推理不必展开成长 textual chain；iterative 与 parallel latent computation 可以高效整合多条视觉线索。IPRM 对已经提供给模型的 features 进行推理，不建模合法 READ(i) intervention，也不预测不同 evidence trajectories 的 post-read consequence、管理 causal streaming memory，或约束 imagined 与 grounded evidence 的边界。
MIRAGE
Yang et al., 2026		把 mobile-agent reasoning 蒸馏到 continuous latent slots；训练阶段用 Q-Former head 将这些 slots 对齐到 frozen next-screenshot features，使 hidden state 同时具有 action 与 transition awareness。Future-state prediction 可以约束紧凑的 latent reasoning，不需要解码冗长 rationale 或生成 pixels，为高效 world-model interface 提供依据。MIRAGE 预测执行 mobile action 后的下一 GUI observation，其 Q-Former world-model head 在 inference 时被移除。本方案的 IWM 则作为 inference-time planner 保留，用来比较多条 hypothetical evidence-read chains，并预测 clue need 与 answerability 的 functional change，而不是 future frames。
JEPA / V-JEPA 2
Assran et al., 2025		Context encoder 与 predictor 学习预测 target representations，而不是重建全部 pixels；V-JEPA 2 还展示了用于 planning 的 action-conditioned latent world model。JEPA 可以作为 IWM 的潜在实现参考：使用 stop-gradient target encoder，在 latent space 预测紧凑的 post-transition representation，而不是生成 imagined caption、reasoning text 或 pixels。Physical-video JEPA 预测 visual state 如何演化；本方案预测合法 evidence action 将如何改变 question-conditioned reasoning state。JEPA 因而是一种 architecture option，而不是本方案 IWM 的定义。
SelectStream
Ge et al., 2026；详见 §1.3		面向 streaming video 的 budgeted online evidence allocation。Adaptive L1 scope 与 capacity-aware consolidation。其 query routing 使用 latent memory graph；本方案保持 graph-free，并在执行前预测 multi-step evidence consequences。
方法定位：IPRM 支持高效 latent multi-path computation；MIRAGE 支持 transition-predictive latent states；SelectStream 支持 bounded online evidence allocation。本方案通过 belief-space 中的 model-predictive evidence planning 连接三者：Q-Former 生成 node-aligned pre-read proposals，IWM rollout 多条合法 READ trajectories，Reasoner 再用真实 evidence 执行和校正。

模块职责禁止行为

事实基础

3.1 L1 grounded evidence memory

采用 SelectStream-like、但保持 grounded 的构建方式。L1 writer 先把视频切成较短的 fixed-duration clips，再根据 content change、temporal continuity 与 memory pressure，对相邻 clips 进行 merge，或扩展其 scope，形成 adaptive-length evidence nodes。稳定内容可以合并成覆盖范围更大的 node；快速变化或显著事件则保留更细的时间粒度。

stream → 短 fixed-interval clips → caption / entity-state / embedding extraction → 基于 change 与 continuity 的 merge 或 boundary decision → 固定容量下的 adaptive-scope grounded L1 nodes

3.1.1 在线 node update 与 capacity-aware consolidation

每个新的短 segment 到达时，writer 都执行一次 question-independent 决策。借鉴 SelectStream 中有用的机制，它联合 attention drift 与 feature change：前者检测 segment encoder 的关注位置是否转移，后者通过 cosine distance 检测 visual-semantic content 是否变化。Exponential moving average 提供局部 baseline；surprise spike、累计 surprise budget 或 maximum segment length 均可触发 segment boundary，而 minimum length 用于避免噪声造成的过度切分。

s_t^attn = JS(A_t || A_{t-1}) s_t^feat = 1 - cos(g_t, g_{t-1}) s_t = λ s_t^attn + (1-λ) s_t^feat s̄_t = ρ s̄_{t-1} + (1-ρ)s_t

Segment 结束后，轻量 segment encoder 生成 candidate z_j。一个 learned write determiner 综合其 quality/grounding score、surprise、duration、temporal gap、capacity pressure，以及它与 active nodes 的 similarity；它预测明确的 typed action，而不是含义模糊的单一分数：

d_j = D_ψ(z_j, quality_j, surprise_j, Δt, {cos(z_j,h_i)}, |M|/K) d_j ∈ {discard_low_quality, merge_update(i*), append_new, consolidate_then_append}

Low quality 指证据不可靠或 grounding 不充分，而不是与当前问题不相关。由于未来问题未知，determiner 不能仅因 question relevance 低而丢弃一个有效事件。若最佳 feature match 超过 redundancy threshold 且 candidate surprise 较低，writer 更新对应 node；否则创建新 node。Gated update 在吸收真实变化的同时避免覆盖历史：

i* = argmax_i cos(z_j,h_i) γ_j = sigmoid(MLP([z_j; h_i*; s̄_j; Δt; quality_j])) h_i* ← (1-γ_j)h_i* + γ_j f_write(z_j,h_i*)

执行 update 时，还要合并 time span，对 caption 与 entity/state fields 做 grounded merge，保留 source provenance 与 lineage，并更新 write/merge metadata；随后使 §3.2.1 中缓存的 question-independent Q-Former tokens U_i 失效并重新计算。若容量将超过 K，writer 合并风险最低的一对 node：高 feature redundancy 鼓励合并，而 surprise、access frequency、recency 与 evidential quality 共同保护高价值 node。该设计保留 SelectStream 的 priority-preserving consolidation 思路，但不构建 semantic graph edges。

(u,v) = argmin merge_cost(u,v) merge_cost = dissimilarity(u,v) + protection(u) + protection(v) M ← (M \ {u,v}) ∪ {GroundedMerge(u,v)}

3.1.2 作为 feature embeddings 存储的基础 node content

Caption、entity、visual embedding 与 timestamps 是每个 L1 node 的基础内容。Node 既保留可审计的 source fields，也将这些内容保存为对齐的 model-facing feature embeddings：

M[i] = [ f_caption(i), f_entity/state(i), f_visual(i), f_time(t_start,t_end) ] f_caption = Proj(Encode(有界 grounded caption)) f_entity/state = Proj(Encode(grounded entities 与 states)) f_visual = Proj(visual 或 multimodal clip representation) f_time = 显式 start/end timestamps 的 temporal embedding

所有 feature slots 都投影到共享 dimension，并携带显式 validity masks。原始的有界 caption、entity/state fields 与精确 timestamps 仍与 embeddings 一起保存，用于 provenance、debugging 和 tool arguments。因此 timestamps 有意采用双重表示：精确 metadata 用于 temporal legality 与审计，learned feature embedding 用于 Q-Former/IWM computation。

每个 materialized node 保存稳定 node ID、精确 source interval 与 timestamps、有界 grounded caption、证据支持的 entities/states、embedding 或 embedding reference、provenance/evidence pointers、visibility、lineage/merge history 和 read status。L1 是最终答案的 factual substrate。

L1 字段用途访问边界
Node ID、time span、availability、lineage稳定寻址、合法性控制与审计始终 memory-visible
有界 caption、entity/state tags、embedding reference为 Q-Former 提供粗粒度 candidate representation只在声明的 pre-read contract 下可见；本身不足以作为 final answer evidence
细粒度 frames、完整 caption/dialogue、OCR/audio、verified provenance权威 grounded observation只有真实 READ(i) 或 typed evidence tool call 后才向 Reasoner 暴露

通过 tool calling 按需获得额外信息。L1 不需要预先计算所有 entity relations、dialogue claims、temporal chains 或 state changes。当 Reasoner 需要更多细节时，可以使用 Steam_Video_Agents/atomic-skill-decomposition-and-assembly 中 typed、executable 的基础设施。可用操作包括 event 与 entity-history retrieval、temporal-neighborhood lookup、clue/event localization、visual-evidence 与 dialogue extraction、entity tracking、event ordering 和 state-change checks。

每个 tool result 都必须返回 timestamps 与 evidence references，通过对应 verifier；请求的信息不存在时必须 fail closed。因此，tool calling 是 grounded reading 的按需扩展：需要什么信息再获取什么，不必把所有可能结构都预存进每个 node。它不会为主方法建立 semantic graph edges，也不能把 IWM prediction 转换成事实。

在 READ(i) 之前，下游模型只能接收 pre-read contract 明确允许的有界 address/proposal view；权威 source value 必须等到执行后才可见。

架构变更：显式 L1.5 semantic/correlation graph 从主方法中移除。确定性的 temporal、visibility、provenance、availability 和 budget constraints 仍可作为 masks，但目标设计不构造静态 semantic adjacency、cursor-local rows 或 graph action compiler。

已有 L1.5、cursor、complete-graph 与 full_graph_iwm artifacts 继续作为可复现历史 baseline 和 regression tools；它们不再定义当前论文方法。
候选表示

3.2 Node-aligned Q-Former proposals

唯一职责：把每个 video-memory node 压缩成少量、与问题相关、保留时间信息、且始终绑定 node ID 的 pre-read proposal tokens，供 IWM 预测 multi-step、multi-clue acquisition consequences。

输入

X_i = FrozenVideoEncoder(x_i) ∈ R^(L_i×d_v) P_i = Q_φ(X_i, q, τ_i) ∈ R^(m×d_w)
输入内容设计边界
X_i由冻结 visual/VLM encoder 预计算的 token-level node features，包括 visual frame/patch tokens、可用 OCR/subtitle features、modality/type embeddings 和基础 L1 feature slots。使用 token-level features，而不只使用最终 pooled embedding；首版不把 video encoder 与 Q-Former 端到端联合训练。
qQuestion tokens 用于让 learned queries 聚焦 node i 中可能与问题有关的部分。主版本不输入完整、持续变化的 reasoning state h_t；该状态留给 IWM，使同一问题下的 node proposals 稳定且可缓存。
τ_i显式归一化的 start/end time、duration，以及可选的 query-time offset，经小型 time MLP 编码。时间信息直接写入 proposal tokens；Q-Former 不单独输出 temporal-relevance score。

3.2.1 Node craft/update 时计算 question-independent query tokens

为了避免每个问题都重新对完整 token sequence X_i 做 attention，L1 可以在 node 被创建、merge 或发生实质 update 时，运行一个小型 Q-Former-style node compressor。固定数量的 learned node queries 先进行 self-attention，再 cross-attend 到 node features：

U_i = Q_base(Q_node, X_i, τ_i^abs) ∈ R^(m_0×d) Q_node：带 self-attention 的 learned query tokens Q_node → X_i：对 token-level node features 的 cross-attention

U_i 是可缓存、question-independent 的 node content 与 absolute-time summary。它不能编码 question relevance、answerability、reasoning trajectory 或 node-to-node relation，并始终绑定 node_i。当 node 的 source span、caption/entity fields、feature embeddings 或 merge lineage 改变时，必须重新计算并使旧缓存失效。

问题到来后，question-conditioned Q-Former 基于缓存的 node queries 进行 refine，而不再重复处理完整 clip：

P_i = Q_question(U_i, E_q(q), τ_i^rel) ∈ R^(m×d_w) τ_i^abs = [t_start/T, t_end/T, duration/T] τ_i^rel = [t_start−t_q, t_end−t_q]

这个 factorization 将 node crafting 与 question-conditioned proposal generation 分开：第一阶段只在 memory 变化时运行一次，第二阶段在 query time 保持轻量。两个阶段都不执行 cross-node attention；multi-node 与 multi-clue interaction 仍属于 IWM。

输出契约

P_i = Q_φ(X_i,q,τ_i) ∈ R^(m×d_w), m = 4 或 8 P = [P_1,…,P_N] ∈ R^(N×m×d_w) P_i ↔ node_i

每组 proposals 可以保留粗粒度 node content、question relevance、时间位置和可能的 evidence role——信息量应足以让 IWM 判断它与其他 clues 的联合后果。每组 tokens 始终绑定对应 node ID；全局混合不能丢失可执行的 node identity。

Proposal tokens 不应直接编码完整 caption、final answer、imagined reasoning trace、answerability verdict、next-read decision 或 multi-clue consequence。Synergy、conditional relevance、redundancy、ordering 和 delayed consequences 都属于 IWM。

V1 实现：采用共享的 4–6 层 BLIP-2-style cross-attention Transformer，hidden size 768/1024，每个 node 4–8 个 queries。先预计算冻结 node features 并 warm up representation/clue/time preservation，再在学习 IWM dynamics 时冻结 Q-Former。§7 统一评测 clue recall、proposal-only QA leakage、token budget m∈{2,4,8,16} 与 node-order consistency。Reference path 包含所有合法未读 nodes；任何 selector 都是需要单独 recall audit 的效率优化。

Counterfactual dynamics

3.3 Multi-step compositional IWM

唯一职责：基于当前真实 reasoning state 与 node-aligned Q-Former proposals，低成本预测连续读取多个 clues 后的联合推理后果，为 Reasoner 提供 multi-step look-ahead。IWM 不是第二个 Q-Former、node-ranking policy，也不负责最终 QA。

grounded memory nodes → Q-Former proposal tokens → IWM multi-step consequence rollouts → Reasoner grounded reads and QA / abstain / replan

真实初始状态与有界输入

初始状态由 Reasoner 对问题和已经真实读取的 evidence 的 representation 投影得到。少量 state tokens 表示当前已知内容、仍缺失的推理条件、已经读取的 clues，以及答案是否接近充分；无需手写庞大的 belief schema。

Z_0 = S_η(H_R(q,E_t)) ∈ R^(M_s×d) P_i = Q_φ(q,X_i,τ_i) ∈ R^(M_p×d) IWM input = (Z_0, P_(1:N), mask_t, b_t)

每组 P_i 始终绑定具体 node ID，只携带低带宽的 pre-read content 与时间信息，不包含完整 grounded evidence。Mask 约束 visibility、arrival time、already-read/visited status 和 trajectory legality；b_t 编码剩余 reads、rollout horizon 与 wait budget。主线不需要 L1.5 graph 或 semantic adjacency。

Action-conditioned shared transition

在 imagined step h，模型预测下一步读取 node i_h 将产生什么后果。一个小型 latent Transformer 在所有 imagined hops 之间复用同一个 transition cell：

U_h = CrossAttn(Z_h,P_(i_h)) Z_(h+1) = LN(Z_h + TransitionBlock(Z_h,U_h,e_h)) ρ_k = (i_(k,1), …, i_(k,L_k)), L_k ≤ H

第一版每个 imagined hop 只加入一个 node，并使用小 beam（例如 H=3, B=4），允许提前 halt。因此 A→B→C 可以表达 multi-clue combination，而无需在单个 action 中枚举任意 node subset；只有数据确实需要时，才扩展 parallel clue sets。

该 transition 必须学习 non-additive consequence：C(A,B) ≠ C(A)+C(B)。它需要区分 complementary、redundant 与 contradictory clues，识别一个 clue 如何使下一个 clue 变得有用，并预测一条 path 是否仍不完整或已经不可恢复。

潜在的 JEPA-style 实现

JEPA 可以作为 IWM 的潜在 architecture reference，因为它预测抽象 target representations，而不是重建 raw observations。Context encoder 表示 Z_h；action-conditioned predictor 接收 READ(i_h) 与 P_(i_h)；stop-gradient target encoder 则表示 teacher Reasoner 在真实读取 evidence 后的状态：

Ẑ_(h+1) = Predictor_θ(Z_h, READ(i_h), P_(i_h)) Z*_(h+1) = stopgrad(TargetEnc(H_R(q,E_t ∪ {o_(i_h)})))

这是一种实现选择，不改变 IWM 的定义。与 physical-video JEPA 不同，这里的 prediction target 是 evidence acquisition 带来的 functional、question-conditioned consequence；仍需 next-clue、answerability、contradiction 与 insufficiency heads，而且 predicted representation 仍不能作为最终答案证据。

Rollout 输出与事实边界

R_t = {(ρ_k, C_k, u_k)}_(k=1)^B C_k = Pool(Z_(k,1:L_k)) u_k ∈ {CONTINUE, EXPECTED_ANSWERABLE, EXPECTED_ABSTAIN}

每个 candidate 只包含 node IDs、少量 latent consequence tokens 和预计 terminal status。这些 tokens 概括 predicted progress、synergy、redundancy、contradiction 与 remaining evidence need，仅作为 planning context；它们不是 imagined caption、numeric reward、Q-value、memory write 或 final-answer evidence。Terminal label 同样只是预测，真实 answer/abstain 决策仍由 Reasoner 在 grounded execution 后作出。

训练目标：使用 frozen teacher Reasoner 真实读取 clue prefixes 与 combinations（如 A、B、A+B、A+C）后产生的 functional consequences，监督 next-clue distribution、terminal status、functional planning behavior 以及每个 rollout horizon；不能把 IWM 自己的 imagined state 当作事实 target。生成最终答案时屏蔽全部 consequence tokens，使答案只依赖 q+E_grounded。

Grounded control

3.4 Reasoner execution and QA

唯一职责：比较 IWM 预测的 multi-step evidence trajectories，选择并执行真实 evidence reads，根据 observation 调整行为，判断 grounded answerability，最终回答或 abstain。

IWM predicts multi-step consequences. Reasoner performs grounded multi-step execution and QA.

Reasoner 不为全部未读 nodes 编码 proposals，不模拟大规模 counterfactual tree，不预测未读 node 的具体内容，也不把 IWM consequence 当作回答证据。它是一个统一的 multimodal tool-using model，但 runtime 严格分为两种模式；无需额外设置 Planner LLM、post-read judge 或独立 answerability model。

Control mode：路径选择与 grounded execution

a_t = R_ψ^control(q,E_t,R_t,m_t,b_t) a_t ∈ {READ(i), REPLAN, WAIT, ANSWER_READY, ABSTAIN}

Control mode 接收问题、只记录真实 reads 的 evidence ledger、最多 B 条 IWM rollouts、execution state、剩余 read/wait/replan budgets 与 tool schema。每条 rollout 暴露 node sequence、少量 projected consequence tokens 和 terminal prediction。Reasoner 不应接收完整 Q-Former proposal bank，否则它可能绕过 IWM，自行执行无约束 retrieval。

Typed action执行约束
READ(node_id, rollout_id)读取一个已到达、可见的 node，并把带 timestamp、provenance 与 read order 的 observation 加入 E_t。V1 默认每次只读一个 node。
REPLAN(reason)发生 mismatch、contradiction、path exhaustion 或 insufficient progress 后，从更新过的 grounded state 重新运行 IWM。
WAIT只在允许未来证据的 streaming protocol 中开放；普通 clue-navigation evaluation 不启用。
ANSWER_READY声明当前 grounded evidence 可能已经充分，随后切换到隔离的 Answer mode。
ABSTAIN(reason)以 typed cause 终止，例如 missing evidence、unresolved conflict、budget exhausted 或 unrecoverable memory loss。

Multi-step execution 指同一持续 episode 中交错执行多次真实 tool calls。每次 READ(i) 后，Reasoner 都先观察真实结果，再决定继续预测 path、跳过已经冗余的 hop、提前停止或 replan；绝不把整条 imagined trajectory 当作一个 atomic batch 直接执行。

READ(12) → grounded o_12 → READ(37) → grounded o_37 → ANSWER_READY 或：READ(12) → prediction mismatch → REPLAN

Answer mode：只进行 grounded QA

Control mode 输出 ANSWER_READY 后，同一个模型执行一次独立 answer forward，并通过 input/attention contract 移除 IWM consequence tokens、未执行 rollouts、Q-Former proposals 与未读 node information：

y = R_ψ^answer(q,E_grounded) output ∈ {ANSWER(y, evidence_refs), ABSTAIN(reason)}

Evidence ledger 中每项都保留 node ID、timestamp、grounded visual/text content 或可审计 feature reference、可用的 OCR/subtitles、provenance 与 read order。最终答案必须引用真正读取过的 node IDs；自由生成的 model summary 不能单独作为 evidence，fail-closed validation 会拒绝任何未读 node reference。

训练使用完整 grounded execution episodes，覆盖正确、冗余、冲突、缺失证据与 replan cases；统一训练流程见 §6。

4. 正式 runtime contract

Z_t = S_η(H_R(q,E_t)) P_i = Q_φ(q,X_i,τ_i), i ∈ U_t R_t = Rollout_θ(Z_t,{P_i},H,B) a_t = R_ψ^control(q,E_t,R_t,m_t,b_t) 若 READ(i)： o_i = Execute(READ(i)); E_(t+1) = E_t ∪ {o_i} 若 REPLAN： 重新计算 Z_(t+1)、P 与 R_(t+1) 若 ANSWER_READY： y = R_ψ^answer(q,E_grounded) 以 grounded ANSWER 或 ABSTAIN 结束

所有模型输入都必须有界。任何模型都不能接收完整视频、hidden answers、未选择的 source clips 或未经压缩的全部历史。Prediction 可以影响获取哪些 evidence，但绝不能越过事实边界进入答案。

允许的确定性控制主方法中不允许
Visibility、provenance、availability、temporal legality、already-read state 与 budgets以静态 semantic adjacency 作为 reasoning substrate
显式 padding 与 unavailable-node masks隐藏 relevance threshold 或 mandatory Top-K
Fail-closed answer-evidence validation把 imagined rollout 持久化为 grounded memory
可审计的 future-evidence wait/defer policy提前读取尚未出现的 future clips

5. 为什么需要 action-conditioned world model

Reactive Reasoner 本身也能边读取边重新规划，因此“支持多步推理”不足以证明 IWM 有必要。IWM 必须低成本预演多个 counterfactual branches，例如 A→B、A→C 与 D→E，避免为每个分支付出真实 reads 和大模型 calls。

多层 Q-Former 或 iterative module 只是在反复 refine 已经提供的 features：

z_(h+1) = F(z_h, P)

网络更深并不自动成为 world model。每个 IWM step 都必须对应合法 evidence intervention，并由 teacher 在真实 evidence 上执行相同 prefix 后的 consequence 监督：

READ(i_(1:h)) → r*(i_(1:h))

普通 iterative reasoning 学习如何在已有 features 上计算；IWM 学习尚未执行的 acquisition 会如何改变后续 reasoning。其价值必须体现为 matched budgets 下更少的 reads/calls、更高 chain completion，或更好的 grounded QA 与 abstention。

Go/No-Go：如果 reactive Reasoner 在相同预算下得到相同 trajectories 与结果，或收益可以由 parameter-matched extra depth 解释，则 IWM 没有必要。
Dynamics supervision

6. 训练与 V1 实现

仅使用最终 QA loss 不能证明 IWM 学会了 dynamics。数据流程必须从同一 immutable initial state 执行真实 clue combinations，例如 ∅、A、B、A+B 和 A+C。

r*(S) = R_teacher(q, E_0 ∪ E_S) r̂(S) = D(T_θ(P,S))

冻结 teacher Reasoner 读取真实 evidence 后产生 functional targets，包括 answerability、next evidence need、subsequent read distribution、answer distribution、continue | answer | abstain、contradiction 与 insufficiency。

训练必须覆盖 clue synergy、leave-one-clue-out、redundancy、contradiction、conditional relevance、不同 clue prefixes、可交换与顺序敏感的 sequences、缺少关键证据时的 abstention，以及表面相似但没有 realized clue gain 的 hard negatives。

数据按 video-disjoint 划分；candidate order 随机化；teacher branches 从 immutable checkpoints 出发；hidden grounded values 永不进入 pre-read proposal input。

Reasoner 模型与接口

主 Reasoner 建议采用开放权重的 multimodal Qwen3.5-9B 并通过 LoRA 适配。这是当前 implementation choice，而不是科学定义的一部分；较小模型和 frozen prompting 仍是必要的规模与适配 controls。

部分V1 建议
ReasonerQwen3.5-9B；LoRA rank 16（ablate 32），作用于 attention Q/K/V/O 与 MLP；初期冻结 visual encoder
IWM interface两层 IWM-to-Reasoner projector；top B=4 rollouts；每条最多 H≤3 nodes；每个 rollout step 约两个 consequence tokens
Typed tokens<READ>、<REPLAN>、<ANSWER_READY>、<ABSTAIN>、<ROLLOUT>、<EVIDENCE>
Execution limits每次 tool call 执行一个 grounded read；每个 episode 最多 3–4 reads 与 1–2 replans
Answer单独 forward，输入仅为 question 与 grounded evidence

最低限度的模型 controls 包括：较小 Qwen3.5 Reasoner 作为规模下界、9B 主模型、frozen-9B prompting 用于确认 LoRA 价值，以及只用于离线 trajectory/target construction 的更大 teacher。

Execution episodes 与可信 labels

(q,R_0) → a_0 → o_1 → a_1 → o_2 → … → y

当多个 clue orders 都合法时，next-read supervision 必须是 multi-positive：对合法 action set 优化 marginal likelihood，不能把另一个同样有效的 clue 标为错误。可信 ANSWER_READY label 要求 frozen teacher 基于 grounded evidence 稳定作答，并与 full-video reference 一致，最好再通过 evidence-removal 或 counterfactual check 验证；不确定状态保持 ignore，而不是强制归入 answerability class。

ABSTAIN targets 来自人为移除必要 clues、budget exhausted、无法消除的 contradiction、benchmark-unanswerable cases，以及 teacher 判定不充分的 leave-one-clue-out states。多个 annotated clue intervals 并不自动表示每条 clue 都必要，也不表示存在唯一顺序。

简化的 V1 训练流程

阶段训练信号与目的
Baseline gate · 不属于训练阶段评测 frozen/reactive no-IWM Reasoner 的 next-read、answerability、abstention 与 grounded QA，用于判断 world model 是否必要，但不把它计入 training curriculum。
1 · Unified contract SFT用 mixed batches 联合训练 Control 与 Answer modes：oracle trajectories 教 typed tool use；corrupted、redundant 与 wrong-terminal rollouts 教 early stop 和 REPLAN；answer-only batches 使用 (q,E_grounded)→(y,evidence refs)，并屏蔽所有 IWM tokens。同一次训练中先以 oracle 为主，再逐步提高 noisy cases 比例。
2 · Real-IWM adaptation冻结 IWM，训练 projector 与 Reasoner LoRA，使其适应真实 path format、prediction errors、horizon degradation、consequence-token geometry 与 terminal bias；同时保留少量 oracle、corrupted-rollout 与 grounded-answer replay，避免遗忘。
Optional · low-rate joint tuning只有 frozen-IWM adaptation 已饱和时，才解冻 IWM 最后若干层；visual encoder 与 Q-Former 继续冻结，并满足 η_IWM < η_projector ≈ η_Reasoner-LoRA。V1 不要求该步骤。
V1 停止点：Unified contract SFT 加 real-IWM adaptation。只有简单流程已经稳定，且 matched no-IWM comparison 显示仍存在可学习差距时，才加入 joint tuning 或 RL。
L_R = λ_ctrl L_ctrl + λ_ans L_answer + λ_ref L_evidence-ref + λ_rob L_robust

Control loss 监督 typed actions；answer loss 只在 grounded Answer mode 生效；evidence-reference loss 要求输出真正读取的 node IDs；robustness loss 在 corrupted IWM context 下训练拒绝、replan、early stop 与 abstention。无需单独 numeric utility/value head。Optional GRPO 推迟到 SFT 稳定之后，且不是 V1 必需；后续若使用 reward，必须重罚 unsupported answers、unread-node citations 与无上限 replanning。

Matched causal evaluation

7. Evaluation 与 causal gates

在相同 Q-Former、Reasoner、L1 memory、真实 read budget 和大模型 call budget 下比较：

  1. Q-Former proposal tokens 直接输入 Reasoner；
  2. 参数量匹配的 deep Transformer 或 iterative module；
  3. 每次真实 read 后 replan 的 reactive Reasoner；
  4. single-step consequence model；
  5. independent-node consequences 的加性组合；
  6. multi-step compositional IWM；
  7. IWM 只提供 node sequences、不提供 consequence tokens；
  8. IWM 只提供 consequence tokens、不提供 node sequences；
  9. shuffled IWM rollouts；
  10. oracle real post-read consequences；
  11. Answer mode 可见 IWM tokens，与按要求屏蔽 IWM tokens 的 Answer mode。

还需使用较小 Reasoner、9B 主模型与 frozen-9B prompting 进行 model-scale controls。历史 graph navigation 与 explicit planners 是可选 legacy baselines，不能替代以上 matched controls。
